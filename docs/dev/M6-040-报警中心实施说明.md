# M6-040 应用内报警中心实施说明

## 1. 目标与边界

在日志中心新增「报警日志」，把两类事件统一到一个可查询、可统计、可确认的视图：

1. **风险域名访问**（DNS 拦截）：回答「哪些客户端地址访问了哪个被拦截域名、访问了多少次」；
2. **系统故障**：数据库/日志存储/DHCP/DNS 掉线、磁盘水位、日志外发降级、情报源同步失败、上游探活失败。

右上角报警栏轮询未确认报警；**查看即确认**（点击通知或报警行），确认是全局的（单机产品），
记录 `acked_by`。系统故障恢复后自动置为 `resolved`，再次发生重新打开为未确认。

不在本期范围：邮件/Webhook/钉钉外发（沿用 M6-005 告警通道）、按用户维度的已读状态、
原始日志明细二次存储。

## 2. 数据模型

迁移：`db/postgresql/migrations/0047_alert.sql`。

| 字段 | 说明 |
|---|---|
| `dedup_key` | 唯一键，决定聚合粒度 |
| `source` | `dns` / `system` |
| `kind` | `risk_url`、`db_down`、`logstore_down`、`dhcp_down`、`dns_down`、`disk_pressure`、`log_export_degraded`、`intel_sync_failed`、`upstream_probe_failed` |
| `severity` | `critical` / `warning` / `info` |
| `status` | `open`（未确认）/ `acked`（已确认）/ `resolved`（已恢复） |
| `client_ip` / `client_mac` / `domain` | 风险访问维度 |
| `component` | 系统故障组件中性名（database/logstore/dhcp/dns/host/log-export/intel/upstream） |
| `count` | 窗口内事件数或连续故障次数 |
| `first_seen` / `last_seen` | 首末发生时间 |
| `acked_at` / `acked_by` / `resolved_at` | 确认与恢复留痕 |

### 去重键

- DNS：`dns|<client_ip>|<domain>|<YYYYMMDDHH>` —— **1 小时桶**，同小时累加，跨小时新开一条。
- 系统：`system|<kind>|<component>` —— 同一组件只有一条活动报警。
- 磁盘：`system|disk_pressure|<mount>`；情报源：`system|intel_sync_failed|<source key>`；
  上游：`system|upstream_probe_failed|<upstream id>`。

### 合并语义（`ON CONFLICT`）

- `count = GREATEST(alert.count, EXCLUDED.count)`：采集器 60s 回扫最近 2 小时，
  ClickHouse 返回的是「桶内累计值」，重复回扫不会重复计数；
- `first_seen = LEAST(...)`、`last_seen = GREATEST(...)`；
- 之前已 `resolved` 的同键事件：状态回到 `open`，清除 `acked_at/acked_by/resolved_at`，
  `count` 用本次值（视为新一次故障/新一小时的访问）。

> 注意：DNS 报警在同一小时内被确认后，继续命中**不会**重新变未确认（避免同一事件反复打扰）；
> 下一个小时桶会产生新的报警。系统故障恢复后再次发生则重新打开。

## 3. 采集

`internal/module/alerts/collector.go`，每 60s 一轮，启动即执行一次。

### 3.1 DNS 风险访问

`internal/module/logquery/alerts.go` 新增 `(*ChStore).BlockedEvents`：

```sql
SELECT toStartOfHour(ts), coalesce(toString(sip),''), domain, any(category),
       count(), min(ts), max(ts)
FROM ipam.logs
WHERE ts >= ? AND type='dns' AND action='blocked' AND domain != '' AND sip IS NOT NULL
GROUP BY 1,2,3
ORDER BY count() DESC
LIMIT 5000
```

- `sip` 是 DNS 查询源地址（客户端），`action='blocked'` 由 Vector 的 `parse_rpz` 打标；
- 单次最多 5000 组，极端场景按命中次数截断，避免控制面内存被打满；
- 内存模式（未配置 `IPAM_CH_ADDR`）不启用 DNS 报警采集。

### 3.2 系统故障

| 探针 | 判据 | 级别 | 阈值 |
|---|---|---|---|
| 数据库 | `pool.Ping` 失败 | critical | 连续 2 次 |
| 日志存储 | ClickHouse `Ping` 失败 | critical | 连续 2 次 |
| DHCP | Kea `version-get` 失败 | critical | 连续 2 次 |
| DNS | `/run/ipam/unbound-ctl.sock` 不可达 | critical | 连续 2 次 |
| 磁盘 | 任一挂载点 ≥90% | warning | 立即 |
| 日志外发 | `exportSvc.Status().Degraded` | warning | 立即 |
| 情报源 | 已启用且 `lastStatus=failed` | warning | 立即 |
| 上游 | 已启用且 `ConsecutiveFails >= 3` | warning | 立即 |

- 服务探针连续失败 2 次才报警，避免网络抖动误报；失败但未达阈值也计入「当前故障集合」，
  不会被误判为已恢复。
- `ResolveStaleSystem(managedKinds, activeKeys)` 只恢复**本轮已启用探针**产生的报警：
  未配置的能力（如未接 ClickHouse）不会把历史报警错误地置为 resolved。

## 4. 接口

契约：`api/openapi/paths/alerts.yaml`、`api/openapi/components/schemas/alerts.yaml`，
挂载在 `/logs` 下复用 `logs` 权限域：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/logs/alerts` | 列表：`from/to/q/source/kind/severity/status/page/pageSize`；未确认优先、`last_seen` 倒序 |
| GET | `/logs/alerts/stats` | 状态/级别/类型计数 + 风险域名 Top + 客户端地址 Top + 趋势（≤48h 按小时，否则按天） |
| GET | `/logs/alerts/unread` | 未确认总数 + 最近 N 条（报警栏轮询） |
| POST | `/logs/alerts/ack` | 单条/批量确认 `{alertIds}`，幂等 |
| POST | `/logs/alerts/ack-all` | 确认全部未确认 |

`q` 为不区分大小写子串，命中标题/摘要/域名/客户端地址/客户端 MAC/组件；
`%`/`_`/`\` 已转义，避免用户输入被当成通配符。

### RBAC

`internal/module/platform/rbac.go` 新增 `requiredPerm`：
`POST /api/v1/logs/alerts/ack` 与 `/ack-all` 只需要 `logs:read`（确认不是配置变更），
其余 logs 写操作仍要求 `logs:write`。operator/auditor/user 均可确认自己看到的报警。

## 5. 前端

### 5.1 报警日志页

`web/apps/web-ipam/src/views/logs/alerts/index.vue`，路由 `/logs-center/alerts`：

- 4 张统计卡：报警总数 / 未确认 / 严重报警 / 风险域名；
- 时间窗 1h/6h/24h/7d/30d + 关键字模糊搜索 + 来源/级别/状态过滤；
- 报警趋势（`TrendChart`）、风险域名 Top、客户端地址 Top；
- 报警表格：级别、类型 + 域名/客户端摘要、来源、客户端地址、次数、状态、最近发生；
- 点击行（或通知跳转带 `alertId`）→ 自动确认并打开详情抽屉；
- 「确认本页」「全部确认」；30s 自动刷新。

### 5.2 右上角报警栏

`web/apps/web-ipam/src/layouts/basic.vue`：

- 30s 轮询 `GET /logs/alerts/unread?limit=8`；
- 有未确认报警时显示红点；标题/摘要按 `kind` 本地化（不直接展示后端中文）；
- 点击通知 → `POST /logs/alerts/ack` + 跳转 `/logs-center/alerts?alertId=<id>`；
- 单条确认、全部确认、清除通知都会同步确认后端报警，避免下一轮轮询又出现。

## 7. 踩坑与约束

- **不要按 `last_seen` 直接累加计数**：采集器回扫会重复。必须用 ClickHouse 桶内累计值 +
  `GREATEST` 合并。
- **未配置的探针不能参与自动恢复**：否则未接 ClickHouse 的环境会把历史 `logstore_down`
  错误地标成已恢复。用 `managedKinds` 限定。
- **系统探针需要连续失败阈值**：单次抖动不应产生报警；但失败未达阈值时要保留在故障集合中。
- **界面不出现底层产品名**：组件名统一用中性词（数据库/日志存储/DHCP/DNS/主机…）。
- **确认动作降级为 `logs:read`** 只对 `/logs/alerts/ack*` 生效；其他 logs 写操作仍走 `logs:write`。
