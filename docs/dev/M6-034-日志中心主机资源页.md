# M6-034 日志中心主机资源监控页：实现说明

## 1. 背景

M6-032/M6-033 已把主机与控制面指标按分钟落库，并在「系统管理 → 服务与运行」提供基础趋势卡片。但排障时仍缺一个独立、可查询的监控视角：没有容量构成（磁盘各挂载点、内存构成、连接池占用）、不能自定义起止时间、看不到逐条采样明细。

本任务在「日志中心」新增独立菜单页「主机资源」（`/logs-center/host`），只消费 M6-032 已发布的契约，**不新增后端端点**。

## 2. 页面结构

| 区块 | 内容 | 数据源 |
|---|---|---|
| 顶部指标卡 | CPU / 内存 / 磁盘（取最满挂载点）/ 1 分钟负载 | `GET /system/metrics`（30s 轮询） |
| 查询工具条 | 预设 1h/6h/24h/7d/30d、自定义起止时间、查询/重置 | — |
| 运行趋势 | CPU / 内存 / 磁盘 / 负载 4 张曲线 + 窗口峰值 + 历史起始时间 | `GET /system/metrics/history`、`/summary` |
| 容量构成 | 磁盘使用分布（按挂载点）、内存构成（已用/可用）、数据库连接池（使用中/空闲） | `GET /system/metrics`、最新采样行 |
| 采样明细 | 时间、CPU、内存、磁盘、负载、并发任务、连接池、日志延迟；客户端分页 | `GET /system/metrics/history` 返回点 |

## 3. 关键设计

### 3.1 复用已有契约

- `history`：`from`/`to`/`step`；服务端按 `date_bin()` 降采样，点数 ≤720、窗口 ≤90 天，超出自动放大或 400；
- `summary`：窗口峰值、峰值时刻、最满挂载点、`since`；
- `metrics`：当前快照，含每个挂载点的 `usedBytes/totalBytes/usedPct`，因此饼图无需新增接口。

前端按时间窗推导 step（≤6h → 60s、≤24h → 120s、≤7d → 600s、更长 → 1800s），与服务端兜底一致。

### 3.2 新增通用饼图组件

`components/pie-chart.vue`：

- 纯 SVG 环形饼图（`thickness=0` 即实心），无第三方图表库依赖，符合 M6-018 离线约束；
- 扇区路径由起止角计算，单扇区（100%）留 0.99° 避免起止点重合不渲染；
- 中心可显示汇总值/说明（磁盘已用合计、内存已用占比、连接池 使用中/上限）；
- 图例显示名称、格式化数值、占比；`value<=0` 的项自动忽略；空数据显示占位；
- `formatter` 由调用方注入，磁盘/内存传字节格式化，连接池传整数。

配套单测 5 例：空数据、双扇区图例与占比、单扇区、formatter、中心汇总值。

### 3.3 查询与刷新语义

- 预设范围点击即重查（切换 `windowRange`）；
- RangePicker 选择后立即重查，同时「查询」按钮可重复执行；非法区间给出 warning 且不发请求；
- 历史查询失败清空曲线并提示，**不影响**顶部实时快照；
- 快照 30s 轮询一次，保留上一次值避免闪空；历史不自动轮询（避免无谓查询）。

### 3.4 术语与权限

- 文案遵循 M6-031：只出现「数据库连接池 / 磁盘 / 内存」等业务词，不暴露 PostgreSQL 等产品名；
- 路由 authority `dash:read`（与 `/api/v1/system/metrics*` 的 RBAC 域一致），内置 admin/operator/auditor/user 均有该权限。

## 6. 边界

- 不新增后端接口；饼图数据来自当前快照，因此只反映「最近一次采样」的构成，不随历史时间窗回放；
- 磁盘按挂载点汇总已用空间，btrfs 子卷等重复挂载会重复计数（已知边界，单机常规部署无影响）；
- 挂载点路径仅管理页展示，不进入 `/metrics`；
- 采样明细为服务端降采样后的点，查看原始分钟级数据请把窗口缩到 ≤6h。
