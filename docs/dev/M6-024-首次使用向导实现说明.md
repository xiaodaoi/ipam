# M6-024 首次使用向导实现说明

> 对应任务卡：`docs/pm/board/review/M6-024-首次使用向导.md`
> 范围：仪表盘入口、`/onboarding` 五步只读检测、浏览器本地状态、离线图标与 E2E 覆盖。

## 1. 为什么做「只读检测」而不是「配置表单」

向导只需要回答两个问题：**还差什么**、**去哪儿补**。若把组织/子网/DNS 表单搬进向导，
会出现两套校验与两套保存路径，后续改字段时必然漂移。因此：

- 每个步骤只调用既有只读接口，把结果折算成「已完成/待完成 + 摘要」；
- 具体创建/修改跳转到原页面完成，向导不持有表单状态；
- 进度每次进入页面重新派生，不以本地缓存充当事实。

代价是进入向导时会有 5 个并发只读请求（组织、子网、上游、区域、记录），
开发栈实测 < 200ms；单步失败只影响该步，不会让整页报错。

## 2. 五个步骤与判定口径

| 步骤 | 判定 | 跳转 |
|---|---|---|
| 建立组织架构 | `GET /orgs` 返回至少 1 个节点 | `/system/orgs` |
| 规划 DHCP 子网 | `GET /subnets` 至少 1 个子网 | `/dhcp/subnets` |
| 配置 DNS 上游 | 至少 1 个 `enabled=true` 的上游 | `/dns-service/upstreams` |
| 添加 DNS 区域与记录 | 存在区域，且前 5 个区域中至少读到 1 条记录 | `/dns-service/records` |
| 确认账号安全 | `totpEnabled=true` 或 `mustChangePassword=false` | `/profile` |

说明：

- 第 4 步只扫前 5 个区域，避免区域很多时产生 N 次请求；开发栈与常见交付规模下足够。
- 第 5 步不强制改密：交付默认关闭「首次登录强制改密」，因此「无待改密」即视为完成，
  同时把「建议启用 2FA」写进摘要，而不是阻塞完成。
- 任一步接口 401/403/网络错误 → 该步 `error` 文案「检测失败（可能无权限）」，其余步骤照常。

## 3. 状态与入口

- 键：`ipam.onboarding.v1.<username>`（`localStorage`）。
- 值：`{ completed?, dismissed?, updatedAt? }`。
- 仪表盘 banner：`!completed && !dismissed` 时显示；「稍后再说」写入 `dismissed`。
- 向导页：`已完成/已忽略` 时按钮变为「重新显示向导」，写入 `completed=false, dismissed=false` 并立即重检。
- 隐私模式/配额不足：写入失败静默降级（状态仅当前页面有效），不抛错、不影响使用。

> 账号名取自 `userStore.userInfo.username`；未加载完成时用 `anonymous` 作为兜底键，
> 因此状态隔离是「同一账号」级别，而不是「同一角色」。

## 6. 已知边界

1. **状态不跨设备**：按账号存浏览器，换机/清缓存会重新提示；若客户要求统一引导进度，需要新增用户偏好表（当前单机交付无此必要）。
2. **第 4 步采样**：只检查前 5 个区域的记录，超大规模下可能把「有记录但都在后段」误判为未完成；可后续按需改为 `GET /dns/records?limit=1` 一类的全局计数端点。
3. **权限**：无 DNS/组织读权限的账号会看到「检测失败（可能无权限）」，这是预期行为，不影响其使用其他模块。
