# M6-006 审计合规实现说明

## 1. 数据

迁移 0030 为 `operation_audit` 增加：

- `payload`：脱敏请求体 JSON（≤8KB）；
- `prev_hash`：上一条链哈希；
- `chain_hash`：本条 SHA256。

## 2. 写入

`audit_recorder.go`：

- 变更方法（POST/PATCH/PUT/DELETE）读取 body（limit 8KB）后立即恢复，保证 handler 正常读取；
- JSON 递归脱敏：key 含 password/token/secret/license/private/authorization/cookie → `***`；
- 非 JSON/超限不记录 payload。

`audit_pg.go`：

- 事务内 `pg_advisory_xact_lock(918273645)` 串行化；
- 读取上一条 `chain_hash`，`nextval('operation_audit_id_seq')` 预取 ID；
- `chain_hash = SHA256(prev + id + ts + 身份 + 方法/路径/动作/资源 + 状态 + detail + payload)`；
- 插入后提交；清理仍惰性执行（180 天）。

## 3. 校验

`GET /audits/verify?from&to`（logs:read，≤31 天）：

- 取时间窗内 `chain_hash <> ''` 的记录（最多 10000 条，按 id 升序）；
- 重算每条哈希；并校验 `prev_hash` 等于上一条 `chain_hash`；
- 返回 `{checked, valid, brokenId?, message}`。

前端审计页“完整性校验”按钮 + 头部 Tag；详情抽屉展示脱敏请求体与链哈希。

## 4. 边界

- 迁移前记录无链哈希，不参与；
- 超级用户可重算整链，需外部只读/备份/WORM 配合；
- before 快照未实现，当前记录变更后请求体；
- 保留 180 天（M5-032），未做 UI 可配置。
