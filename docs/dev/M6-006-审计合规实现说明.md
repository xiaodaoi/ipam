# M6-006 审计合规实现说明

## 1. 数据

迁移 0030 为 `operation_audit` 增加 `payload`、`prev_hash`、`chain_hash`；迁移 0038 再增加 `before_json`（M6-006 实体级变更前快照）：

- `payload`：脱敏请求体 JSON（≤8KB，变更后意图）；
- `before_json`：脱敏的变更前实体快照 JSON（≤8KB；仅对已登记 before 加载器的资源）；
- `prev_hash`：上一条链哈希；
- `chain_hash`：本条 SHA256。

## 2. 写入

`audit_recorder.go`（`Recorder`）：

- 变更方法（POST/PATCH/PUT/DELETE）读取 body（limit 8KB）后立即恢复，保证 handler 正常读取；
- JSON 递归脱敏：key 含 password/token/secret/license/private/authorization/cookie → `***`；
- 脱敏为 fail-closed：命中机密键且值为文本/数字时一律打码；布尔策略开关（如 `forcePasswordChange`）保留可读，便于审计辨识；
- 非 JSON/超限不记录 payload；
- **实体级 before 快照**：`RegisterBefore(resource, loader)` 按路由模板登记“变更前实体”加载器；中间件在 `c.Next()`（handler 执行）**之前**调用加载器读取旧实体，`json.Marshal` → 递归脱敏 → 序列化（≤8KB）后随审计入库。未登记资源 before 为空。
  - 已在 `cmd/control-plane/main.go` 登记：`/subnets/:subnetId`、`/users/:userId`、`/roles/:roleId`、`/orgs/:orgId`、`/system/security-settings`、`/system/log-export-settings`。
  - `payload`（变更后意图）+ `before`（变更前实体）配对即实体级 before/after。

`audit_pg.go`：

- 事务内 `pg_advisory_xact_lock(918273645)` 串行化；
- 读取上一条 `chain_hash`，`nextval('operation_audit_id_seq')` 预取 ID；
- `chain_hash = SHA256(prev + id + ts + 身份 + 方法/路径/动作/资源 + 状态 + detail + payload)`；
- `before` 非空时在末尾追加 `\n{before}` 参与哈希；为空则不计入，保证 0038 迁移前历史链不失效；
- 插入后提交；清理仍惰性执行（180 天）。

## 3. 校验

`GET /audits/verify?from&to`（logs:read，≤31 天）：

- 取时间窗内 `chain_hash <> ''` 的记录（最多 10000 条，按 id 升序）；
- 重算每条哈希；并校验 `prev_hash` 等于上一条 `chain_hash`；
- 返回 `{checked, valid, brokenId?, message}`。

前端审计页“完整性校验”按钮 + 头部 Tag；详情抽屉展示 **变更前实体（脱敏快照）**、脱敏请求体（变更后意图）与链哈希。

## 4. 边界

- 迁移前记录无链哈希，不参与；
- 超级用户可重算整链，需外部只读/备份/WORM 配合；
- 保留 180 天（M5-032），未做 UI 可配置。
