# M6-011 工程质量与发布流水线实现说明

## 1. 前端单测与覆盖率

- 入口：`cd web && pnpm test` → `vitest run --coverage apps/web-ipam`。
- 只跑 `apps/web-ipam`：上游 Vben 的 `date.test.ts` 依赖带斜杠的时区名，CI/容器常为 `UTC`，会误报；业务测试不应被上游环境假设阻塞。
- 覆盖率范围：`apps/web-ipam/src/utils/*.ts`（排除 `site-branding.ts`，其依赖浏览器偏好）。
- 阈值：lines/statements/functions 80%，branches 70%。
- 新增用例：
  - `mac.test.ts`：常见 MAC 写法归一化、非法输入；
  - `lease.test.ts`：剩余租期分级、过期、关键字过滤。

## 2. E2E

`tests/e2e/run.mjs`：

- 通过 `chromium.launch()` 启动；`PLAYWRIGHT_CHROMIUM` 可指定浏览器路径。
- 自动探测 `https://127.0.0.1:8443` 与 `http://127.0.0.1:8443`。
- 登录需拖动滑块；登录后根据 URL 是否含 `#/` 判断 hash/history 路由。
- 每步记录耗时；失败截图 + `artifacts/result.json`。
- 覆盖：健康检查、登录、仪表盘、子网、租约、DNS、日志检索、审计、账号。

CI（`.github/workflows/ci.yml` 的 `e2e` job）：

1. 复用 `web-ci` 的 `webui-dist`；
2. Go 编译控制面并以内存模式启动（`IPAM_POC_PASSWORD`/`IPAM_JWT_SECRET`）；
3. `pnpm exec playwright install --with-deps chromium`；
4. `node tests/e2e/run.mjs`。

## 3. 压测

`tests/load/main.go` 使用标准库，登录一次后并发 GET：

```bash
go run ./tests/load -base http://127.0.0.1:8443 -path /api/v1/subnets \
  -concurrency 20 -duration 10s
```

- 生产限流默认 600 次/分钟/IP；压测需隔离环境设置 `IPAM_RATE_LIMIT=0`，否则会出现 429（这是预期安全行为）。
- 本地内存模式基线（20 并发 5s）：subnets 18.6k RPS / p95 2.7ms；dashboard 16.5k RPS / p95 3.0ms（0 错误）。

## 4. 安全扫描

`security.yml`：govulncheck、gosec(SARIF)、pnpm audit、trivy fs。周度与手动触发，避免阻塞日常 PR；发现高危时由维护者开卡修复。

## 5. 发布

`release.yml` 在 tag `v*` 时矩阵构建全部自建镜像：

- `docker/build-push-action`：`linux/amd64,linux/arm64`、`sbom: true`、`provenance: true`；
- `anchore/sbom-action` 输出 SPDX JSON artifact；
- `cosign sign --yes` keyless 签名；
- `gh release create --generate-notes`。

边界：首次发布需验证 GHCR 权限、arm64 下 unbound 编译时长与 kea 基础镜像可用性；本环境未执行 tag 发布。
