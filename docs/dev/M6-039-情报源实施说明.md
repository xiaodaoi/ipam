# M6-039 情报源管理与分层编译：实现说明

> 关联：`docs/dev/M6-038-RPZ开源情报自动阻断-方案v1.md` §4/§8/§14，`docs/dev/M6-038-RPZ实施说明.md`（4 个固定区与热载链路）。
> 本文覆盖 M6-039 P1 主体（预设/自定义情报源、许可与密钥门禁、拉取解析、失败回退、分层编译与调度）与 P2 运营闭环（单源贡献上限、版本回滚、同步观测）。

## 1. 设计对接点

M6-038 已交付 4 个固定 RPZ 区，顺序即优先级：

```
wl.whitelist.rpz → intel.hot.rpz → intel.broad.rpz → intel.custom.rpz
```

M6-039 不新增区、不改区顺序，只负责**往 `intel.hot.rpz` / `intel.broad.rpz` 填内容**：

- 白名单仍由 `wl.whitelist.rpz` 的 passthru 承担，且编译时会把命中白名单的源域名从 hot/broad 剔除（减少无效记录、避免两区互相打架）；
- 编译/下发/回滚完全复用 M6-038 的「内容指纹 → 原子写 → 单区 `auth_zone_reload` → `list_auth_zones` 校验 serial → 失败回滚」链路，源头只是换成本地磁盘缓存；
- `intel.custom.rpz` 仍专供「名单/策略分组」编译，情报源不进入该区，便于排障时区分来源。

## 2. 数据与落盘

### 2.1 元数据入库，IOC 不入库

迁移 `db/postgresql/migrations/0045_intel_source.sql` 只建 `intel_source` 表，字段含名称、`key`、`kind`（preset/custom）、`layer`、`url`、`format`、`auth_header`、`secret_file`、许可信息、`update_interval`、`enabled`、`entries`、`last_sync_at`、`last_status`、`last_error`。

拉取到的域名写入 `<rpz dir>/sources/<key>.domains`（一行一个，原子 rename），编译时读取。这样百万级 IOC 不进入 PostgreSQL，也不会撑爆 audit/备份。

### 2.2 密钥不入库

- 服务端把密钥写到 `secretDir`（默认 `/run/ipam/intel-secrets`，`IPAM_INTEL_SECRET_DIR` 可覆盖，目录 0700、文件 0600）；
- **目录属主必须与控制面运行用户一致**：镜像以 `uid=10001(ipam)` 运行，`/run/ipam` 卷默认属 root，因此由 `volume-init` 预建 `/run/ipam/intel-secrets` 并 `chown 10001:10001`、`chmod 700`（见 `deploy/compose/compose.yaml`）；目录不可写时返回 `INTEL_SECRET_DIR_UNWRITABLE` 并提示设置 `IPAM_INTEL_SECRET_DIR`，不会把原始 `mkdir ... permission denied` 直接抛给用户；
- 库里只存 `secret_file` 路径；
- 接口只回 `hasSecret`，明文永不出站；
- `clearSecret=true` 删除文件并清空路径。

### 2.3 自定义源的 key

服务端在 `CreateSource` 时生成 UUID 并派生 `key = custom:<uuid>`，PG 显式写入该 id，保证「库内 key」与「磁盘缓存文件名」稳定一致（不依赖 DB 默认值返回）。

## 4. 启用门禁

`UpdateSource(enabled=true)` 时校验：

1. `url` 非空且以 `http(s)://` 开头 → 否则 `INTEL_SOURCE_NO_URL`（400）；
2. `requiresAck && AckedAt == nil` → `INTEL_SOURCE_LICENSE_UNCONFIRMED`（400），前端必须勾选「我已阅读并确认许可（含商用限制）」；
3. 需要鉴权（`authHeader` 非空，或 URL 含 `{secret}` 占位符）但密钥文件不存在 → `INTEL_SOURCE_SECRET_REQUIRED`（400）。

通过后立即调用一次 `SyncSource`。**同步失败不回滚启用状态**，只把 `last_status=failed` / `last_error` 写回，UI 在状态列展示——避免上游临时抖动导致「刚启用又被关掉」。

## 5. 解析器（`auto`）

`ParseFeedDomains` 逐行取第一个「像域名」的 token：

- 跳过注释（`#` `;` `!` `//`）与空行；
- 支持 `0.0.0.0 evil.com`（hosts）、`evil.com`（域名清单）、`http://evil.com/x`（URL 清单）、`"1","2026-01-01","http://evil.com/x"`（CSV）、`evil.com CNAME .`（RPZ 文本）；
- 跳过 IP 字面量、`localhost`、纯数字标签（日期/ID）、首尾连字符或空标签；
- 去重、小写、去尾点、去 `*.` 前缀。

## 6. 失败回退与容量

- 拉取失败 → 记 `failed` + `last_error`，**不写缓存**；
- 拉取成功但解析 0 条（多半是上游改版/返回 HTML）→ 记 `failed`，**不写缓存**；
- 只有解析出条目才原子替换缓存，因此旧数据继续拦截（fail-safe）；
- 分层编译时按层截断：hot ≤ 100 000、broad ≤ 300 000，超限写日志并停止继续追加；
- 编译时统一剔除白名单（`whitelisted` 支持后缀语义）。

## 7. 调度

`StartIntelScheduler(ctx, svc, time.Minute)`：每分钟扫一次已启用且有 URL 的源，`last_sync_at + update_interval` 到期才同步；无源启用时为空转。同步完成后由 `SyncSource` 调 `Compile`，内容没变时复用 serial、不写盘、不热载（M6-038 指纹机制）。

## 11. 修复记录

### 2026-11-19 · abuse.ch 同步返回 HTTP 410

- **现象**：配置 ThreatFox 的 Auth-Key 后同步失败，`lastError=http 410`。
- **根因**：abuse.ch 于 2026-10 关闭无鉴权下载，旧地址 `https://threatfox.abuse.ch/export/csv/recent/` 与 `https://urlhaus.abuse.ch/downloads/hostfile/` 全部 `410 Gone`；新 v2 导出要求 Auth-Key 作为 URL 路径段（`/v2/files/exports/<key>/hostfile.txt`）。
- **修复**：预设改为 v2 hostfile 地址并用 `{secret}` 占位；`HTTPSourceFetch` 拉取时替换占位符、错误文本抹掉密钥（含 URL 转义形态），避免 `lastError` 泄漏；`validateSource` 把 URL 占位符也视为「需要密钥」；迁移 `0046` 只升级仍是旧值的预设行；前端按 URL 占位符显示密钥输入框，并提示不要直接粘贴密钥到地址。
- **验证**：真实 key 拉取 ThreatFox hostfile `200 / 968994 字节`；产品内（临时自定义源）解析 `29262` 条并注入热层、`dig j8.asdlot.org` → NXDOMAIN、日志 `[intel.hot.rpz]`；假 key 返回 `http 401` 且 `lastError` 无密钥；`go test ./...`、`golangci-lint` 0 issues。


### 2026-11-19 · 保存鉴权密钥报 `mkdir /run/ipam/intel-secrets: permission denied`

- **根因**：控制面容器以 `uid=10001(ipam)` 运行，`/run/ipam` 是 root 属主的共享卷（0755），应用无法创建 `intel-secrets` 子目录；`volume-init` 之前只初始化了 `ch-exports`/`vector-config`。
- **修复**：`volume-init` 同时挂载 `ipam-run`，预建 `/run/ipam/intel-secrets` 并 `chown 10001:10001` + `chmod 700`；`writeSecret` 的 `MkdirAll`/`WriteFile` 失败统一包装为 `INTEL_SECRET_DIR_UNWRITABLE`，接口返回明确提示（含 `IPAM_INTEL_SECRET_DIR` 逃生口）。
- **验证**：重建后目录为 `drwx------ 10001:10001`；通过 API 写入探针密钥 → `hasSecret=true`、文件 0600；`clearSecret` 后文件删除、`hasSecret=false`；`go test ./...`、`golangci-lint` 0 issues。

## 12. 运营闭环（P2，2026-11-25）

> 目标：把「能同步」升级为「可运营」——限制单源垄断容量、出错可观测、劣化可一键回滚。迁移 `0055_intel_source_governance.sql`。

### 12.1 同步观测

- `intel_source` 增加 `last_duration_ms / last_added / last_removed / last_excluded`，列表接口直接返回，页面无需额外请求。
- 新增 `intel_source_run`：每次手动/定时/启用/回滚执行各记一条，包含耗时、状态、触发来源、条目数、增删量、白名单排除数、生成版本号与错误文本；每源保留最近 50 条。
- 接口：`GET /dns/intel/sources/{sourceId}/runs?limit=20`。
- 审计：同步/回滚 handler 写入 `auditmeta.DetailKey`，操作审计里可直接看到条目数、耗时、增删量与失败原因（密钥仍由通用脱敏规则处理）。
- 指标：`/metrics` 新增 `ipam_intel_source_enabled / entries / last_status / last_sync_timestamp_seconds / last_sync_duration_seconds`，按 `key`（及 `layer`）标注。

### 12.2 单源贡献上限（质量闸门）

- 每个源可配置 `maxSharePct`（0~100，默认 60，0=不限）。
- 仅当同层有 **多个** 启用源且总需求超过层容量（hot 10 万 / broad 30 万）时生效：单源最多贡献 `层容量 × pct%`，随后仍受全局容量截断。
- 只有一个源时不额外限制，避免单源部署被平台默认值截断；总需求未超容量时也不做配额，避免无意义丢条目。
- 白名单剔除发生在配额计数之前，被豁免的域名不占用源配额；同步时统计 `lastExcluded` 供 UI 展示。

### 12.3 版本快照与一键回滚

- 每次同步成功且域名集合发生变化（新增或移除），把解析后的原始清单写入 `<rpz>/sources/<key>/rev-<6位序号>.domains`，并在 `intel_source_revision` 记录版本号、条目数、SHA256；每源保留最近 20 个版本。
- 内容未变化不生成新版本（避免定时任务刷出大量空版本）；版本只存域名清单，不存上游正文。
- 接口：`GET /dns/intel/sources/{sourceId}/revisions`、`POST /dns/intel/sources/{sourceId}/revisions/{revision}/rollback`。
- 回滚将目标版本写回当前缓存、重编译对应层，并记录一条 `status=rolled_back, trigger=rollback` 的执行记录；原版本不删除，因此可再次回滚到回滚前版本（回滚可逆）。
- 当前生效版本由「当前缓存 SHA256」比对得出，列表返回 `active=true`。
- 删除自定义源时一并删除其版本目录（DB 侧 `ON DELETE CASCADE`）。

### 12.4 前端

- 情报源卡新增「贡献上限」编辑项、「运行记录」入口（同步记录 / 历史版本两个页签）。
- 状态列展示最近同步耗时与 `+新增 / -移除 / 白名单排除`；条目列展示当前配额。
