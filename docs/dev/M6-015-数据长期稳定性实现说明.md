# M6-015 数据长期稳定性与容量护栏实现说明

## 1. 采集端

`config/vector/vector.toml`：

```toml
buffer.type = "disk"
buffer.max_size = 1_000_000_000
buffer.when_full = "drop_newest"
request.retry_max_attempts = 10
request.retry_initial_backoff_secs = 1
request.retry_max_duration_secs = 60
```

- 磁盘缓冲位于 `vector-data` 卷，与 checkpoint 同卷；
- CH 短时不可用时最多堆积 1GB，超过丢弃最新，保护采集端/宿主；
- 重试 10 次、退避上限 60s，避免瞬时故障直接丢日志。

## 2. 查询端

`OpenChStore` 设置：

- `max_execution_time=3`；
- `max_memory_usage=1_000_000_000`；
- `max_bytes_before_external_group_by=256_000_000`；
- `max_bytes_before_external_sort=256_000_000`。

`ChStore.Query` 对 `count()` 使用 15s TTL、最多 256 条的进程内缓存，键为 SQL+绑定参数的 SHA256（时间转 UnixNano）。只缓存 total，不缓存明细，避免展示过期数据。

## 3. 指标

| 指标 | 来源 | 用途 |
|---|---|---|
| `ipam_log_rows` | `system.parts` | 在线行数 |
| `ipam_log_disk_bytes` | `system.parts` | 日志磁盘占用 |
| `ipam_log_parts` | `system.parts` | part 数量/合并压力 |
| `ipam_log_latest_age_seconds` | `max(ts)` | 采集停滞检测 |
| `ipam_host_disk_total_bytes` / `free_bytes` | hostmetrics | 容量比例/预测 |

`/metrics` 中 LogStats 查询失败会记录 `[metrics] log stats`，不影响其他指标输出。

## 4. 告警

见 `observability/alerts.yml`：

- `IpamLogPartsHigh` > 500；
- `IpamLogIngestStalled` > 600s；
- `IpamLogDiskGrowthFast` 6h > 5GB；
- `IpamLogDiskRatioHigh` > 60%；
- 原有磁盘 85%/90%。

## 5. 保留策略

`log_settings.retention_days`（1–3650）由页面配置，`ChAdmin.SetTTL` 修改主表与 MV 内表 TTL；归档按月 Parquet，保留月数可配置。多年留存建议“在线 180–365 天 + 归档多年”。

## 6. 验证

- `vector validate` 通过；Vector 重启无重放；
- `/metrics` 返回日志指标；
- 30 天查询首次 0.13s，重复查询 3–10ms（count 缓存 + ClickHouse 页缓存）；
- `golangci-lint` 0 issues；E2E 11/11。
