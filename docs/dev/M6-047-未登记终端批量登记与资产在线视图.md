# M6-047 未登记终端批量登记、忽略名单与资产在线视图

> 起因：M6-046 让 IPv6-only 终端可见后，「未登记终端」稳定在 240+ 条，但只能一条条登记；打印机/AP 等无需登记的终端混在列表里，真正待登记的终端被淹没；资产页只有通讯录信息，看不到终端现在是否在线、用的哪个地址；组织筛选还是精确匹配，与日志中心的子树口径不一致。

## 1. 需求与取舍

| 能力 | 取舍 |
|---|---|
| 批量登记 | **部分成功**（逐条校验/写入，失败项按 index 返回），不做整体回滚——批量登记 500 台不应因一行格式错误全废 |
| 忽略名单 | 独立表 `asset_ignore`，不污染资产登记（忽略项没有使用人/部门/组织）；按身份键（MAC 优先 / DUID 回退）抑制，可恢复 |
| 在线状态 | `GET /assets` 在服务端 join 联动绑定后产出 `ipv4/ipv6/state/online/lastSeen`，`online` 与仪表盘「在线租约」同口径（只认 active 且租期未过） |
| 组织筛选 | 资产列表按子树展开，与日志中心 `org_group.path` 口径一致；未知组织返回空而不是退化为全量 |

## 2. 契约（API 先行）

- `Asset` 新增只读字段：`ipv4`、`ipv6`、`online`、`state`、`lastSeen`；
- `AssetList` 新增 `onlineCount`；
- `GET /assets` 新增 `online` 查询参数（true/false），`orgId` 语义明确为"含全部子节点"；
- 新增 `POST /assets/bulk`：`AssetBulkRequest { items[] }` → `AssetBulkResult { ok, saved, failures[] }`，上限 500；
- 新增 `GET/PUT /assets/ignored`、`DELETE /assets/ignored/{identity}`：`IgnoredTerminal`、`IgnoredTerminalUpsert`、`IgnoredTerminalList`；
- 契约源：`api/openapi/{paths/asset.yaml,components/schemas/asset.yaml,openapi.yaml}`，再 `make gen`。

## 3. 后端实现

### 3.1 仓储与筛选

- `AssetRepo.List(ctx, orgIDs []string, q string)`：`nil`=不过滤；非 nil 空切片=组织不存在（返回空）；PG 用 `org_id::text = ANY($n)`；
- `AssetService.subtreeOrgIDs`：`orgs.Get` 校验存在后走 `subtreeIDs`（含自身），避免未知 ID 退化为全量；
- `AssetService.List` 统一入口，handler 不再直接触达 repo。

### 3.2 租约视图（`AssetLeaseIndex` / `LeaseIndex`）

```text
bindings ──resolveBindingIdentity──> identity (MAC 优先 / DUID 回退)
   ├─ online = 存在 state=active 且 cltt+valid_lft 未过期（或 cltt/valid_lft 缺省）
   ├─ state  = 该身份所有绑定中最严重者（conflict>grace>active）
   ├─ ipv4/ipv6 = 首个可用地址（过滤 0.0.0.0 / ::）
   ├─ lastSeen  = max(cltt)
   └─ DUID 别名：解析出 MAC 的绑定同时以 DUID 建索引，保证只存 MAC 的资产行也能命中
```

资产页按 `identity` 取视图，避免同一设备 v4/v6 两条绑定出现两次。

### 3.3 忽略名单

- 表 `asset_ignore(identity PK, mac, duid, reason, created_at)`，`lower(mac)` / `duid` 唯一索引（迁移 `0052_asset_ignore.sql`）；
- `Discover` 读取忽略名单后并入 `known` 集合：MAC、DUID、identity 三键同时生效，因此"先按 DUID 忽略、后解析出 MAC"仍被抑制；
- 删除不存在返回 404（`ErrIgnoredNotFound`）。

### 3.4 顺带修复

`logquery.PgOrgExpander` 原 `SELECT mac FROM asset` 在 `asset.mac` 允许为空后会扫描 NULL 失败，导致日志中心按组织过滤 500。改为 `coalesce(mac,'') ... WHERE mac IS NOT NULL` 并跳过空串（M6-046 迁移的连带回归）。

## 4. 前端

- **未登记终端**：表格多选 → 「批量登记（N）」（共享使用人/部门/组织，组织在所选终端同属一个子网时默认带入）、「忽略所选（N）」；行内新增「忽略」；右上「忽略名单」弹窗展示身份/原因/时间并可「恢复」；
- **资产登记**：新增「当前地址」「在线状态」列与在线/离线筛选（服务端参数）；统计卡由"标签覆盖"改为"在线终端 + 离线台数"；CSV 增加 IPv4/IPv6/在线列；
- zh/en 文案成对；术语表补「忽略名单 / 批量登记」。

## 5. 验证

**单测（`go test ./internal/module/ipam/`）**

- `TestAssetListExpandsOrgSubtree`：根含子树 2 条、子节点 1 条、未知组织 0 条；
- `TestDiscoverSkipsIgnored`：DUID 忽略 → 解析出 MAC 后仍被抑制；恢复后再次可发现；重复恢复 404；
- `TestBulkUpsertPartialSuccess`：2 成功 + 2 失败（BAD_MAC / OWNER_REQUIRED），index 正确；
- `TestAssetLeaseIndex`：active 在线、grace 不计在线、过期剔除、conflict 状态保留、DUID 别名命中；
- handler：`TestAssetHandler_OnlineEnrichmentAndFilter`（在线字段 + online=false 过滤）、`TestAssetHandler_BulkAndIgnore`（部分成功 / 400 / 忽略后不出现 / 恢复 404）。

**真实环境（2026-11-24）**

```text
[migrator] applied 0052_asset_ignore
GET /assets/discovered -> 246
POST /assets/bulk (3 项，1 项非法 MAC) -> ok=false saved=2 failures=[{index:2,BAD_MAC}]
GET /assets?q=P1批量测试 -> 2 条，online=true，带 ipv4/state=active/lastSeen，onlineCount=2
GET /assets?online=false -> 0（仅有的两条资产在线）
PUT /assets/ignored（DUID-only 终端）-> 发现列表 246→243（1 忽略 + 2 已登记），忽略项不在列表
GET /assets/ignored -> 1 条；DELETE -> 204；发现列表恢复 244
组织子树：父节点 2 条 / 子节点 1 条 / 未知组织 0 条
清理后 asset=0、asset_ignore=0
```

E2E 新增「批量登记与忽略名单（API）」步骤，并在「未登记终端发现」「资产登记」中断言多选/忽略名单入口、当前地址/在线状态列；**23/23 通过**。

## 6. 遗留

- 忽略名单目前无原因输入框（接口已支持 `reason`），后续可在忽略时弹窗填写；
- 资产页仍为前端分页（`/assets` 未做 cursor/offset 分页与 `pg_trgm`），终端规模再上一个量级需服务端分页 + 统计；
- 组织筛选在内存实现下走节点遍历、PG 走 `org_id::text = ANY`，若组织数上万需改为 `org_group.path LIKE` 直接子查询；
- 忽略名单未纳入审计事件（属于低风险抑制操作）。
