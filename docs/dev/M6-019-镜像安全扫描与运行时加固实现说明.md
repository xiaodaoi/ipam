# M6-019 容器镜像安全扫描与运行时加固实现说明

> 目标：补齐发布产物**镜像层 CVE 扫描**门禁，并统一容器运行时加固；不改动受业务约束的以 root 运行场景（unbound/kea）。

## 1. 背景与缺口

现有安全能力：`govulncheck`、`gosec`、`pnpm audit`、`trivy fs`（源码依赖）、SBOM + cosign 签名。
缺口：
- `release.yml` 构建并推送镜像，但**未扫描镜像内 OS/库漏洞**（`trivy fs` 看不到运行镜像）；
- 无 Dockerfile/compose 误配扫描；
- 运行时加固不一致：`unbound`/`kea*` 缺 `no-new-privileges`，`coherence-daemon` 无健康检查。

## 2. 实现

### 2.1 发布门禁镜像扫描（`release.yml`）
新增 `image-scan` job（`needs: images`），矩阵扫描 `control-plane/coherence-daemon/unbound/kea-dhcp4/kea-dhcp6/kea-ctrl-agent`：
- 登录 ghcr，`aquasecurity/trivy-action` 以 `scan-type: image` 扫描 `:${{ github.ref_name }}`；
- `severity: HIGH,CRITICAL` + `ignore-unfixed: true`（只对可修复漏洞阻断，避免上游未修版本卡发布）；
- 输出 SARIF 上传代码扫描；命中即非零退出；
- `release-notes` 改为 `needs: [images, image-scan]`，扫描不过则不产出 Release。

### 2.2 周期配置扫描（`security.yml`）
新增 `trivy-config` job：`scan-type: config`，扫描 `deploy/` 的 Dockerfile/compose 误配，`severity: HIGH,CRITICAL`，
`trivyignores: .trivyignore.yaml`。

### 2.3 本地脚本（`scripts/scan-images.sh`）
- 默认扫描 `ipam/{control-plane,coherence-daemon,unbound}:${IPAM_VERSION:-0.1.0-dev}`；
- trivy 解析顺序：PATH 中的 `trivy` → `docker run aquasec/trivy`（挂 docker.sock）；
- 两者均缺失时明确跳过；`--strict` 下判失败；命中 HIGH/CRITICAL 可修复漏洞非零退出。
- Makefile：`make scan-images`。

### 2.4 误配修复与例外（`.trivyignore.yaml`）
- 修复 `Dockerfile.prebuilt` 的 DS-0029（`apt-get install` 补 `--no-install-recommends`）；
- 对 DS-0002（镜像以 root 运行）在 `kea`/`unbound`/`coherence-daemon` 三处按路径抑制，附理由与到期日：
  - `unbound`：需绑特权端口 53 并依赖内置 `username: unbound` 降权（chroot 关闭，§6.2）；
  - `kea-dhcp4/6`：需绑特权端口 67/547 且 DHCP 数据面 `socket-type: raw`（需 CAP_NET_RAW）；
  - `coherence-daemon`：非 root 化需重构多 uid 共享的 `/run/ipam` 属主（待办，见任务卡）。

### 2.5 运行时加固（`deploy/compose/compose.yaml`）
- `unbound`/`kea-dhcp4`/`kea-dhcp6`/`kea-ctrl-agent` 增加 `security_opt: no-new-privileges:true`（不缩减其特权能力，仅禁止经 execve 提权）；
- `coherence-daemon` 增加 `healthcheck: test -S /run/ipam/coherence.sock`。

## 3. 为什么不把 coherence-daemon 改成非 root

`/run/ipam` 为多容器共享 UDS 卷：`control-plane`(uid 10001)、`unbound`(uid 999)、`kea`(root)、`coherence-daemon`
均在此创建 socket/文件。当前目录属主 root:root 0755，各服务以“各自身份创建后再 chown”或 root 方式工作。
非 root 化需要将目录改为共享组可写（如 root:10001 0775）并逐个核对创建时序（unbound 绑 53 后降权、kea raw socket），
属**高风险改动**；本卡不改，仅记录约束与建议，避免破坏 DNS/DHCP 数据面。

## 4. 验证证据

- `docker compose config` 通过；`no-new-privileges` 覆盖 9 个服务（+4）；
- 重建 `coherence-daemon/unbound/kea*` 后：`coherence-daemon` 健康检查 **healthy**、unbound 监听 53（UDP/TCP）、
  kea-ctrl-agent 命令返回 **200**、control-plane `/readyz` ready；**E2E 15/15**；
- `trivy config --skip-check-update --severity HIGH,CRITICAL --ignorefile .trivyignore.yaml deploy`：
  **0 命中**（修复 DS-0029、抑制 DS-0002）；
- `bash -n scripts/scan-images.sh`、工作流 YAML 解析通过。

## 5. 边界

- 镜像 CVE 扫描依赖漏洞库下载：本开发机 `mirror.gcr.io`/`registry-1.docker.io` 不可达，未能本地跑完 DB 下载；
  GitHub Actions 托管 runner 可正常获取，`image-scan` 在 CI 生效。
- 配置扫描的 `.trivyignore.yaml` 路径相对扫描根（`deploy/`）书写，改动 `scan-ref` 时需同步。
- 后续可将 `coherence-daemon` 非 root 化（含共享卷属主重构）单独立卡。
