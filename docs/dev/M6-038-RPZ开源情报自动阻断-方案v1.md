> 卡号：`M6-038`。**P0 已实施并验证通过（2026-11-19）**，实现见 `docs/dev/M6-038-RPZ实施说明.md`；

> 关联：吸收「封禁运行时账本/实际态」历史缺陷；替代 `blocklist` 的 `local_zone` 运行路径

## 1. 目标与非目标

### 1.1 目标

1. **自动获取互联网开源威胁情报**，按策略自动阻断恶意域名与恶意应答 IP。
2. **情报源由用户完全维护**：可新增、编辑、克隆、启用/禁用、删除、回滚；上游接口变更时无需等待版本升级。
3. **白名单豁免必达**：误报可被人工与自动机制及时放行，且放行对全链路生效。
4. **性能可预算**：容量与更新代价可量化，不因情报更新造成解析中断。
5. **可观测**：拦截量、命中排行、情报源健康度、误报候选全部可见可审计。
6. **合规可控**：开源情报**默认全部关闭**，由用户阅读许可后手动启用；不引入 GPL 依赖。

### 1.2 非目标（明确边界）

| 非目标 | 原因 | 后续 |
|---|---|---|
| URL 路径级阻断（`http://x.com/a/b`） | DNS 层只能到域名/应答 IP | 需引入 SWG/代理，单独立项 |
| 客户端绕过防护（DoH/自改 DNS） | 属网络边界职责 | 建议项：Kea 只下发内网 DNS + 边界阻断 53/853 与公共 DoH（见 §12.4） |
| 按客户端网段差异化策略（view/tag） | 当前 `policy_group.view_name/cidrs` 未真正参与拦截 | P3 用 `tags`/`view_*` 实现，需先做可行性验证 |
| 情报数据再分发 | 各源许可限制 | 产品只做运行时拉取，不内置、不转发数据 |

## 2. 现状与实测基线

### 2.1 当前实现事实

- unbound **1.26.0**，`Linked modules: dns64 python respip validator iterator` → **RPZ 原生可用**（依赖 `respip`），但现配置 `module-config: "python iterator"` **缺 respip，需改 `"python respip iterator"` 并重启一次**。
- 现有封禁走 `unbound-control local_zone <name> static`（`internal/module/dns/blocklist.go`），`BuildRPZZone` 为死代码，`conf_apply.go` 的 `RpzZones` 渲染逻辑存在但无 zonefile 落地。
- `policy_group.view_name/cidrs` 只在 `/dns/diagnose` 提示中生效，**不参与实际拦截**。
- 拦截日志无 `action=blocked`（ClickHouse 计数为 0）→ 仪表盘「今日拦截量」恒为 0。
- 实测复现缺陷：`RemoveEntryZone` 不清 `applied` 记账、`Reconcile` 只信内存记账 → **删条目后重新添加、或 unbound 单独重启后，该区块不再下发**（`www.crphb.com` 曾真实未被拦截）。

### 2.2 RPZ 能力实测（临时实例，已清理，生产未动）

| 验证项 | 结果 |
|---|---|
| QNAME 拦截 / 泛域名 | `CNAME .` → NXDOMAIN；`*.x` 生效 |
| 动作 | `rpz-drop` 丢包；`rpz-tcp-only` UDP 截断后走 TCP；Local Data（`A <提示页IP>`）直接返回自定义答案 |
| 白名单 `rpz-passthru` | **zone 顺序决定优先级**：白名单 zone 在前 → 放行；在后 → 仍被拦 |
| `local-zone` 与 RPZ 优先级 | **`local-zone` 优先于 RPZ**：同时存在时白名单 passthru 无效 → **现有封禁必须迁移到 RPZ，否则豁免无效** |
| 空 zone（仅 SOA/NS） | 正常加载、不拦截；单区热载 **7 ms** → **停用源无需改配置、无需整机 reload** |
| 损坏 zone 文件 reload | `error failed to read <zone>`，zone 进入 expired，**未缓存域名直接无结果**（服务降级） → **必须先校验再原子替换，坏文件自动回滚** |
| 运维接口 | `list_auth_zones`（含 RPZ 与 serial）、`auth_zone_reload <zone>`、`rpz_enable/rpz_disable`、`fast_reload` |
| 拦截日志格式 | `info: rpz: applied [<rpz-log-name>] <qname> <rpz-action> <client_ip>@<port> <qname> <qtype> IN` |

### 2.3 容量与更新代价实测（合成 RPZ zone）

| 条目数 | zone 文件 | 启动加载 | 常驻内存 | 全量 reload（命令耗时） |
|---|---|---|---|---|
| 10 000 | 244 KB | 152 ms | 18 MB | 79 ms |
| 50 000 | 1.3 MB | 485 ms | 41 MB | 428 ms |
| 100 000 | 2.5 MB | 920 ms | 70 MB | 887 ms |
| 300 000 | 7.7 MB | 2.8 s | 186 MB | 2.9 s |
| 1 000 000（外推） | ~26 MB | ~9 s | ~620 MB | ~10 s |

**更新期间的用户影响（300k 条、4 线程、约 96 QPS 持续探测、客户端 1 s 超时）：**

| 操作 | 控制命令耗时 | 查询失败 | 最大单查询延迟 | 内存 |
|---|---|---|---|---|
| `auth_zone_reload <zone>` | 2.9–3.2 s | **0 SERVFAIL / 0 拒绝**；0.2–0.3% 单查询超时 | ≤1 s | 不变 |
| `reload`（整机，清缓存） | <10 ms 返回（zone 后台加载） | 0.26% 超时 | 99 ms | +6 MB |
| `fast_reload` | 3.2 s | **0** | 2 ms | 187→361 MB（翻倍） |

结论：
- 「3 秒停顿」实质是**构建新结构的耗时，不是服务中断**；切换瞬间仅毫秒级锁，用户侧表现最多是单条查询多等 ≤1 s，客户端会重试。
- 真正的用户可感风险是 **`reload` 清空缓存导致的回源尖峰**，而非 CPU 停顿。
- `num-threads` 必须 ≥4（当前为 1），否则切换窗口更明显。

## 3. 总体架构

```
   ┌─ 预设模板（随版本发布，只读，默认关闭）────────────┐
   │  abuse.ch URLhaus / ThreatFox / Spamhaus DROP …   │
   └───────────────┬───────────────────────────────────┘
                   │ 用户克隆 / 填写 key / 启用
   ┌───────────────▼───────────────┐
   │ 情报源（PG，用户可增删改）      │  endpoint[] / 鉴权 / 格式 / 层级 / 动作 / 间隔
   │ 状态：enabled · mode · health  │  草稿 → 校验 → 生效 → 版本回滚
   └───────────────┬───────────────┘
                   │ 内置调度（默认全关；启用后按间隔，带抖动）
   ┌───────────────▼───────────────────────────────────────────────┐
   │ 同步器：条件请求 → 下载(tmps) → 解析适配 → 规范化 → 去重       │
   │        → 质量闸门 → 与白名单求差 → 编译 zone → 原子替换        │
   │        → auth_zone_reload（失败自动回滚）+ 指标/审计           │
   └───────────────┬───────────────────────────────────────────────┘
                   │ 固定 4 个 rpz: clause（永不在运行期增删）
   ┌───────────────▼───────────────────────────────────────────────┐
   │ unbound                                                       │
   │  ① wl.whitelist.rpz   passthru（必须第一）                     │
   │  ② intel.hot.rpz      高频层（≤10 万）                         │
   │  ③ intel.broad.rpz    宽层（≤30 万）                           │
   │  ④ intel.custom.rpz   本地自定义（原封禁条目迁移至此）          │
   │  module-config: "python respip iterator"                       │
   └───────────────┬───────────────────────────────────────────────┘
                   │ rpz 日志行
   ┌───────────────▼───────────────┐    ┌──────────────────────────┐
   │ vector → ClickHouse logs       │───→│ 仪表盘拦截量 / 命中排行   │
   │ action=blocked, block_zone …   │    │ 误报候选 / 源健康度       │
   └────────────────────────────────┘    └──────────────────────────┘
```

**设计原则**

1. **配置与数据分离**：`rpz: clause` 固定 4 个，永不动态增删（避免整机 reload 与缓存抖动）；启停通过「写空 zone + 单区热载」实现。
2. **默认关闭**：安装后 0 个情报源启用，4 个 zone 为空（仅 SOA/NS）。
3. **fail-safe 而非 fail-open**：拉取失败保留最后好数据继续拦截；坏数据在落地前被拒绝。
4. **先校验后生效**：任何变更都不直接触碰运行态。

## 5. 情报源管理（用户维护的核心）

### 5.1 三层来源模型

| 层 | 说明 | 可编辑 | 升级影响 |
|---|---|---|---|
| **预设模板** | 随版本发布的只读条目（端点/格式/许可/推荐间隔） | ❌ 可克隆 | 升级时更新，展示「预设已更新（差异）」→ 采纳/忽略 |
| **用户源** | 用户新建或由预设克隆，独立存储 | ✅ 全部字段 | 不受升级覆盖 |
| **上传源** | 隔离环境离线导入的 zone/CSV | ✅ | — |

### 5.2 状态机（4 个正交维度，不合并成一个开关）

| 维度 | 取值 | 语义 | 影响运行态 |
|---|---|---|---|
| `enabled` | on/off | 是否参与 zone 编译 | ✅ 重编译 + 单区热载 |
| `mode` | `active` / `shadow` | 正式拦截 / 只记录（`rpz-action-override: disabled` + `rpz-log`） | ✅ |
| `health` | `ok` / `stale` / `paused` | 连续失败自动 `paused`（**旧数据继续生效**） | ⚠️ 不改策略 |
| `config_state` | `clean` / `dirty` / `drift` | 草稿未生效 / 预设已更新 | ❌ |

### 5.3 新增 / 编辑流程（草稿 → 校验 → 生效）

```
① 编辑表单（可随时保存草稿，不影响运行态）
② 测试：真拉 + 真解析，返回报告（不落盘）
    · HTTP 状态 / Content-Type / 大小 / 耗时 / 格式自动识别（含置信度）
    · 条目数 / 坏行数 + 前 5 条样例 / 与内置豁免库冲突条目
    · 抽样 5 条将被拦截的域名
③ 生效：编译 → 质量闸门 → 原子替换 → auth_zone_reload → serial 校验 → 失败回滚
④ 生成 revision（配置 + 编译结果 + diff），支持 diff 查看与一键回滚
```

### 5.4 生效路径与代价

| 操作 | 生效路径 | 代价 | UI 提示 |
|---|---|---|---|
| 编辑备注/间隔/许可/动作 | 仅 DB | 0 | 立即 |
| 启用/停用热层源 | 重编译 hot → 单区热载 | 79–887 ms | 无感 |
| 启用/停用宽层源 | 重编译 broad → 单区热载 | ≈3 s 命令；0.3% 查询多等 ≤1 s | 建议低峰（可预约） |
| 修改动作映射 | 重编译受影响 zone | 同上 | 同上 |
| 全部停用（应急） | 4 zone 写空 → 4 次单区热载 | 每区 ~7 ms | 立即 |
| 需立刻清缓存 | `fast_reload`（默认）/ 低峰 `reload` | 内存瞬时限翻倍 / 回源尖峰 | 需显式勾选 |

**缓存语义（必须写进实现）**

- `cache-max-ttl=300` → 停用/豁免后最长 5 分钟仍可能按旧结果应答。
- 白名单（几十条）→ 逐条 `flush_zone`（实测 22 ms/条）。
- 整源停用（万级）→ **不逐条 flush**（10 万条约 37 分钟），采用「自然过期 + 可选 `fast_reload`」。

### 5.5 导入 / 导出

- 源配置导出 YAML/JSON（**不含密钥**），支持多节点批量部署与灾备恢复。
- 上游接口变更时，可一次导入修好的配置。

## 6. 上游变更防护（8 道护栏）

| # | 护栏 | 目的 |
|---|---|---|
| 1 | 多端点 + 优先级 + 单端点启停 | 主端点 410/404 时自动切备 |
| 2 | URL 模板变量 `{{auth_key}} {{yyyy}} {{mm}} {{dd}}` | 适配带鉴权/带日期的路径；key 只在服务端渲染 |
| 3 | 格式自适应 + 用户锁定 | 上游把 RPZ 换成 hosts 时不误解析 |
| 4 | 内容契约校验 | 识别 HTML 登录页/410 页面/空文件/JSON 错误体（**否则会出现"同步成功但 0 条"**） |
| 5 | 突变阈值 | 条目数变化 >±50% 或单次删除 >30% → 拒绝本次并保留旧版 |
| 6 | 连续失败自动 pause | 3 次失败 → `paused`（旧数据继续拦截）+ 告警；支持一键 resume |
| 7 | 预设漂移检测 | 版本升级带来的预设差异 → 采纳/忽略；**用户改过的字段永不被覆盖** |
| 8 | 配置导入导出 | 快速修复全部源；灾备重建 |

## 7. 白名单与误报闭环

### 7.1 四层白名单

| 层 | 机制 | 说明 |
|---|---|---|
| L1 源侧裁剪 | 同步器按配置裁剪子集 | ZRD 不加载；DBL 只取 phishing/malware；URLhaus 自带 Top1M 排除 |
| L2 内置永久豁免库 | 编译期内置 passthru 条目，不可删 | Microsoft/Apple/OCSP、主流 CDN、支付与办公 SaaS 登录域 |
| L3 运维豁免表 | `intel_whitelist` + UI | `pattern + 原因(必填) + 类别 + 有效期 + 操作人`；立即生效 |
| L4 自动误报收敛 | 每日任务（ClickHouse 命中） | 7 天内被 ≥N 个不同客户端访问且查询量 Top 50 → 进「疑似误报」队列（不自动放行）；同源连续 3 天产生误报 → 自动降级 `shadow` |

### 7.2 白名单生效链路（顺序不可错）

```
写 wl.whitelist.rpz（passthru，必须第一个 rpz clause）
  → auth_zone_reload wl.whitelist.rpz
  → flush_zone <domain>（清除负缓存，22 ms/域）
  → 校验：dig 应返回正常解析
```

### 7.3 影子模式（上线安全阀）

`rpz-action-override: disabled` + `rpz-log: yes` → 只记录「将会拦截什么」，不真正拦截。新建源可配置 `shadow_days`（默认 7），到期提示切换为 `active`。

## 8. 编译与下发

### 8.1 zone 布局

| 顺序 | zone | 内容 | 目标规模 | 更新频率 |
|---|---|---|---|---|
| ① | `wl.whitelist.rpz` | 豁免（passthru） | ≤1 万 | 事件驱动 |
| ② | `intel.hot.rpz` | 高置信、高频（URLhaus/ThreatFox/自定义热条目） | ≤10 万 | 15 min |
| ③ | `intel.broad.rpz` | 宽层（DBL 子集、DROP rpz-ip 等） | ≤30 万 | 6 h + 低峰 |
| ④ | `intel.custom.rpz` | 本地自定义（原封禁条目迁移） | 任意小 | 事件驱动 |

文件与元数据：
- `config/unbound/zones/rpz/<zone>.zone`（容器内 `/etc/unbound-rendered/zones/rpz/`）
- `<zone>.meta.json`：`sha256 / entries / soa_serial / source_ids / built_at`
- 历史快照：`history/<zone>.<sha8>.zone`（保留 5 份，用于回滚）

### 8.2 编译规则

1. **SOA serial 每次编译递增**（epoch 秒），保证任何 reload 路径都能感知变化。
2. 只输出 unbound 支持的 trigger：QNAME、Response-IP；丢弃 `nsdname/nsip/clientip`。
3. 域名规范化：小写、punycode、去尾点、去非法字符；URL 类源提取 host（丢 path/query）。
4. IP 类 IOC → `rpz-ip` 形态（`<reversed>.rpz-ip CNAME .`）。
5. 与白名单求差（域名及其子域全剔除）。
6. 去重后按字典序输出（稳定 diff，便于版本比较）。

### 8.3 下发流程（永不覆盖运行中的坏文件）

```
写 <zone>.zone.tmp
  → 控制面自解析校验（行数/语法/坏行率/最小条目）
  → fsync + 原子 rename
  → unbound-control auth_zone_reload <zone>
     失败 → 立即恢复上一份快照并再次 reload → 标记 APPLY_ROLLED_BACK
  → unbound-control list_auth_zones 校验 serial 与预期一致
     不一致 → 同上回滚
```

## 9. 性能设计与容量预算

| 项 | 取值 | 依据 |
|---|---|---|
| 热层上限 | 10 万条 | reload 887 ms、内存 70 MB |
| 宽层上限 | 30 万条 | reload ≈3 s、内存 186 MB |
| 超过上限 | 走 `fast_reload`（内存瞬时限翻倍）或蓝绿 | 实测 fast_reload 0 超时 |
| `num-threads` | ≥4（建议 4） | 单线程切换窗口更明显 |
| 更新窗口 | 热层全天；宽层低峰 + 抖动 | 0.3% 查询延迟可接受，但不叠加 |
| 内存告警 | 容器内存 >80% → 自动暂停宽层更新 | 降级不宕机 |
| 缓存 | 保持 `cache-max-ttl=300` | 决定停用/豁免的生效时延上限 |

**可选（P3，若有零中断 SLA）**：双 unbound 蓝绿 + 切换层（iptables/HAProxy）+ `dump_cache`/`load_cache` 预热。

| 情报类别 | 置信度 | 默认动作 | 说明 |
|---|---|---|---|
| 恶意载荷分发（URLhaus） | 高 | `CNAME .`（NXDOMAIN） | 默认 |

## 13. 合规与安全

1. **不引入 GPL 依赖**：HaGeZi/OISD（GPL-3.0）不内置；`rsync`（GPLv3）不使用，改用 HTTPS + `curl`。
2. **abuse.ch 许可**：社区 API 明确不授权用于商业产品 → 产品不内置其数据，由客户自备 key（客户为被许可方）；对外交付需法务确认，或采购商业 API。
3. **密钥**：仅存引用（环境变量/secret 文件），不入库、不回显、不写日志；渲染 URL 时脱敏。
4. **审计**：源的增删改、启停、生效、回滚、白名单变更全部记审计（操作人/时间/前后差异）。
5. **默认安全姿态**：全部情报源默认关闭；启用需显式确认许可；新源默认 `shadow`。
6. **失败安全**：拉取失败/数据异常 → 保留旧数据继续拦截（fail-safe），绝不因更新失败而放行。

**单元测试**
- 格式适配器表驱动：rpz / hostfile / domains / urls / csv / json；含坏行、HTML 登录页、空文件、超大文件、编码异常。

- 启停：停用后 zone 为空且不拦截；启用后条目数正确。

**集成 / 故障注入**
- 上游返回 HTML/410/截断 → 不落地、保留旧数据、标记 rejected。
- 写坏 zone 后 reload → 控制面必须已拦截（不允许 unbound 读到坏文件）；人为制造 apply 失败 → 自动回滚且 serial 校验通过。
- unbound 重启后实际态校正（`list_auth_zones` 为空 → 重新下发）。
- `flush_zone` 后白名单立即生效（dig 验证）。

**性能 / 回归**
- 10 万 / 30 万条压测脚本（记录 reload 耗时、查询超时率、内存），阈值：0 SERVFAIL、超时率 <1%、命令耗时 <5 s（30 万）。
- 3000 客户端模拟的冷缓存回源尖峰观察（可选）。

**E2E / 界面**
- 新增源 → 测试 → 启用 → 命中 → 白名单豁免 → 停用，全链路；zh/en 文案成对；默认关闭引导存在。

## 16. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 上游改接口/加鉴权（如 abuse.ch 2026 迁移） | 同步失败或 0 条 | 8 道护栏 + 保留旧数据 + 暂停告警 + 导入导出快速修复 |

| 大规模 zone 启动慢 | 重启时间长 | 宽层 ≤30 万；启动时间纳入 SLO 文档 |

## 18. 附录：实测环境与原始数据

- 环境：unbound 1.26.0（容器 `ipam-unbound-1`），临时实例端口 15353/15354/15355/15356，`module-config: "respip validator iterator"`，`num-threads` 1 与 4 对比；测试结束已删除临时目录，生产实例未修改。
- 探测方式：Go UDP 客户端，约 96 QPS，客户端超时 1 s，逐秒统计成功/超时；另用 `dig` 做功能验证。
- 关键原始结果：
  - 300k zone 启动 2815 ms / RSS 186 MB / 全量 reload 2907 ms。
  - `auth_zone_reload` 2.9–3.2 s，0 SERVFAIL，2–3/1060 超时，最大延迟 ≤1 s。
  - `fast_reload` 3.2 s，0 超时，最大 2 ms，RSS 187→361 MB。
  - 空 zone 单区 hot load 7 ms。
  - 损坏 zone reload → `error failed to read <zone>`，zone expired，未缓存名无结果。
  - rpz 日志样例：`info: rpz: applied [spamhaus-dbl] wikipedia.org. rpz-nxdomain 127.0.0.1@53113 wikipedia.org. A IN`。
  - 白名单顺序：前 → 放行；后 → 拦截；`local-zone static` 存在时 passthru 无效。
