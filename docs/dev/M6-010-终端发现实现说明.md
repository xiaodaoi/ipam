# M6-010B2 未登记终端发现实现说明

## 1. 数据来源

`coherence_binding` 由 Kea 租约同步（30s）维护，包含 MAC、IPv4、IPv6、主机名、状态与 cltt。
发现逻辑将绑定与 `asset` 表按归一化 MAC 做差集。

## 2. 后端

`AssetService.Discover(ctx, bindings)`：

- MAC 归一化（小写冒号格式）；
- 跳过 `inactive`；
- 同一 MAC 去重（IPv4/IPv6 双栈只保留一条）；
- IPv6 `::` 归一为空；
- 按 `cltt` 倒序；
- 资产表已有 MAC 不返回。

端点：`GET /assets/discovered`（assets:read），handler 通过 `SetBindingSource` 注入 PG 绑定加载函数，未注入时返回空列表（便于单测/内存模式）。

## 3. 前端

页面：DHCP 服务 → 未登记终端（`/dhcp/ledger/discovered`）。

- KPI：未登记数、有 IPv4、有 IPv6、最近活动；
- 搜索 MAC/IP/主机名；
- 状态着色（conflict 红、grace 橙、active 绿）；
- 「登记」弹窗：MAC 只读，使用人必填，部门/组织/备注可选；调用现有 `PUT /assets`；
- 登记成功后刷新列表（该 MAC 消失），可在资产页继续维护标签。

## 4. 验证

- 单测：`TestDiscoverUnregistered`（已登记排除、重复去重、inactive 过滤、IPv6/主机名）。
- 真实环境：
  - `GET /assets/discovered` 返回 `00:0c:29:29:11:4f`（10.61.40.20）；
  - `PUT /assets` 登记后列表为 0；
  - `DELETE /assets/{mac}` 后恢复；
- E2E：`/dhcp/ledger/discovered` 页面加载通过（11/11）。

## 5. 边界

- 仅展示 coherence 绑定中的终端；从未产生租约的设备不会出现；
- 发现列表不自动登记，避免误建资产；
- 同一 MAC 多 IP 只显示一条（IPv4/IPv6 各取绑定值）。
