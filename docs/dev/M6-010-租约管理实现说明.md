# M6-010A 租约管理实现说明

## 1. 设计

Kea 租约保存在 memfile 中，控制面**不落库**，通过 ctrl-agent 的 lease_cmds hook 实时读写：

| 能力 | Kea 命令 | 端点 |
|---|---|---|
| v4 列表 | `lease4-get-all` | `GET /dhcp/leases4` |
| v4 单条 | `lease4-get` | 更新前存在性检查 |
| v4 延期/改绑 | `lease4-update` | `PATCH /dhcp/leases4/{ip}` |
| v4 释放 | `lease4-del` | `DELETE /dhcp/leases4/{ip}` |
| v6 释放 | `lease6-del` | `DELETE /dhcp/leases6/{ip}?leaseType=` |

延迟以 `valid-lft` 写回；改绑以新 `hw-address` 写回；`subnet-id` 来自现有租约，避免调用方伪造。
释放命令 result=3（不存在）按幂等成功处理。

## 2. 依赖与分层

- `internal/engine/lease`：共享 `Lease4` 模型。
  - 原因：`kea` 包已 import `dhcp`（配置生成），`dhcp` 不能再 import `kea`；用独立模型包打破循环。
- `internal/engine/kea/lease.go`：HTTP 客户端封装（复用 `CtrlAgent.Command`）。
- `internal/module/dhcp/lease_handler.go`：HTTP 校验/转换/错误映射；`LeaseAgent` 接口便于单测。
- main：`keaCmd` 非空时注入 lease agent；内存模式返回空列表。

## 3. 校验

- `validLifetime`：60–31536000 秒；
- `hwAddress`：`aa:bb:cc:dd:ee:ff`，统一小写；
- `hostname`：≤255；
- `leaseType`：仅 `IA_NA`/`IA_PD`；
- PATCH 至少提供一项，否则 400；地址不存在 404。

## 4. 前端

DHCP 服务 → 租约管理：

- v4/v6 分页签、KPI（v4 总数/冲突、v6 总数/PD）；
- 搜索 IP/MAC/主机名/DUID；
- v4 行操作：延期（秒）、改绑（MAC+主机名）、释放（二次确认）；
- v6 行操作：释放；
- 剩余时长按 `cltt + valid-lft - now` 计算；冲突状态 `state != 0` 标红。

## 5. 验证证据

- 单测：`go test ./internal/engine/kea ./internal/module/dhcp`；
- 端到端（真实 Kea）：
  - `lease4-add 10.61.40.251` → `GET /dhcp/leases4` 可见；
  - `PATCH validLifetime=1800` → 返回 1800；
  - `PATCH hwAddress=02:00:00:00:00:bb,hostname=lease-test` → 生效；
  - `DELETE` → 204，`lease4-get` result=3；
  - `DELETE /dhcp/leases6/...:fe?leaseType=IA_NA` → 204，`lease6-get` result=3。

## 6. 边界

- 租约操作直接作用于运行态；Kea 重启后以持久化 memfile 为准（操作已即时写入）。
- 改绑只改租约，不创建 host reservation；长期固定应使用「保留与绑定」。
- 未提供 v6 延期/改绑（Kea lease6-update 语义更复杂，列入 010B）。
