# M6-036 上游 IPv6 探活修复与健康语义校正：实现说明

## 1. 问题现象

上游管理页中所有 IPv6 条目显示「已摘除」，RTT `0 ms`、连续失败 `63473`，而 IPv4 条目均在线。用户据此怀疑 IPv6 地址被删除。

## 2. 排查结论

| 检查 | 结果 |
|---|---|
| 数据库 `upstream` 表 | `[2406:440:3c08:101:0:1:0:136]:53`、`[...:137]:53` 两条记录完好，`enabled=true` |
| `unbound-control list_forwards` | 没有这两条 IPv6 地址；unbound 实际使用 IPv4 上游（`crc.com.cn` 等转发规则指向 `10.61.0.x`） |
| control-plane 容器地址族 | `/proc/net/if_inet6` 仅有 `lo`；访问任何 IPv6 立即 `Network is unreachable` |
| 宿主 / unbound（hostNetwork）实测 | `2406:...:136`、`2406:...:137`、`2400:3200::1` 的 UDP/TCP 53 均返回 `NOERROR`，**三者实际健康** |
| 失败计数 | 15s 一次 × 约 11 天 = 63473，说明容器重建后一直在累计；计数无上限 |

**根因**：control-plane 在纯 IPv4 的默认桥接网络中，所有 IPv6 探活都会立即失败 → 3 次后标记 down；探活只探测 `Addrs[0]`、失败计数无上限、文案把「探活失败」写成「已摘除」，共同造成误解。

**关键澄清**：`SyncForward` / `SyncForwardRules` 只按 `enabled` 过滤，从不读取健康状态。因此「已摘除」从未真正删除地址或把地址移出转发，仅是健康标签；原提示「摘除中的上游不参与递归选路」与实现不符。

## 3. 修复内容

### 3.1 控制面 IPv6 出口

`deploy/compose/compose.yaml`：

- control-plane 额外接入 `probe-v6` 网络；
- 该网络 `enable_ipv6: true`，默认 ULA 子网 `fd00:1:2:3::/64`，可用 `IPAM_PROBE_V6_SUBNET` 覆盖；
- 数据面 unbound / kea 仍为 `network_mode: host`，不接入该网络，行为不变；
- 控制面仍保留默认网络，PG/CH/Kea 的服务名解析不受影响。

### 3.2 探活状态机

`internal/module/dns/upstream.go`：

| 改动 | 说明 |
|---|---|
| 探测全部地址 | 遍历 `u.Addrs`，任一地址 TCP:53 可达即在线；RTT 取成功地址最小值 |
| 失败计数封顶 | 新增 `maxConsecutiveFails = 999`，超过后保持 999 |
| 恢复语义 | 一次成功即恢复（原注释「2 连胜回切」与实现不符，已修正） |
| 锁粒度 | 先在锁外完成网络探测，再持锁更新状态；`Status` 不再被 2s 超时阻塞 |
| 语义说明 | 注释明确「探测结果仅用于展示，不参与转发选路」 |

### 3.3 契约与文案

- `api/openapi/paths/upstream.yaml`、`components/schemas/upstream.yaml`：描述改为「连续 3 次失败标记异常，一次成功恢复；仅用于展示，不改变转发选路」；执行 `gen-openapi.sh` 再生。
- 前端 zh/en 成对调整：
  - `upstream.health.down`、`upstream.summary.down`：「已摘除」→「探活失败」；
  - `upstream.stat.abnormalHint`、`forward.stat.linkedHint` 同步；
  - `upstream.toolbar.hint`：改为「健康状态仅供排障参考，转发按已启用上游下发」；
  - `forward.stat.linkedHintOff`：改为「按已启用上游下发」；
  - `common.removedSuffix`：「（探活失败）」。

## 6. 边界与后续

- 探活使用 TCP:53，少数只开 UDP 的 DNS 服务器仍可能显示失败；如遇此类环境，可后续改为发一次真实 DNS 查询（需新增解析器实现与超时控制）。
- 健康状态仍不参与转发选路；若未来要做「按健康摘除」，必须先改 `SyncForward`/`SyncForwardRules` 并在架构文档登记 ADR，避免与 unbound 自身的多上游重试冲突。
- 宿主完全禁用 IPv6 时，`probe-v6` 网络仍可创建但无全局出口，IPv6 上游会显示探活失败——这是符合实际的提示，不再误标「已摘除」。
