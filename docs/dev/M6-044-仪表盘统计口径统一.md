# M6-044 仪表盘统计口径统一实现说明

> 用户反馈：仪表盘「活跃终端」、地址池「已用」与 DHCP 子网页「在线租约」数字不一致，且不同时间刷新后对不上。本文记录根因、统一后的口径定义、代码路径与真实环境验证。

## 1. 问题与根因

| 页面/卡片 | 旧口径 | 结果 |
|---|---|---|
| 仪表盘「活跃终端」`onlineNow` | 今日 DHCP 日志 `distinct client_ip` | 只统计当天产生过 DHCP 事件的地址；零点/重启后骤降 |
| 仪表盘「地址池利用率」`poolUtilTop.used` | 今日日志 IP 落入池区间计数 | 同上，与租约无关 |
| 仪表盘「活跃终端趋势」 | 日志逐小时去重地址 | 与「当前在线」不是同一时点口径 |
| DHCP 子网页「在线租约」 | 地址台账 `coherence_binding` 有效租约 | 真实在线数 |

三处各用一套数据源，因此同一地址池出现 49 / 102 两个「已用」，仪表盘 KPI 也随时间窗口漂移。

## 2. 统一后的口径（架构 §13.4「在线 = 租约存在」）

| 指标 | 定义 | 数据源 |
|---|---|---|
| 在线租约 `onlineNow` | 当前 `active/grace` 绑定、落在已配置子网内、非静态/保留、非 `0.0.0.0`/`::` 的**地址数**（双栈按地址计） | 地址台账 `ipam.LedgerSource` |
| `onlineV4` / `onlineV6` | 上述集合按地址族拆分 | 同上（新增契约字段） |
| 地址池已用 `poolUtilTop.used` | 上述地址中落入该池闭区间的个数；PD 池不是地址池，跳过 | 同上 + 子网池定义 |
| 「DHCP 活跃地址趋势」 | 近 24h 日志逐小时去重客户端地址 | DHCP 日志（页面明确标注“日志口径”，不与在线租约相减） |
| 「今日新增 / 近 24h 离线」 | 日志 MAC 窗口推导 | 日志（标签加「（日志）」防止误读为租约口径） |
| 利用率分析页「已用」 | 每 5 分钟采样：池内**绑定 + 预留** | 采样表 `subnet_utilization`（含预留，故略高于在线租约，页面已说明） |

一致性约束：

- 同一快照时刻：`onlineNow == onlineV4 + onlineV6`；
- 覆盖全部有租约池时：`Σ poolUtilTop.used == onlineNow`；
- 单个池：仪表盘「已用」== DHCP 子网页该子网的在线租约数；
- 台账不可用（未注入 / DB 异常 / 空子网）→ 回退日志活跃 IP，页面不白屏。

## 3. 关键代码路径

- `internal/module/dashboard/service.go`
  - `LedgerSource` / `SetLedgerSource`：注入与 `ipam` 台账同源的数据（`cmd/control-plane/main.go` 复用 `ledgerSrc`）。
  - `onlineLeaseAddrs(src)`：遍历 `Bindings`，只取 `active/grace`，剔除未指定地址、预留地址与子网外地址，返回去重地址集合。
  - `Overview`：并发取数；台账可用时用 `onlineLeaseAddrs`，否则回退 `logs.DistinctClientIPs`；据地址族累加 `OnlineV4/OnlineV6`。
  - `poolTop`：在已排序地址集合上二分计数（`countAddrInRange`），跳过 `kind=pd`。
- `internal/module/dashboard/handler.go`：映射 `onlineV4/onlineV6`。
- `api/openapi/components/schemas/dashboard.yaml`：`onlineNow` 重新定义，新增 `onlineV4/onlineV6`（required），`make gen` 再生。
- `web/apps/web-ipam/src/views/dashboard/ipam/index.vue`：KPI 卡改为「在线租约」+ IPv4/IPv6 拆分提示；趋势卡改名并加口径说明；新增/离线标签标注日志口径。
- `web/apps/web-ipam/src/locales/langs/{zh-CN,en-US}/dashboard.json`、`dhcp.json`：成对文案；利用率页说明“含预留”。

## 4. 真实环境验证（2026-11-23 02:2x，`http://127.0.0.1:8443`）

```
GET /api/v1/dashboard?poolTopN=100
  onlineNow 278 = onlineV4 104 + onlineV6 174
  poolUtilTop.used 合计 278
  无线vlan66 10.61.66.0/23  used 103 / 497
  vlan66     ...:61:66:0/112 used  90 / 65535
  vlan50     ...:60:226:0/112 used 84 / 1262

GET /api/v1/ledger?family=4&state=online  total 104
GET /api/v1/ledger?family=6&state=online  total 174
GET /api/v1/ledger?subnetId=d697a9f9-…&state=online total 103
```

- 仪表盘在线租约 = 子网页 v4+v6 在线租约（104+174=278）；
- 仪表盘池已用合计 = 在线租约（278）；
- 无线 vlan66 v4：仪表盘 103 = 子网页 103（同一快照）。

> 说明：`coherence_binding` 以 MAC 为主键、一行同时带 v4/v6，因此双栈终端会贡献两个地址；卡片标题使用「在线租约 · 地址数」而非「终端」，避免把地址数当设备数。

## 5. 回归与门禁

- 单测：租约口径、family 拆分、保留剔除、子网外剔除、PD 池跳过、台账缺失回退。
- `go test ./...`、`golangci-lint`、`vue-tsc`、oxfmt/oxlint/stylelint、i18n 三门禁、E2E 全绿。
- 日志链路（M6-043）同批次验证：ClickHouse `ipam.logs` 持续写入，近 10 分钟 dns 45k+ / dhcp 186 条。

## 6. 遗留

- 「在线」仍为租约存在近似，非主动探测（P2 预留）。
- 利用率分析页含池内预留，与「在线租约」相差一个预留数；若后续要求完全一致，需要把「已用」拆成“在线/预留”两列并升版契约。
