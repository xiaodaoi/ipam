# M6-023 DNS 能力补齐（009B2）实现说明

> 对应任务卡：`docs/pm/board/review/M6-009-DNS 功能补齐.md`（009B2）
> 范围：泛域名、DoT、secondary/AXFR、拦截提示页、策略时段、内置分类库、CSV 导入导出与版本回滚。

## 1. 目标

把 DNS 侧「能配但不生效 / 只能单条维护」的能力补齐到可交付状态，并保证：

- 泛域名符合 RFC 1034（`*.example.com` 覆盖任意层级子域，不误伤区顶点）；
- DoT、secondary 渲染经 `unbound-checkconf` 校验后方可落盘；
- 封禁策略支持时段窗口，窗口外自动撤销运行时拦截；
- 名单支持批量导入/导出、版本快照与回滚、内置分类库一键安装。

## 2. 关键设计决策

### 2.1 泛域名：local-data 不展开，改走 auth-zone + zonefile

实测 unbound 1.26 的 `local-data: "*.wild.example.com ..."` **不会展开**：dig 子域返回 NXDOMAIN，
`unbound-checkconf` 却不会报错。因此：

- 含 `*` 记录的区域改渲染 `auth-zone { name; zonefile; for-downstream: yes }`；
- zonefile 由控制面生成到 `config/unbound/zones/<zone>.zone`（容器内 `/etc/unbound-rendered/zones/`），
  含最小 SOA/NS 自举记录；
- 其余区域仍用 `local-zone static + local-data`（行为不变）。

实测结果（`crphbz.com` 加 `*.wild A 10.99.9.9`、`* A 10.99.9.8`、显式 `www A 10.61.40.50`）：

| 查询 | 结果 |
|---|---|
| `a.wild.crphbz.com` | `10.99.9.9` |
| `b.c.wild.crphbz.com` | `10.99.9.9` |
| `wild.crphbz.com` | NODATA（未被通配误伤） |
| `www.crphbz.com` | `10.61.40.50`（显式记录优先） |
| `foo.bar.crphbz.com` | `10.99.9.8`（区顶点通配） |

记录名校验由 `ValidateRecordName` 收紧：只允许最左标签为 `*`，拒绝 `a.*.b`、`**`、`a..b`、`*.`。

### 2.2 通配 redirect：local-zone redirect + 区顶点 IP

封禁运行时同样受「local-data 不展开通配」影响。M6-023 修正为：

- `nxdomain/drop/tcp_only` → `local-zone static <base>`（子域 NXDOMAIN，语义略宽，已在卡片记录）；
- 通配 `redirect` → `local-zone redirect <base>` + `local-data "<base> A <提示页IP>"`，
  该区下所有名字（含多级子域）统一答提示页 IP；
- 精确 `redirect` → 仍为 `local-zone static <base>` + 顶点 A，避免把整域误导向提示页；
- 同一名字同时存在 redirect 与 NXDOMAIN 条目时 **redirect 优先**；
- 区类型变化时先 `local_zone_remove` 再按新类型添加（`ensureZone`）。

实测：`*.redir.m6test.example redirect` + `blockPageIP=10.61.40.9` 后，
`x.redir...`、`a.b.redir...`、`redir...` 均解析到 `10.61.40.9`。

### 2.3 DoT

- Upstream 契约新增 `tlsName`；`protocol=dot` 时渲染：

```yaml
forward-tls-upstream: yes
forward-addr: 1.1.1.1@853#cloudflare-dns.com
```

- 同一 forward-zone 内混用 dot/udp 时只取 dot 目标，避免明文回落；
- 端口缺省 853；`tlsName` 用于证书校验（SNI），留空表示直连。

### 2.4 Secondary / AXFR

- 区域新增 `kind=secondary` + `primary`（逗号分隔，支持 `ip[:port]`）；
- 渲染 `auth-zone` + `primary` + `fallback-enabled/for-downstream/for-upstream: yes`，
  不再生成 local-data；区域数据由主服务器同步；
- 端口统一转成 unbound 要求的 `ip@port` 语法。

### 2.5 提示页

- `DnsSettings` 新增 `blockPageIP/blockPageTitle/blockPageMessage`；
- 控制面提供免认证 `GET /blocked`（同源页面，CSP 允许内联样式），
  标题/正文可由设置覆盖，HTML 转义；
- `blockPageIP` 为空时 redirect 条目退化为 NXDOMAIN；
- 设置变更经 settings notify 触发 `ReplayAll`，使已下发条目指向新 IP。

### 2.6 策略时段

- `PolicyGroup.schedule = {days[], start, end}`：空=全天；`days` 空=每天；
  `start > end` 表示跨零点；非法时间按「不限」处理；
- `Schedule.Active(now)` 纯函数判定，单测覆盖跨零点/星期/非法值；
- `StartScheduleScheduler` 每分钟 `Reconcile`：窗口内下发、窗口外撤销；
- 服务自行记录已下发的 zone/data（`applied`），支持撤销与类型切换。

> 时区：按 control-plane 进程本地时区解释（容器默认 UTC）。若客户按本地时间配置，
> 需在 compose 中为 control-plane 设置 `TZ`（如 `Asia/Shanghai`）。

### 2.7 CSV / 版本 / 内置库

- `POST /dns/blocklists/{id}/entries/import`：CSV 文本（可选 BOM），
  列 `pattern[,action[,category]]`，支持 `#` 注释、表头、`replace` 清空后导入；
  非法域名/未知动作/重复计入 `skipped`（最多回传 20 条原因）；
- `GET .../entries/export`：UTF-8 BOM CSV（Excel 友好），按 pattern 排序；
- 订阅同步、CSV 导入前自动 `SnapshotVersion`；`GET .../versions` 列表，
  `POST .../versions/{v}/rollback` 以快照替换条目并把版本号 +1（历史不回退）；
- 内置分类库（ads/trackers/gambling/adult/social）随产品分发，一键安装为
  `kind=builtin` 名单；明示为「基线种子，非全量」，避免覆盖率承诺。

## 5. 已知边界与后续

1. **NOTIFY**：本期只做 secondary 拉取（AXFR），未实现主区变更 NOTIFY 主动推送；
   主从切换依赖 unbound 的 refresh 周期。
2. **精确条目语义略宽**：精确 `nxdomain` 仍以 `local-zone static` 实现，
   会同时拦截其子域；已在任务卡记录，后续如需严格单名可改用 RPZ 或逐名策略。
3. **RPZ zonefile 路径**：当前 `RPZ` 配置引用 `/var/lib/ipam/rpz`，该路径未与 unbound 容器共享，
   `conf_apply` 会跳过 RPZ 区；实际拦截依赖运行时 `local_zone/local_data`。后续统一共享卷后可启用 RPZ 原生路线。
4. **内置库覆盖有限**：定位为开箱基线，不承诺全量；客户可叠加订阅源或 CSV 导入。
5. **时区**：策略时段按进程时区解释，生产需显式设置 `TZ`。
