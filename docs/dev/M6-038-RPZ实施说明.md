# M6-038 RPZ 化封禁 + 白名单豁免 + 情报源骨架：实现说明

> 对应任务卡：`docs/pm/board/done/M6-038-RPZ开源情报自动阻断.md`；方案：`docs/dev/M6-038-RPZ开源情报自动阻断-方案v1.md`。

## 1. 为什么必须迁到 RPZ

旧实现用 `unbound-control local_zone <name> static` 逐条下发。实测结论：

| 结论 | 影响 |
|---|---|
| `local-zone` **优先于** RPZ 的 `rpz-passthru` | 两条路径并存时「白名单豁免」永远不生效，必须整体迁移 |
| `local_zone static` 会拦整棵子树 | 精确条目（例如只拦 `a.example`）会连 `b.a.example` 一起拦，语义比用户预期更宽 |
| 运行期态只记在控制面内存（`applied` map） | 删条目后重加、或 unbound 重启后会「以为已下发」而不再下发（历史缺陷） |
| 拦截无日志 | 仪表盘「今日拦截量」恒为 0，无法排障 |

## 2. 架构

### 2.1 4 个固定区（顺序即优先级）

```
wl.whitelist.rpz   (passthru，必须第一)
intel.hot.rpz      (P0 空；P1 高频情报)
intel.broad.rpz    (P0 空；P1 宽口径情报)
intel.custom.rpz   (现有封禁条目)
```

- `config/unbound/unbound.conf` 增加 `num-threads: 4`、`module-config: "python respip iterator"`；
- 4 个 `rpz:` 子句由控制面渲染（`internal/engine/unbound/config.go`），运行期**不增删**；
- 启停某个源 = 写空 zone + `auth_zone_reload`，不做整机 reload，避免缓存抖动。

### 2.2 zone 渲染（`internal/pkg/rpz`）

- 动作映射：`nxdomain → CNAME .`、`drop → CNAME rpz-drop.`、`tcp_only → CNAME rpz-tcp-only.`、`passthru → CNAME rpz-passthru.`、`redirect → A <提示页IP>`（Local Data）；
- 同名冲突按固定优先级收敛，输出按 owner 字典序排序 → 同样输入产生同样字节（sha256 判定「是否需要下发」）；
- `*.x` 同时输出 `x` 与 `*.x`；plain pattern 只拦该名（相对旧 `local_zone static` 是**收紧**，已记录为行为变更）。

**关键坑（本次实测踩到）**：RPZ 区的 owner 必须写成「相对区名」的形式（`www.crphb.com`，不带尾点，实际 owner 是 `www.crphb.com.<rpz-zone>.`），unbound 匹配时再削掉区名后缀。写成绝对名（`www.crphb.com.`）会被当作区外数据忽略，表现为「zone 已加载、serial 正确，但策略完全不生效」。已修复并有单测覆盖。

### 2.3 编译/下发（`internal/module/dns/intel.go`）

每次收敛（启动、条目变更、每分钟调度）执行：

1. 读白名单 + 所有生效策略组的条目 → 生成 4 个区的记录集；
2. 生成「内容指纹」= 用 `serial=0` 渲染的文本 sha256（**不含 serial**）；
3. 指纹未变 → 沿用上一版 serial，跳过写盘与热载（否则 `serial=now` 会让每分钟调度都整区重载）；
4. 指纹变化 → `serial = max(now, prev+1)`，写 `.tmp` → 原子 rename → `auth_zone_reload <zone>` → `list_auth_zones` 校验 serial；
5. 失败（热载报错或 serial 不符）→ 用上一版内容回滚并标记 `status=failed`，不影响其他区；
6. 内容切换成功后，对比新旧 owner 集合，**只** flush 新增/移除的名字（单区变更 >200 条时跳过，依赖 `cache-max-ttl: 300`），保证「封禁/解封立即生效」而不至于万级条目逐条 flush（实测 22ms/条）。

运行态来源为 `list_auth_zones`（`internal/engine/unbound/authzone.go`），不再信任内存记账：unbound 重启后若运行态缺失，下一轮会自动重下发。

### 2.4 配置校验（`internal/engine/unbound/forward.go`）

`unbound-checkconf` 校验候选块时会报 `RPZ requires the respip module`。处理方式：候选文本含 `rpz:` 时补一行 `module-config: "respip iterator"`。**不**复用主 conf 的 `python respip iterator`——控制面镜像不带 python 运行时，`unbound-checkconf` 会在 python 初始化阶段失败（实测 `Py_InitializeFromConfig: init_fs_encoding`）。

### 2.5 日志链路（`config/vector/vector.toml`）

`rpz:` 子句开启 `rpz-log: yes` 与 `rpz-log-name: <zone>`（不给名字时日志里没有区名，无法判断是哪一层的策略）。实际日志格式：

```
[1795066093] unbound[1:2] info: rpz: applied [intel.custom.rpz] www.crphb.com.cn. rpz-nxdomain 127.0.0.1@59547 www.crphb.com.cn. A IN
```

新增 `parse_rpz` transform 接入 `normalize`，落库 `action=blocked`；仪表盘 `dns.blockedToday` 与日志中心的 action 过滤据此可用。

> **修复（2026-11-20，M6-040）**：白名单命中同样会打印 `rpz: applied [wl.whitelist.rpz] ... rpz-passthru ...`，
> 表示**放行**而非拦截。早期 `parse_rpz` 只匹配 `rpz: applied` 就记 `action=blocked`，并把前面的通配规则名
> （如 `*.corp.example`）当作查询域名，造成「已加白仍显示拦截」的假报警。现在解析会跳过 `rpz-passthru`，
> 并取 `client@port` 之后的真实查询名。详见 `docs/dev/M6-040-报警中心实施说明.md` §9.8。

### 2.6 接口与前端

| 端点 | 说明 |
|---|---|
| `GET /dns/intel/whitelist` | 白名单列表 |
| `POST /dns/intel/whitelist` | 新增（`kind=qname|suffix`，原因必填），保存后立即重编译 + flush |
| `DELETE /dns/intel/whitelist/{id}` | 删除，立即恢复拦截 |
| `GET /dns/intel/zones` | 4 个区运行态（entries / serial / loadedSerial / status） |
| `POST /dns/intel/zones/reload` | 声明式重编译 + 热载，返回本次实际热载的区 |

权限复用 `dns:read|write`（`/api/v1/dns/*` 自动映射），未新增权限域。契约先改 `api/openapi/**` 再 `bash scripts/gen-openapi.sh` 再生。

前端「封禁管控」页新增两张卡：

- **RPZ 运行态**：4 行（顺序即优先级）、条目数、编译号/运行态编译号、状态标签（空区/已生效/待校正/下发失败）、「重新编译并热载」；
- **拦截白名单**：关键字过滤、新增（域名 + 范围 + 原因）、删除（Popconfirm 提示立即恢复拦截）。

zh/en 文案成对新增（`dns.blocklist.intel.*`），通过 `check-ui-i18n.py` / `check-ui-terms.py` / `check-i18n-keys.py` 三门禁。

## 5. 已知边界（P1/P2 → backlog）

- 情报源 CRUD / 预设模板 / 自动同步调度 / 质量闸门 / revision 回滚 / 离线导入未实现（`intel.hot`、`intel.broad` 恒为空区）；
- 外部源端到端验证受本机外网限制（abuse.ch 旧地址 410、GitHub raw 不可达），需客户环境或离线包验证；
- RPZ 只覆盖域名（QNAME）与应答 IP（Response-IP）；**路径级 URL 阻断不在 DNS 能力范围**；
- 单区变更超过 200 条时不逐条 flush，最长等待 `cache-max-ttl`（300s）；
- 语义收紧：plain pattern 不再拦整棵子树（旧 `local_zone static` 行为），如需拦子域请用 `*.domain`。
