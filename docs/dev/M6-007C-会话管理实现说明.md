# M6-007C 会话列表与单会话强制下线实现说明

## 1. 目标

补齐 M6-007 账号体系的会话控制能力：

- 用户可查看自己在各设备上的登录会话，并单独下线；
- 管理员可查看指定账号的活跃会话并强制下线；
- 单会话下线后，该会话的访问令牌与刷新令牌立即失效；
- 账号安全属性变更（口令/角色/停用/重置 2FA）自动下线全部会话。

## 2. 数据模型

迁移 `0037_user_sessions.sql`：

| 字段 | 说明 |
|---|---|
| `id` | 会话 ID（16 字节随机 hex），写入 JWT `sid` claim |
| `user_id` / `username` | 归属账号 |
| `ip` / `user_agent` | 登录来源，用于识别设备 |
| `created_at` | 登录时间 |
| `last_seen_at` | 最近活动，RBAC 每分钟节流更新 |
| `expires_at` | 会话过期，随刷新令牌轮换推进 |
| `revoked_at` | 非空=已下线/登出 |

不保存令牌原文、口令或任何可重放凭据。

## 3. 令牌与吊销

- 登录成功后创建会话，访问/刷新令牌写入同一 `sid`；
- 刷新轮换沿用 `sid`，并延长 `expires_at`；
- 下线会话：`revoked_at=now()` + 向 `auth_token_blacklist` 写入 `sess:<id>`，有效期至少覆盖一个刷新令牌周期；
- RBAC 使用新增的 `TokenBlacklist.RevokedAny` 一次 PG 查询同时判断令牌 jti 与会话键，避免每请求增加一次往返；
- 升级前无 `sid` 的令牌继续按原 jti 语义工作，刷新时补建会话。

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/auth/sessions` | 已登录 | 当前账号活跃会话，`current` 标记当前会话 |
| DELETE | `/auth/sessions/{sessionId}` | 已登录 | 仅可下线自己的会话 |
| GET | `/system/sessions?userId=` | `system:read` | 管理端列表，可按用户筛选 |
| DELETE | `/system/sessions/{sessionId}` | `system:write` | 管理端强制下线 |

契约事实源：`api/openapi/paths/auth.yaml`、`api/openapi/paths/session.yaml`、
`api/openapi/components/schemas/auth.yaml#/Session`。

## 5. 前端

- 个人中心 → 安全设置 → 「登录会话」卡片：设备（UA 解析）、IP、登录时间、最近活动、当前标记、单个下线；
- 系统管理 → 账号管理 → 「会话」按钮：弹窗列出该账号会话并强制下线；
- 下线当前会话时自动退出到登录页。

## 6. 账号变更联动

`PATCH /users/{id}` 中以下操作会提升 `token_version` 并下线该账号全部会话：

- 重置口令；
- 变更角色；
- 停用账号；
- 重置 2FA。

修复了此前“角色变更后旧令牌仍保留旧角色权限”的问题。

## 7. 清理与容量

- 后台每小时删除 `expires_at < now() - 7 天` 的会话；
- 会话表只保留元数据，单会话约数百字节，容量可忽略；
- `last_seen_at` 节流写入，正常使用下每会话每分钟最多一次 UPDATE。

## 8. 验证

- 单测：登录登记、列表 current 标记、单会话下线后访问/刷新 401、他人会话 404、
  刷新沿用 sid、登出只影响当前会话、管理端列表/下线、角色变更吊销全部会话、过期会话不展示；
- 真实环境：curl 验证登录 → 列表 → 刷新 sid 不变 → 管理端下线 → 访问/刷新均 401；
