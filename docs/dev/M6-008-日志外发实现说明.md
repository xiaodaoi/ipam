# M6-008 日志外发与采样实现说明

## 1. 配置

表 `log_export_settings`（单行）：Syslog/Kafka/Webhook 开关与地址、sampling_mode、sample_rate。

接口：`GET/PUT /system/log-export-settings`（system:read/write）。

## 2. Vector 渲染

基础模板：`config/vector/vector.toml`（只读挂载到 `/etc/vector-template`）。
控制面 `logexport.Render`：

1. 把 ClickHouse sink 的 `inputs = ["normalize"]` 改为 `["log_out"]`；
2. 追加 `[transforms.log_out]`：
   - all：`type=sample rate=1`；
   - sample：`type=sample rate=N`；
   - errors：`type=filter condition='.severity != "INFO"'`；
3. 按开关追加：
   - `[sinks.siem_syslog]` socket + `encoding.codec="syslog"` + RFC5424；
   - `[sinks.siem_kafka]` kafka + JSON；
   - `[sinks.siem_webhook]` http + JSON + newline framing；
4. 原子写入 `/etc/vector-config/vector.toml`。

Vector 启动参数 `--watch-config`，文件变化自动重载。Compose 用 `vector-config` 卷共享，volume-init 将卷 owner 设为 10001。

## 3. 页面

日志中心 → 外发与采样：4 KPI、通道开关/地址、采样模式/比例、根分区水位提示；保存后提示 Vector 重载。

## 4. 验证

- `vector validate /etc/vector/vector.toml` 通过（Component configuration）；
- 真实渲染包含 `[transforms.log_out]`、clickhouse inputs=log_out、Syslog/Webhook sink；
- 单测覆盖渲染/errors 模式/参数校验。

## 5. 磁盘水位自动降级（M6-008 补充）

- `logexport.Watermark` 每 1 分钟读取根分区使用率：
  - 连续 3 次 ≥ 90%：自动把渲染采样覆盖为 `errors`（仅非 INFO），立即降低 ClickHouse 入库与外发量；
  - 连续 3 次 ≤ 85%：解除覆盖，恢复用户配置；
  - 85%–90% 回差区间保持现状，避免阈值抖动。
- 覆盖只作用于渲染层，不修改 `log_export_settings` 中用户保存的策略；页面显示 `effectiveSamplingMode`、`degraded`、`diskUsedPercent`、`degradedAt`。
- 阈值可用 `IPAM_LOG_DEGRADE_HIGH` / `IPAM_LOG_DEGRADE_LOW` 调整（默认 90/85）。
- `/metrics` 新增 `ipam_log_export_degraded`，并新增告警 `IpamLogExportDegraded`。

## 6. 验证补充

- 单测：自动覆盖/恢复渲染、降级期间保存策略不丢、回差防抖、连续次数门限、env 解析回退；
- `ipam_log_export_degraded` 指标、`vector validate`、页面降级提示。

## 7. 边界

- 自动降级当前固定为 `errors`（后续可做成可配置动作/分级）；
- 外发失败重试由 Vector 内部处理，积压指标未接入 /metrics；
- TLS/SASL/鉴权头未实现；
- 采样同时影响 ClickHouse 与审计合规留存，生产切换需评估；审计数据存于 PG，不受日志采样影响。
