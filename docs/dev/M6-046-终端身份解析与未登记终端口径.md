# M6-046 终端身份解析与未登记终端口径修复

> 起因：终端管理页「未登记终端」只显示 108 条，而在线终端实际 278 台 —— 170 台 IPv6-only 终端（DUID）被身份归一化丢弃，且这类终端根本无法登记。

## 1. 问题证据（修复前，真实环境）

```
coherence_binding 总数             278   （state 全为 active）
├─ mac 形如 68:8f:c9:5b:39:cf     108   → 出现在「未登记终端」
└─ mac 形如 000100012f51e6c5…     170   → ipv4=0.0.0.0，完全不可见（DUID）
asset 表行数                        0
GET /api/v1/assets/discovered     108
```

根因链：

1. `coherence_binding` 以 `mac text PRIMARY KEY` 建模，IPv6-only 终端的行把 DUID 写进 `mac` 列、`ipv4` 写 `0.0.0.0`；
2. `AssetService.Discover` 用 `coherence.NormalizeMAC` 归一化，该函数只接受 **12 位十六进制**，DUID（28/20 位）返回空串；
3. `Discover` 对空 MAC 直接 `continue` → 整类终端被丢弃；
4. `asset` 表 `mac text PRIMARY KEY`，`AssetService.Upsert` 同样只收 MAC → 即使可见也登记不了。

## 2. 身份解析（`internal/module/ipam/asset.go`）

```text
binding.mac ─┬─ 12 位 hex                → MAC 身份
             ├─ DUID → dualstack_identity 映射 → MAC 身份（保留 DUID 供双栈关联）
             ├─ DUID-LLT / DUID-LL → 链路层地址推导 → MAC 身份
             └─ 其他 DUID（如 DUID-UUID） → DUID 身份（仍可登记）
```

- `NormalizeDUID`：小写、去 `: - . 空格`，只接受 4..128 位偶数长度十六进制；与 MAC 归一化分开，避免"长度必须 12"的假设；
- `macFromDUID`：按 RFC 8415 §11 解析
  `DUID-LLT = 0001|0001|time(4B)|MAC(6B)`（28 hex）、`DUID-LL = 0003|0001|MAC(6B)`（20 hex）；
- 映射来源：`dualstack_identity`（`ipam.LoadDUIDToMAC`，main.go 注入），映射优先于启发式；
- 同一身份的多条绑定（v4 行 + v6 行）合并为一条：地址/主机名/子网取并集，状态取最严重（conflict > grace > active），`lastSeen` 取最近租约；
- 只认 `active/grace` 且 `cltt + valid_lft` 未过期（与 M6-045 在线租约口径一致），过期绑定不再伪装成"未登记"。

## 3. 资产身份键改造

**迁移 `db/postgresql/migrations/0051_asset_identity.sql`**

```sql
ALTER TABLE asset ADD COLUMN duid text;
ALTER TABLE asset ADD COLUMN identity text;         -- 主键：MAC 优先 / DUID 回退
UPDATE asset SET identity = lower(mac) ...;          -- 存量行迁移
ALTER TABLE asset DROP CONSTRAINT asset_pkey;
ALTER TABLE asset ADD CONSTRAINT asset_pkey PRIMARY KEY (identity);
ALTER TABLE asset ALTER COLUMN mac DROP NOT NULL;
CREATE UNIQUE INDEX uniq_asset_mac ON asset (lower(mac)) WHERE mac IS NOT NULL;
CREATE UNIQUE INDEX uniq_asset_duid ON asset (duid) WHERE duid IS NOT NULL;
CREATE INDEX idx_asset_org ON asset (org_id);
```

**身份键漂移合并**（`PgAssetRepo.Upsert`）：先按 DUID-only 登记、之后 DUID 被解析出 MAC 时，事务内把旧行 `identity` 迁移到 MAC（若 MAC 行已存在则删除旧行），避免同一设备两条记录。

**其他 P0 修复**

| 问题 | 修复 |
|---|---|
| MAC 搜索不带冒号查不到 | 查询前压缩十六进制（`replace(lower(mac),':','') LIKE ...`），内存实现同语义 |
| `DELETE /assets/{mac}` 永远 204 | PG 检查 `RowsAffected`，0 行返回 `ErrAssetNotFound` → 404 |
| 资产删除/修改审计无 before 快照 | `auditRec.RegisterBefore("/assets/:mac")` 注入 `assetSvc.Get` |
| 未登记列表无子网/组织上下文 | `LoadLedgerBindings` LEFT JOIN LATERAL 取最长前缀子网；登记弹窗默认带入子网所属组织 |
| 未登记列表状态判断写错（`inactive` 不存在于 CHECK 约束） | 白名单 `active/grace` + 租期校验 |

## 4. 契约（API 先行）

- `Asset`：`required: [identity, owner]`，新增 `identity` / `duid`，`mac` 变为可选；
- `AssetUpsert`：`mac` / `duid` 至少一个，`owner` 加 `minLength: 1`；
- `DiscoveredTerminal`：新增 `identity`（必填）、`duid`、`subnetId`、`subnetCidr`、`orgId`；
- `DELETE /assets/{mac}`：明确路径参数为身份键，404 语义写入描述；
- `GET /assets?q=`：说明支持省略分隔符的 MAC 与 DUID。

## 5. 前端

- **未登记终端**：终端列区分 MAC / 「DUID 终端」标签，DUID 全文以 mono 小字展示；新增「子网」「所属组织」列（组织显示完整路径）；搜索支持省略分隔符；登记弹窗显示身份键并默认带入子网组织；
- **资产登记**：终端列显示 MAC 或 DUID 标签；表单新增 DUID 字段（编辑时身份键只读）；校验顺序为「MAC 格式 → DUID 格式 → 至少一个 → 使用人」；CSV 导出新增 DUID 列；
- zh/en 文案成对补齐（`dhcpLedger.assets.*`、`dhcpLedger.discovered.*`）。

## 7. 遗留（下一批）

- 批量登记 + 忽略名单（打印机/AP 等不需要登记的 MAC 可抑制），避免列表只增不减；
- 资产页 join 当前 IP / 在线状态，形成真正的「终端」视图（目前仍是通讯录式）；
- 组织筛选按子树展开（`asset.org_id = $1` 仍是精确匹配，与日志中心的子树口径不一致）；
- `/assets` 分页与服务端统计 + `pg_trgm` 索引（当前全表返回、前端过滤）；
- CSV 导入、标签字典、按使用人聚合的「一人多终端」视图；
- `lastSeen` 目前取 kea `cltt`（租约开始/续约），若需"链路层活跃时间"应改取日志 `max(ts)`。
