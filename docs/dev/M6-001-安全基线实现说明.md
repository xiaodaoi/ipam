# M6-001 安全基线实现说明

> 版本：2026-10-29　状态：已实现并通过验证　关联任务：`docs/pm/board/review/M6-001-安全基线.md`

## 1. 目标与边界

本任务关闭商业交付的五个安全阻断项中的三个：传输安全、密钥/初始口令、账号口令与会话。备份/HA/License 不在本卡范围。

> 2026-10-29 调整：按用户反馈，**首次登录强制改密默认关闭**（避免调试被弹窗阻塞），改为「系统设置 → 账号安全」中的可开关策略；开启后对新账号/重置口令生效。

设计原则：

1. **安全默认**：生产默认 HTTPS、随机初始口令；强制改密默认关闭、可一键开启，开发态允许 HTTP 但显式告警；
2. **单一校验**：创建账号、管理员重置、本人改密共用 `ValidatePassword`，避免策略漂移；
3. **最小改动**：复用既有 JWT/黑名单/用户表，不引入新组件；数据库只加一列；
4. **可回滚**：迁移 `0027` 仅新增列并标记 admin，回滚只需删除列（不破坏既有数据）；
5. **可运维**：初始口令只写本地 0600 文件与启动日志，不入库、不写回 API。

## 2. 接口契约（OpenAPI 先行）

- `POST /api/v1/auth/password`（`changeAuthPassword`，Bearer）：
  - 入参 `{oldPassword,newPassword}`；
  - 旧口令错误 → 401 `BAD_CREDENTIALS`；策略不符 → 400 `WEAK_PASSWORD`；新旧相同 → 400 `SAME_PASSWORD`；
  - 成功 → 200 `{accessToken, refreshToken, mustChangePassword:false}`，旧令牌因 `token_version+1` 立即失效。
- `AuthLoginResult` 新增 `mustChangePassword`（boolean，必填）；
- `UserInfo` 新增 `mustChangePassword`；
- `User` 新增 `mustChangePassword`（系统策略开启时新建/重置为 true，本人改密后 false；默认策略关闭）；
- 口令 schema 最小长度从 8 调整为 10。

`api/gen/**` 与 `web/.../api/schema.d.ts` 均由 `make gen` 生成，无手改。

### 3.1 改密时序

1. 解析 Bearer → 加载用户（存在/启用）；
2. 校验旧口令（bcrypt 常量时间）；
3. 校验新旧不同 + `ValidatePassword`；
4. `UPDATE password_hash, must_change_password=false`；
5. `token_version+1`（其他设备/旧 access/refresh 立即失效）；
6. 重新读取用户，按新版本签发 access/refresh；
7. 审计 `password_change`（成功/旧口令错误）。

### 3.2 初始口令

- 未设置 `IPAM_POC_PASSWORD`：`Ipam-<随机>!9`（24 位），日志与文件各显示一次；
- 设置 `IPAM_POC_PASSWORD`：沿用（自动化/兼容）；
- 用户表 `must_change_password` 仅表示“建议状态”，登录时还要与 `security_settings.force_password_change` 取与：
  `mustChange = user.must_change_password && setting.force_password_change`；
- 默认策略关闭，因此调试时登录不会弹窗；在系统设置开启后才生效；
- 文件路径可用 `IPAM_RUN_DIR` 覆盖（默认 `/run/ipam`）。

## 5. 部署与配置

- `install.sh`：
  - 自动生成 `POSTGRES_PASSWORD`（占位时）、`IPAM_JWT_SECRET`（64 位 hex）；
  - 生成自签证书 `certs/server.crt|key`（CN=主机名，SAN=localhost/127.0.0.1/可选 IP）；
  - 写入 `IPAM_TLS_CERT/KEY`、`IPAM_CERTS_DIR`，`docker compose up -d --wait`，HTTPS `/healthz` 冒烟；
  - 打印初始管理员口令文件。
- `compose.yaml`：
  - `IPAM_JWT_SECRET` 必填（`:?`）；TLS 路径可空（开发态 HTTP）；`IPAM_RATE_LIMIT` 默认 600；
  - control-plane 挂载 `./certs`，healthcheck 走 `/healthz`（无需令牌）；
  - control-plane/coherence/vector：`no-new-privileges` + `cap_drop ALL`；PG/CH 因初始化需要保留 caps；
  - 未新增特权容器；证书目录已加入 `.gitignore`。
- `deploy/README.md`：补充 HTTPS/密钥/初始口令/限流/安全头说明。

## 7. 运维说明

- **首次部署**：`bash deploy/compose/install.sh`，从输出或 `/run/ipam/initial-admin-password` 取初始口令；默认可直接登录（不强制改密），需要时在系统设置开启。
- **正式证书**：替换 `certs/server.crt|key` 为 CA 签发证书；私钥建议 640 且仅容器用户可读（当前自签为 644 便于容器读取）。
- **密钥轮换**：修改 `.env` 的 `IPAM_JWT_SECRET` 并重启 control-plane，会令所有会话失效；应在维护窗口执行。
- **限流**：`IPAM_RATE_LIMIT=0` 关闭通用限流（登录 5 次/分钟仍生效）。
- **回滚**：回退代码后保留 `must_change_password` 列不影响旧版本（旧版本不读取该列）；如需彻底回滚执行 `ALTER TABLE users DROP COLUMN must_change_password`（会丢失强制改密状态）。
