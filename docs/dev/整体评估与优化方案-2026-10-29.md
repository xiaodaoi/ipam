# IPAM 整体评估与优化方案（2026-10-29）

> 评估对象：当前 `main`（`fe7fae7`）全部代码、部署物、文档与任务看板。
> 评估基准：`docs/架构设计文档-V1.md`（单一事实源）、`IPAM需求调研报告.md`（FR/NFR 基线）、`docs/pm/roadmap.md`。
> 方法：逐项对照 P0/P1 需求与 ADR 决策，核对代码、OpenAPI、compose、CI、任务卡与目录实际内容；结论均可在文末证据索引中复核。

## 1. 结论摘要

**一句话判断：核心 DDI 功能已经跑通，是一个完成度较高的「可试用版 / PoC+」；但距离可对外销售的商业 DDI 产品仍有明显差距，当前不建议按 GA 交付。**

已经做好的部分（真实可用的主链路）：

- IPAM：组织树 → 子网/地址池 → 地址六态台账 → 保留/静态绑定 → 资产登记；
- DHCPv4/v6：子网/池、PD 委派、选项与类匹配、保留、租约查询与 Kea 下发；
- DNS：上游、条件转发、本地正/反区域、缓存、RRL、DNSSEC 开关、RPZ 封禁、订阅源同步、策略分组、解析测试台；
- 双栈联动：模板/匹配方案/人工映射/冲突清单，含 C++ hook 与 coherence-daemon；
- 日志：Vector → ClickHouse、检索/TopN/QPS、实时流、操作审计、保留策略与按月 Parquet 归档；
- 平台：JWT + 刷新令牌、RBAC（6 域 × 读写）、组织主数据、品牌定制、47 个页面、104 个 API operation、CI 六道闸。

**五个商业交付阻断项（必须优先解决）：**

| # | 阻断项 | 现状证据 |
|---|---|---|
| 1 | 安全基线不达标 | 控制面仅 HTTP（`install.sh` 明示“TLS 于 M5 接入”）；JWT 密钥未在 compose 下发，重启即全员掉线；初始 admin 口令默认 `admin123`；修改密码页面是空壳（只弹成功提示，不调用 API） |
| 2 | 无高可用 / 灾难恢复 | `deploy/images/keepalived/` 为空，compose 无 keepalived；Kea 配置无 HA hook；无备份/恢复/升级回滚；PG、ClickHouse 均单实例 |
| 3 | 无 License 与商业分级 | 全仓库无 License 代码、端点、页面；需求 F-04（P0）未实现 |
| 4 | 运维与可观测缺失 | 无 `/metrics`、无 Prometheus/Grafana 资产（`observability/` 为空）、无告警通道、无 NTP 配置、无健康/就绪端点、无结构化日志与请求追踪 |
| 5 | 合规与审计不完整 | 审计仅覆盖 POST/PATCH/DELETE，登录只是匿名 create 记录、无结果语义；无变更前后值、PG 内可改可删、无留存/归档；等保要求的“只追加、可取证”未达成 |

**成熟度粗评（主观，仅用于排优先级）：**

| 维度 | 判断 | 说明 |
|---|---|---|
| 核心 DDI 功能 | B | 主链路完整，DNS 记录类型、DHCP RA/option82、冲突探测等仍有缺口 |
| 企业级能力 | D | License、HA、备份升级、LDAP/2FA、告警、报表基本缺失 |
| 安全与合规 | D | 无 TLS、默认口令、审计不可取证，暂不满足政企准入 |
| 可靠性与运维 | D | 单点、无备份、无监控，故障即停服 |
| 产品体验 | C+ | 页面观感已接近商业软件，但 i18n、首次向导、批量操作缺失 |
| 工程质量 | C | 后端单测较好，前端零单测、无自动化 E2E/压测/安全扫描，发布流程缺失 |
| 文档与交付 | C- | 架构/需求文档强，但无根 README、无用户/运维手册、无 API 文档站，路线图状态失真 |

## 3. 关键缺口分析

### 3.1 安全与合规（最高优先级）

1. **传输安全**：控制面 `ListenAndServe` 为明文 HTTP；`install.sh` 自述“当前 HTTP，TLS 于 M5 接入”。管理口令、JWT、配置在管理网明文传输。
2. **密钥与口令**：
   - compose 未传 `IPAM_JWT_SECRET`，启动时随机生成 → **每次重启所有会话失效**；
   - 首次启动播种 `admin / admin123`（或环境变量），没有强制修改；
   - “修改密码”页面不调用任何 API，是占位实现；
   - 无口令复杂度、历史、过期、失败锁定策略。
3. **身份体系**：无 LDAP/AD、无 TOTP 2FA；自定义角色（operator/auditor/自定义）无法在账号界面或契约中赋值，RBAC 实际退化为 admin/user 两级。
4. **审计可信度**：只记录 POST/PATCH/DELETE；登录/登出虽被记为匿名 create，但没有独立的登录成功/失败语义；无变更前后值；`operation_audit` 可被 DBA 修改/删除；无留存/归档/独立导出策略。
5. **运行时加固**：compose 无 `read_only`、`cap_drop`、`security_opt`、资源限制、`/run/secrets`；PG/CH/Kea API 为明文；镜像无签名/SBOM/漏洞扫描。
6. **接口防护**：仅登录接口限流；写接口无限流、无幂等（文档承诺的 Idempotency-Key 未实现）、无请求体大小/超时统一策略。

### 3.2 高可用与数据可靠性

- keepalived 仅存在于设计与空目录；compose 无 VIP 漂移；
- Kea 无 hot-standby/lease 同步，主备双分配风险未解；
- 无 `config-replicate`，主备配置漂移无对账；
- PG、ClickHouse 单实例，无副本、无 PITR、无备份；
- 无升级/回滚工具，迁移无 down/校验；
- 控制面单副本且重启掉会话，无法滚动升级；
- ClickHouse 日志无副本，节点故障即丢失在线检索数据。

### 3.3 可运维性

- 无 `/metrics`、无 Prometheus/Grafana/告警规则（`observability/README.md` 只有说明）；
- 无 `/healthz`、`/readyz`；只有 `/system/info` 的 PG 探针；
- 日志为非结构化 `log.Printf`，无 request-id、无 trace、无访问日志规范；
- 无告警通道（邮件/webhook/钉钉/企微）、无 NTP 校时管理、无容量水位策略；
- 无诊断包（仅前端“复制诊断信息”文本）、无运行手册/应急预案。

### 3.4 功能深度

- **DNS**：记录类型、hosts 导入、DoT、重绑定防护、拦截提示页、时段策略、内置分类库、AXFR/Secondary/NOTIFY、DNS 客户端 MAC 关联；
- **DHCP**：RA 联动、option82、Ping 冲突、租约手工操作、DHCP 故障切换、无状态模式引导；
- **IPAM**：VLAN/站点/用途/负责人、逐 IP 备注标签、利用率历史与阈值、发现纳管、ARP/ping 冲突、CSV 导入导出；
- **日志**：外发、采样/水位、异常报表、取证打包、只追加存储；
- **平台**：License、备份升级、HA、告警、NTP、LDAP/2FA、API Token/MCP、迁移工具、报表。

### 3.5 前端与体验

- **i18n 基本失效**：47 个页面中 41 个含硬编码中文，只有 4 个使用 `$t`；语言切换只影响框架壳；
- 无首次部署向导（F-01 的 5 步）；
- 无统一批量操作（仅台账少量）、无列配置/导出模板、无全局命令面板；
- “修改密码”是空壳；无会话管理/登录设备列表；
- 无前端单元测试与可访问性检查；
- 动态菜单未启用：`accessMode` 仍是 `frontend`，与 §13.2“后端动态菜单、权限码同源”不符；
- 未使用 OpenAPI 生成的 TS 客户端，`api/ipam.ts` 为手写封装（与 §13.2 约定不符，易与契约漂移）。

### 3.6 工程质量与交付

- 前端零单测；`tests/e2e|load|fuzz` 为空；浏览器验证是 `/tmp` 下临时脚本，未入库、不进 CI；
- 无压测、无故障演练、无安全扫描（gosec/trivy/npm audit）、无依赖自动升级；

## 4. 优化方案

> 原则：先解决“能安全交付、能恢复、能升级”，再补功能深度；每一阶段都以可验收的证据收口，而不是以“代码写完”收口。

### Phase 0（1–2 周）· 交付兜底（Quick Wins）

目标：把“明显会出事”的点先补上，形成可对内演示、可小范围试用的基线。

| 项 | 动作 | 验收 |
|---|---|---|
| 传输安全 | 控制面内置 TLS 或前置 Nginx/Caddy；HTTP 自动跳转；证书挂载/自动生成 | 全站 HTTPS，HSTS，HTTP 301 |
| 密钥治理 | compose 注入 `IPAM_JWT_SECRET`（secrets/文件），文档给出生成方式；禁止随机密钥用于生产 | 重启后会话不失效（除主动轮换） |
| 初始口令 | 首次启动生成随机 admin 口令写入一次性文件/日志；标记 must-change | 首登强制改密；无 `admin123` 默认值 |
| 改密闭环 | 实现 `POST /auth/password`（校验旧口令、强度、吊销其他会话）；前端真实调用 | 改密后旧 token 失效，可重新登录 |
| 口令策略 | 长度/复杂度/历史/失败锁定；登录失败审计 | 策略可配置，失败事件可查 |
| 基础备份 | `scripts/backup.sh`：PG dump + CH 备份 + 配置/密钥打包，保留 N 份；`restore.sh` | 演练：空环境恢复后登录/租户数据完整 |
| 可观测最小集 | `/healthz`、`/readyz`、`/metrics`（进程/HTTP/PG/CH/Kea/Unbound）；Prometheus + Grafana 最小面板 | 指标可抓取，服务异常有面板 |
| 文档纠偏 | 修正 roadmap/§7/§9 状态；根 README；删除死代码/产物 | 文档与代码一致，仓库无临时原型 |
| 交付加固 | compose 加 `cap_drop`/`read_only`/资源限制/secrets；install.sh 预检 NTP/端口/内核 | 通过 CIS 基础检查清单 |

**产出**：可安全试用的单机版；一份“已知限制与不适用场景”说明。

### Phase 1（3–6 周）· 商业 GA 最小闭环

目标：满足“能卖、能维护、能理赔”的最低商业条件。

1. **License 与版本分级（F-04）**
   - 离线激活文件（签名校验）+ 在线激活；终端计数（租约 distinct MAC/DUID）；试用 30 天/100 终端；超限软降级（仅告警，不中断现网）；
   - Standard/Enterprise 能力开关与 UI 页；License 页展示授权/到期/用量。
2. **备份/恢复/升级（F-06/F-07）**
   - 定时全量 + 关键表增量；升级前自动快照；一键恢复与回滚；迁移版本表 + 失败自动回退；发布包校验和/签名。
3. **高可用（F-05/D8）**
   - keepalived 镜像 + compose/Helm 双节点 profile；Kea hot-standby；PG/CH 各自本地实例；`config-replicate` 幂等推送与周期对账；脑裂保护；
   - 演练：kill -9 主节点，VIP 漂移 ≤30s、续租不中断、无重复租约。
4. **审计与合规（A-06/E-09）**
   - 登录成功/失败/登出改为独立审计事件（含来源 IP、失败原因）；变更前后值；只追加（触发器/权限/哈希链）；审计留存与归档；审计导出（CSV/JSON）；等保条款映射表。
5. **账号体系（F-02）**
   - LDAP/AD 对接（可配置、可测试连接、按组映射角色）；TOTP 2FA；自定义角色赋值（契约与 UI）；会话列表与强制下线。
6. **可观测与告警（F-08）**
   - Prometheus 抓取 + Grafana 预置面板；告警规则（服务掉线、证书到期、磁盘 80/90%、CH 写入失败、DHCP 池耗尽、DNS 上游全挂）；邮件/Webhook/钉钉/企微；NTP 状态页。
7. **日志外发与容量治理（E-05/E-06）**
   - Vector 增加 Syslog RFC5424/Kafka/Webhook sink（UI 可配、可测）；日志分级采样；磁盘水位自动降级与告警；外发失败重试与积压指标。
8. **前端体验（F-01）**
   - 首次部署 5 步向导；i18n 全覆盖（至少中/英 100% 文案）；真实改密；统一空状态/错误提示；关键页面批量操作。
9. **工程与发布**
   - E2E（Playwright）入 CI：登录、子网→下发、保留、DNS 记录、封禁、日志检索、账号/角色、License、备份恢复；
   - 压测（DNS QPS、DHCP lease/s、日志查询、联动风暴）；安全扫描（gosec/trivy/npm audit）；发布流水线（多架构镜像、SBOM、签名、Release Notes）。

**GA 出口（全部满足才可对外）：**
- 安全：HTTPS only、无默认口令、无高危漏洞、密钥不入库、审计可取证；
- 可靠：HA 演练与恢复演练通过（RTO≤30s、RPO≈0）；
- 运维：指标/告警/备份/升级四件套可用，有运行手册；
- 合规：6 个月日志留存 + 审计留存 + 等保映射；
- 文档：安装/升级/运维/用户/API 五类文档齐全；
- 许可：License 可用，版本边界清晰。

### Phase 2（6–10 周）· 功能补齐与差异化

优先级建议（按销售阻力排序）：

1. **DNS 记录能力**：TXT/SRV/MX、泛域名、hosts 导入、dnsmasq/ISC/Windows 配置迁移；
2. **DNS 安全/架构**：DoT 真正生效（或从 schema 移除）、重绑定防护、AXFR/Secondary/NOTIFY（政企多 DNS 场景）；
3. **封禁产品化**：拦截提示页定制、时段计划、内置分类库与版本回滚、CSV 导入导出、拦截分类报表；
4. **DHCP 深度**：RA 联动（M/O/PIO）、option82 展示与选池、Ping 冲突、租约删除/延期、DHCP 故障切换演练；
5. **IPAM 深化**：VLAN/站点/用途/负责人、逐 IP 备注标签、利用率历史与阈值告警、发现纳管/影子资产、ARP/ping 冲突、CSV 导入导出；
6. **报表与集成**：定时报表（PDF/CSV）、Webhook 事件、API Token（bot）、Idempotency-Key、MCP 网关、Terraform/Ansible Provider；
7. **交付形态**：Helm Chart、离线镜像包/配置包、多架构镜像、国产化 OS/CPU 适配评估。

### Phase 3（长期）· 企业级差异化

- 多站点/多租户管理面、分级授权；
- SNMP/NetConf 拓扑联动、交换机端口定位；
- 云 DNS/DHCP 纳管（Azure/AWS/VMware）；
- 自助 IP 申请/审批工作流；
- OEM 贴牌、DoH/DoT 对外服务、IPv6-only 模式；
- SIEM/态势感知深度对接与合规模板。

> 明确不建议在 GA 前投入：多租户、SNMP 拓扑、云纳管、OEM、DoH 服务端、自助门户。它们会显著拉长交付周期，但不解决当前“不能安全卖”的问题。
