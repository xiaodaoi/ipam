## 背景

M6-038 已把封禁迁到 RPZ，并预留 `intel.hot.rpz`（≤10 万）与 `intel.broad.rpz`（≤30 万）两个空区，但**没有源管理能力**：不能新增/编辑/启停情报源，也不能定时同步。本期补齐，且必须遵守「全部默认关闭、用户手动启用、许可确认」的既定结论。

## 范围

### P1（可交付客户）

1. `intel_source` CRUD：名称、URL、格式（domain/CSV/RPZ/AXFR）、层（hot/broad）、动作、启停、`update_interval`、许可标签、鉴权头/Key 引用（密钥不入库，走 `/run/secrets` 或加密字段）；
2. 预设模板（**默认关闭**，仅展示许可与来源说明）：
   - abuse.ch URLhaus/ThreatFox：新接口需 Auth-Key，社区版**不许商用**，客户自备 key；
   - Spamhaus：免费账号仅 IP 类；DBL 属付费且 ZRD 不加载；
   - OpenPhish：需进一步核实许可后再决定是否提供模板；
   - 明确**不内置** HaGeZi / OISD（GPL-3.0）；
3. 拉取与编译：HTTPS + `curl`（不使用 `rsync`），单源失败保留上一版；总量接近容量上限时告警并拒绝启用；
4. 调度：按源 `update_interval` 拉取 → 编译 → 单区热载 → `list_auth_zones` 校验 → 失败回滚；
5. 前端：源列表（启用状态/上次成功时间/条目数/许可标签）、启停与手动同步、许可确认弹窗；
6. 可观测：每源拉取耗时/条目数/失败原因入审计与指标。

### P2（后续）

- 质量闸门（误报抽检、白名单自动排除、单源贡献上限）；
- revision 与一键回滚（按源保存历史编译产物）；
- 离线导入（zip/CSV 上传，用于无外网客户）；
- 蓝绿双区切换（大源整区替换零抖动）；
- view-tag 粒度（按客户端网段选源）。

### 2026-11-19 · 修复：保存鉴权密钥报权限错误

- **现象**：在「编辑情报源」里给 abuse.ch ThreatFox 填 `Auth-Key` 保存，界面报 `mkdir /run/ipam/intel-secrets: permission denied`。
- **根因**：控制面以 `uid=10001(ipam)` 运行，`/run/ipam` 共享卷属 root（0755），无法创建子目录；`volume-init` 只初始化了 `ch-exports`/`vector-config`。
- **修复**：`volume-init` 增加 `ipam-run` 挂载并预建 `/run/ipam/intel-secrets`（`chown 10001:10001`、`chmod 700`）；`writeSecret` 失败统一返回 `INTEL_SECRET_DIR_UNWRITABLE` 并提示可用 `IPAM_INTEL_SECRET_DIR` 覆盖。
- **验证**：真实栈重建后目录属主/权限正确；API 写入探针密钥 `hasSecret=true`（文件 0600），`clearSecret` 后删除；`go test ./...`、`golangci-lint` 0 issues。

### 2026-11-19 · 修复：abuse.ch 同步 HTTP 410

- **现象**：ThreatFox 配好 Auth-Key 后同步失败，`lastError=http 410`。
- **根因**：abuse.ch 2026-10 关闭无鉴权下载，旧 `export/csv/recent/`、`downloads/hostfile/` 全部 410；新 v2 导出要求 Auth-Key 放在 URL 路径。
- **修复**：预设改为 `https://{threatfox,urlhaus}-api.abuse.ch/v2/files/exports/{secret}/hostfile.txt`；`{secret}` 拉取时才替换（密钥不入库/不回显），错误文本脱敏；URL 占位符纳入「需要密钥」校验；迁移 `0046` 仅升级旧预设值；前端按占位符显示密钥输入并提示勿粘贴到 URL。
