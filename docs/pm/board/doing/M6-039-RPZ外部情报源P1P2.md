## 背景

M6-038 已把封禁迁到 RPZ，并预留 `intel.hot.rpz`（≤10 万）与 `intel.broad.rpz`（≤30 万）两个空区，但**没有源管理能力**：不能新增/编辑/启停情报源，也不能定时同步。本期补齐，且必须遵守「全部默认关闭、用户手动启用、许可确认」的既定结论。

## 范围

### P1（可交付客户）

1. `intel_source` CRUD：名称、URL、格式（domain/CSV/RPZ/AXFR）、层（hot/broad）、动作、启停、`update_interval`、许可标签、鉴权头/Key 引用（密钥不入库，走 `/run/secrets` 或加密字段）；
2. 预设模板（**默认关闭**，仅展示许可与来源说明）：
   - abuse.ch URLhaus/ThreatFox：新接口需 Auth-Key，社区版**不许商用**，客户自备 key；
   - Spamhaus：免费账号仅 IP 类；DBL 属付费且 ZRD 不加载；
   - OpenPhish：需进一步核实许可后再决定是否提供模板；
   - 明确**不内置** HaGeZi / OISD（GPL-3.0）；
3. 拉取与编译：HTTPS + `curl`（不使用 `rsync`），单源失败保留上一版；总量接近容量上限时告警并拒绝启用；
4. 调度：按源 `update_interval` 拉取 → 编译 → 单区热载 → `list_auth_zones` 校验 → 失败回滚；
5. 前端：源列表（启用状态/上次成功时间/条目数/许可标签）、启停与手动同步、许可确认弹窗；
6. 可观测：每源拉取耗时/条目数/失败原因入审计与指标。

### P2（后续）

- 质量闸门（误报抽检、白名单自动排除、单源贡献上限）；
- revision 与一键回滚（按源保存历史编译产物）；
- 离线导入（zip/CSV 上传，用于无外网客户）；
- 蓝绿双区切换（大源整区替换零抖动）；
- view-tag 粒度（按客户端网段选源）。

## 验收要点（P1）

- [x] 源默认全部关闭；启用前必须确认许可，未确认无法启用；
- [x] 单源拉取失败不影响其他源与现有封禁（保留上一版缓存）；
- [x] 热载失败自动回滚（复用 M6-038 单测路径）；
- [ ] 30 万条宽层编译耗时与内存符合方案 §8 预算（2.9s / 186MB），查询无 SERVFAIL（本机仅验证到 10 万级截断逻辑）；
- [x] zh/en 文案成对，界面不出现底层产品名；
- [ ] 客户环境或离线包完成一次真实源端到端验证（本机外网受限，见 M6-038 遗留）。

## 实施记录

### 2026-11-19 · P1 主体（源管理 + 预设 + 调度 + 分层编译）

**做了什么**

- **数据模型**：新增迁移 `db/postgresql/migrations/0045_intel_source.sql`，只存元数据与最近同步状态；拉取到的域名落磁盘缓存（`<rpz dir>/sources/<key>.domains`），百万级 IOC 不入库。
- **预设（全部默认关闭）**：`internal/module/dns/intel_source.go` 内置 5 个模板——abuse.ch URLhaus、abuse.ch ThreatFox、Spamhaus DBL（付费，URL 留空由用户填）、StevenBlack/hosts（MIT）、OpenPhish Community（商用待法务）。不内置 HaGeZi/OISD（GPL-3.0）与 Phishing Army（CC BY-NC）。预设仅在首次启动落库，之后 URL/开关由用户维护，上游改接口无需升级。
- **启用校验**：启用必须 `ackLicense=true`；配置了鉴权头的源还必须先写密钥（`INTEL_SOURCE_SECRET_REQUIRED`）。启用后立即尝试同步一次，失败不回滚启用状态，错误写入 `lastError` 供 UI 展示。
- **密钥**：落 0600 文件（默认 `/run/ipam/intel-secrets`，可用 `IPAM_INTEL_SECRET_DIR` 覆盖），库内只存 `secret_file` 路径，接口只回 `hasSecret`，明文不落库、不回传。
- **解析器 `auto`**：逐行取第一个「像域名」的 token，兼容 hosts / 域名清单 / URL 清单 / CSV / RPZ 文本；跳过 IP、纯数字标签、非法标签（首尾连字符）。
- **拉取**：HTTPS + `curl` 等价实现（`net/http`，60s 超时、正文 ≤32MB），不使用 `rsync`。
- **失败回退**：拉取失败或解析到 0 条都记为 `failed`，**不覆盖**磁盘缓存（fail-safe 继续拦截）。
- **分层编译**：`intel.go` 编译时把启用源按 hot/broad 注入对应区，统一剔除白名单（含子域语义），热层 ≤10 万、宽层 ≤30 万，超限截断并记日志。
- **调度**：`StartIntelScheduler` 每分钟检查到期源（无启用源时为空转），到期才同步，同步后复用 M6-038 的内容指纹 + 单区热载 + serial 校验链路。
- **契约**：先改 spec（`paths/intel.yaml` 追加 `IntelSourceCollection/Item/Sync`，`components/schemas/intel.yaml` 追加 `IntelSource*`，`openapi.yaml` 挂 3 条路径）再 `bash scripts/gen-openapi.sh` 再生 Go/TS。
- **前端**：封禁管控页新增「情报源」卡（新增 `views/dns/blocklist/intel-sources-card.vue`）：默认关闭徽标、许可/商用提示、启用需勾选确认、密钥只写不回显、立即同步、编辑 URL/层/间隔/密钥、删除仅自定义；同时在「RPZ 运行态」卡增加「查看拦截记录」按钮，跳日志检索并预置 `action=blocked`。
