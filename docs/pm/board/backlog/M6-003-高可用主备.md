## 前置条件（重要）

**单台主机无法实现真正的高可用。** keepalived VRRP 需要至少两个节点；Kea hot-standby 需要两台 peer；主机断电/内核/磁盘故障时，同机所有容器一起不可用。

- 003B 双机主备：需要 **2 台独立主机/VM**，位于不同电源、网络与磁盘故障域（同宿主机的两台 VM 只能用于功能验证，不能作为生产 HA）。
- 单主机阶段：只能做 **003A 单机韧性 + 冷备恢复**，SLA 明确排除宿主整机故障。

## 003A 单机韧性（现在可做）

- Docker healthcheck + `restart: unless-stopped`（已具备）；
- systemd 开机自启 + 看门狗定时器（健康检查失败自动 `docker compose up -d`）；
- 备份/恢复演练（M6-002 已具备）+ 冷备 RTO 文档；
- 监控告警（M6-005 已具备）；
- 磁盘/内存/证书容量告警与日志归档；
- 单机故障恢复手册（重装/换盘/恢复备份）。

验收：健康检查失败后 ≤2 分钟自动恢复容器；冷备恢复 RTO 有实测记录；单机边界写入售前说明。

## 003B 双机主备（需第二节点）

- keepalived 镜像 + 双节点 compose/Helm profile（unicast VRRP、VIP、脑裂保护）；
- Kea hot-standby（lease 同步、max-unacked-clients）；
- `config-replicate` 幂等推送与周期对账；
- 切换后全量对账；
- 故障演练脚本与报告。

验收：kill -9 主节点 VIP 漂移 ≤30s、续租不中断、无重复租约；主备配置无漂移。

## 推荐硬件/网络

- 两台同规格主机（或不同物理机上的 VM），各 4C8G/200GB SSD；
- 独立电源、独立上联交换机/链路；
- 心跳/VRRP 使用独立管理网段，unicast；
- 外部 NTP；UPS 可选但建议。
