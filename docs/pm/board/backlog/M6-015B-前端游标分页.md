## 背景

M6-015 已在后端为日志、审计、台账提供游标分页（`cursor` 取自上一页 `nextCursor`），并对 offset 深分页设了 1 万条上限（`PAGE_TOO_DEEP`）。前端现状不一致：

| 页面 | 现状 | 问题 |
|---|---|---|
| 日志检索 `views/logs/search/index.vue` | `page`/`pageSize` offset 分页 | 超过 1 万条被后端拒绝，前端只能收敛页码并提示缩小时间窗 |
| 操作审计 `views/logs/audit/index.vue` | 已用 `cursor` | 无需改造，作为参照实现 |
| 地址台账 `views/dhcp/ledger/v4.vue` | 单次 `pageSize: 500` + 客户端分页 | 地址数 >500 的网段数据被截断，地图状态不完整 |

## 目标

- 日志检索改为「上一页 / 下一页」游标翻页，移除深分页上限提示；
- 台账地图按游标分批拉全量（或按可视区增量加载），不再截断 500 行；
- 保留现有筛选条件、时间窗与导出行为；
- 兼容旧链接/刷新：URL 不持久化游标，刷新回到第一页。

## 方案要点

### 日志检索

- 状态改为 `cursorStack: string[]`（记录每页入口游标）+ `nextCursor`；
- 提供「上一页」时从栈中弹出；「下一页」使用 `nextCursor`；
- 保留总数为近似值（`total` 仍由后端返回，仅用于展示）；
- 移除 `MAX_OFFSET` / `reachableTotal` / 深分页提示文案（或改为说明「最多可翻至最后一条」）；
- 导出 CSV 继续走后端全量导出接口，不受分页影响。

### 台账地图

- 首次 `listLedger({subnetId,family,pageSize:500})`，若 `nextCursor` 非空则继续拉取直到为空（设上限与进度提示）；
- 或改为「先渲染首屏，滚动/缩放到可视区时增量加载」，优先保证 /16 等大网段可用；
- 加载期间显示进度与「已加载 N 个地址」；
- 失败时保留已加载数据并提示重试。

## 验收标准

- [ ] 日志检索可逐页翻到结果末尾，不再出现「深分页受限」提示；
- [ ] 翻页/改筛选/改时间窗行为正确，无重复或漏行（以 `(ts, client_mac, domain)` 排序键为准）；
- [ ] 台账 /24 与 /22 网段地址完整（>500 条时不再截断）；
- [ ] 加载大网段有进度提示，页面不卡死；
- [ ] 单测覆盖游标栈与「下一页/上一页」边界；
- [ ] E2E 覆盖日志翻页与台账大网段加载；
- [ ] 文案 zh/en 成对更新，术语门禁通过。
