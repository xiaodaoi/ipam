## 目标

把当前「单机韧性 + 冷备」升级为真正的双机主备：VRRP VIP 漂移、Kea 租约热备、配置幂等复制与切换后对账，满足架构决策 **D8：RTO≤30s**。

## 前置条件（硬约束）

**单台主机无法实现真正的高可用。**

- keepalived VRRP 至少 2 个节点；Kea hot-standby 需要两台 peer；
- 两台主机必须位于不同电源、网络与磁盘故障域（同宿主机的两台 VM 只能做功能验证，不能作为生产 HA）；
- 主备各自独立 PostgreSQL / ClickHouse 实例（架构 §高可用：不引入分布式存储）；
- VRRP 使用独立管理网段、unicast；外部 NTP；建议 UPS。

## 实施范围

1. **keepalived 容器**：hostNetwork + NET_ADMIN（唯一特权容器），unicast VRRP、VIP 漂移、备机抢占延迟 60s、双向心跳与脑裂保护；
2. **Kea hot-standby**：`libdhcp_ha` 配置（primary/standby、`max-unacked-clients`）、lease 同步、故障切换后租约一致性；
3. **config-replicate**：主节点控制面把组织/子网/池/DNS 转发等配置幂等推送到备节点，周期对账并暴露漂移指标；
4. **切换演练脚本与报告**：`kill -9` 主节点进程/整机断电两种场景，记录 VIP 漂移耗时、续租成功率、重复租约数；
5. **文档**：安装/升级/运维手册新增双机章节；单机边界说明与双机 SLA 区分；
6. **监控**：keepalived 状态、VIP 归属、Kea HA 状态、配置漂移告警。

## 验收标准

- [ ] 主节点 `kill -9` 后 VIP 漂移 ≤30s，客户端续租不中断；
- [ ] 主节点整机断电后 VIP 漂移 ≤30s，DNS/DHCP 服务恢复；
- [ ] 切换后无重复租约，Kea HA 状态回到 normal；
- [ ] 主备配置对账无漂移（连续 24h 漂移计数为 0）；
- [ ] 切换演练报告归档（时间线、指标、异常）；
- [ ] 双机部署文档、故障处理手册、监控告警齐备；
- [ ] 单机安装路径不受影响（compose profile 区分）。
