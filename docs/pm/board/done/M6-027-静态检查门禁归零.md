## 问题（实测，HEAD = d036804）

按 `scripts/make-part.sh lint`（= `golangci-lint run` + `cd web && pnpm run lint`）逐段执行：

| 阶段 | 结果 |
|---|---|
| golangci-lint | `0 issues`（本来就是绿的） |
| stylelint | **29 errors**（`order/properties-order`、`rule-empty-line-before`），7 个文件 |
| oxfmt --check | **64 files** 未格式化 |
| oxlint | **10 errors**（`no-non-null-assertion` ×6、`consistent-type-specifier-style` ×3、`prefer-lowercase-title` ×1）+ 1 warning |
| eslint | **2058 errors / 43 files**（其中 1645 条来自生成物 `schema.d.ts`；其余为 `perfectionist/sort-object-types`、`vue/html-closing-bracket-newline`、`@typescript-eslint/no-invalid-void-type` 等） |

两个结构性问题：

1. **格式化所有权冲突**：`vsh lint` 的执行顺序是 stylelint → oxfmt → oxlint → eslint，而
   eslint 中的排版类规则（`vue/html-closing-bracket-newline`、`unicorn/no-nested-ternary`、
   `unicorn/number-literal-case`）与 oxfmt 的规范化结果**方向相反**：
   `eslint --fix` 之后 oxfmt 报 34 个文件，`oxfmt` 之后 eslint 又报 176 条 —— 无法同时满足。
2. **生成物被当作手写代码检查**：`src/api/schema.d.ts`（16k 行，`gen-openapi.sh` 产出）与
   `src/icons/*.generated.ts` 由脚本生成，脚本本身不做格式化，导致「重新生成即有 diff」。

附带发现 1 处 M6-025 遗留：23 处 `toLocaleString/DateString/TimeString('zh-CN')`
在英文界面仍输出中文日期格式（M6-025 只统一了部分文件）。

## 目标

- `bash scripts/make-part.sh lint` 端到端 exit 0，且**可重复执行**（不再出现两套规则互相回滚）；
- 生成物不参与 lint/格式化，`make gen` / `make gen-icons` 后 `make lint` 仍为绿；
- 顺带修掉真实的代码问题，而不是靠 disable 掩盖；
- 明确的工具职责边界，写入文档，避免后续再踩。

## 决策（写入 `docs/dev/M6-027-静态检查与格式化约定.md`）

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | **oxfmt 是唯一格式化工具**；eslint 关闭 4 条与其冲突的排版规则（`vue/html-closing-bracket-newline`、`vue/multiline-html-element-content-newline`、`unicorn/no-nested-ternary`、`unicorn/number-literal-case`） | 消除 `eslint --fix ↔ oxfmt` 死循环；格式化只保留一处事实源 |
| D2 | 生成物加入 oxfmt `ignorePatterns` 与 eslint `ignores`（`apps/web-ipam/src/api/schema.d.ts`、`**/*.generated.ts`） | 生成脚本不做格式化，纳入门禁必然产生「重新生成即有 diff」 |
| D3 | `*.d.ts` 关闭 `unicorn/require-module-specifiers` | 模块增强文件必须保留 `export {}`，否则 `declare module` 从「增强」退化为「整体替换」 |
| D4 | `pnpm-workspace.yaml` / `package.json` 关闭 `pnpm/yaml-no-unused-catalog-item`、`pnpm/json-enforce-catalog` | 上游底座 catalog 保留模板/文档站依赖条目，清理会牵连上游升级路径 |
| D5 | eslint 配置集中在 `web/eslint.config.mjs`，不新增应用级配置 | 避免 `@vben/eslint-config` 在应用包内被判定为 extraneous 依赖 |

### 踩坑记录（重要）

`eslint --fix` 会把 `src/types/user-info.d.ts` 末尾的 `export {}` 当作
「empty export specifier」删除。该文件是 `declare module '@vben/types'` 的**模块增强**：
一旦失去顶层 import/export，TS 会把它当作全局脚本，`declare module` 由「增强」变成
「整体替换」，于是全仓 84 个 `Module '@vben/types' has no exported member` 错误。
处理：恢复 `export {}`，并在 eslint 中对 `**/*.d.ts` 关闭 `unicorn/require-module-specifiers`。
**以后不要对 `.d.ts` 直接跑 `eslint --fix`。**
