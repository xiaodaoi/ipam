## 背景

M6-039 把外部情报注入 RPZ 后，DNS 拦截日志已带 `action=blocked`，但只能在日志检索里逐条翻；
客户需要「谁在访问风险域名」的独立视图，以及一个把风险事件与系统故障汇总到一起的入口。
当前右上角通知栏是空列表（上游演示数据已移除），没有任何后端事件源。

## 目标

1. **风险 URL 报警**：从日志宽表聚合 `action=blocked` 事件，可按客户端地址 / 域名模糊查询，
   展示命中次数与时间范围；同（客户端 IP + 域名）在 1 小时窗口内累加为一条报警。
2. **系统故障报警**：数据库、日志存储、DHCP、DNS 掉线，磁盘水位 ≥90%，日志外发降级，
   情报源同步失败，上游探活失败，统一进入同一报警表。
3. **独立界面**：日志中心新增「报警日志」页，支持模糊搜索、类型/级别/状态过滤、
   统计卡（总数/未确认/严重）、趋势图、风险域名 Top、客户端地址 Top。
4. **右上角报警栏**：轮询未确认报警，徽标提示；点击通知 → 自动确认并跳转对应报警；
   支持单条确认与全部确认；「查看全部」进入报警日志页。
5. **确认语义**：确认是全局的（单机产品），记录 `acked_by`；未确认=徽标计数；
   系统故障恢复后自动置为 `resolved`，再次发生则重新打开。

## 非目标

- 邮件/Webhook/钉钉外发（M6-005 既有告警通道，本期不复用）；
- 按用户维度的已读状态（单机产品，全局确认即可）；
- 原始日志明细的二次存储（报警只存聚合结果，明细仍在 ClickHouse）。

## 设计要点

### 数据模型（PG `alert`）

| 字段 | 说明 |
|---|---|
| `dedup_key` | 唯一键：`dns\|<ip>\|<domain>\|<YYYYMMDDHH>` / `system\|<kind>\|<component>` |
| `source` | `dns` / `system` |
| `kind` | `risk_url`、`db_down`、`logstore_down`、`dhcp_down`、`dns_down`、`disk_pressure`、`log_export_degraded`、`intel_sync_failed`、`upstream_probe_failed` |
| `severity` | `critical` / `warning` / `info` |
| `status` | `open`（未确认）/ `acked`（已确认）/ `resolved`（已恢复） |
| `client_ip` / `client_mac` / `domain` | 风险 URL 维度 |
| `component` | 系统故障组件（中性名：database/logstore/dhcp/dns/host...） |
| `count` | 窗口内事件数（DNS）或连续故障次数（系统） |
| `first_seen` / `last_seen` | 首末发生时间 |
| `acked_at` / `acked_by` | 确认审计 |
| `resolved_at` | 恢复时间 |

- DNS 报警以「小时桶」入 `dedup_key`，采集器每 60s 回扫最近 2 小时，
  以 ClickHouse 的分桶累计值 `GREATEST` 合并，重复扫描不会重复计数。
- 系统报警按组件唯一；探针连续失败才报（避免网络抖动），恢复即 `resolved`。
- 保留 90 天，清理任务每日执行一次（可配置）。

### 采集

| 来源 | 判据 | 级别 |
|---|---|---|
| 风险域名访问 | CH `type=dns AND action=blocked AND sip!=''`，按 `(sip, domain, toStartOfHour(ts))` 聚合 | warning |
| 数据库 | `pool.Ping` 失败 | critical |
| 日志存储 | CH `Ping` 失败 | critical |
| DHCP 服务 | Kea `version-get` 失败 | critical |
| DNS 服务 | unbound 控制套接字不可达 | critical |
| 磁盘 | 任一挂载点使用率 ≥90% | warning |
| 日志外发 | `exportSvc.Status().Degraded` | warning |
| 情报源 | 已启用且 `lastStatus=failed` | warning |
| 上游探活 | 已启用上游连续失败 ≥3 次 | warning |

### 接口（`/api/v1/logs/alerts*`，复用 `logs` 权限域）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/logs/alerts` | 列表：from/to/q/source/kind/severity/status + 分页 |
| GET | `/logs/alerts/stats` | 统计：总量/状态/级别/类型 + Top 域名/Top 客户端/趋势 |
| GET | `/logs/alerts/unread` | 报警栏：未确认总数 + 最近 N 条 |
| POST | `/logs/alerts/ack` | 单条或批量确认 `{alertIds}` |
| POST | `/logs/alerts/ack-all` | 确认全部未确认 |

确认动作对 `operator/auditor/user` 降级为 `logs:read`（确认不是配置变更），
其余写操作仍按 `logs:write`；RBAC 对 `/api/v1/logs/alerts/ack*` 做路径特化。
