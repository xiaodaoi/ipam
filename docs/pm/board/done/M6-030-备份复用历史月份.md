## 问题

`internal/module/backup/backup.go` 每次备份都调用 `ExportMonth` 重新导出**所有**有数据的月份。
按 `operations.md` 容量口径（500 万行/天 ≈ 223MB/天，180 天 ≈ 40GB）：

- 单次备份需重导 40GB，默认 2h 预算仍可能不够；
- 保留 7 份 → 磁盘占用随份数线性增长（≈280GB）。

日志按月分区且历史月份基本只读，重复导出既浪费 CPU/IO，也让备份窗口不可控。

## 目标

- 历史月份在**数据未变化**时复用上一份成功备份中的 Parquet（硬链接，不复制、不额外占盘）；
- 数据变化（迟到日志/回填）时自动重新导出，保证备份内容与库一致；
- 复用前校验源文件完整（`PAR1` 结尾），避免传播 M6-028 发现的截断文件；
- 恢复语义不变：每份备份目录仍是自包含的（硬链接在源备份被清理后仍有效）。

## 方案

| 项 | 设计 |
|---|---|
| 行数指纹 | `LogStore` 用 `MonthRows(ctx)` 取代 `Months(ctx)`（来自 `system.parts` 元数据，轻量）；manifest 新增 `monthRows` |
| 复用条件 | 最近成功备份中存在该月文件 **且** 其 manifest 的 `monthRows[month]` 与当前一致 **且** 文件尾为 `PAR1` |
| 复用方式 | `os.Link(src, dst)`；失败（跨设备等）则回退重新导出 |
| 当前月 | 不特殊处理：行数一致即复用，有新增日志则自然重新导出 |
| 兼容旧备份 | 无 `monthRows` 的旧 manifest 不复用，逐月重新导出一次后形成新基线 |
