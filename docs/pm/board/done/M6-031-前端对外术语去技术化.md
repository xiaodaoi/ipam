# [M6-031] 前端对外术语去技术化

| 字段 | 内容 |

## 问题

默认界面在 4 类位置暴露底层技术名，客户会据此判断技术栈：

| 位置 | 具体 |
|---|---|
| 仪表盘硬编码 | `views/dashboard/ipam/index.vue` `LIGHT_LABEL` → 服务健康卡显示 `PostgreSQL / ClickHouse / Kea DHCP / Unbound DNS` |
| 页面硬编码 | `views/dhcp/subnets/index.vue`（`Kea #12`、`Kea subnet-id`、`Kea lease_cmds`）、`components/log-storage-panel.vue`（`ClickHouse TTL`） |
| i18n 文案 | zh-CN 48 处、en-US 47 处：`dhcp.json` / `logs.json` / `system.json` / `page.json` |
| 衍生实现细节 | `Vector`、`Parquet`、`config-set`、`lease_cmds`、`option-data`、`client-classes`、`system.parts` |

## 目标

- 默认界面只出现业务词，不暴露具体产品名与实现细节；
- 运维排障能力不丢失：仪表盘服务健康卡 tooltip 悬停显示原始组件名；
- 法务归属保留：关于页开源组件名称原样保留，区块标题改为「开源组件与许可」；
- 建立门禁，防止后续新增文案重新引入技术名。

## 方案

| 项 | 决策 |
|---|---|
| 处置档位 | A 直接删（语境已含 DHCP/日志/DNS）≈60%；B 换业务词 ≈30%；C 原样保留 ≈10% |
| 术语 | PostgreSQL/PG→配置数据库；ClickHouse→日志存储；Kea→DHCP 服务；Unbound→DNS 解析服务；Vector→日志采集服务；Parquet→归档文件 |
| 硬编码 | `LIGHT_LABEL`、`ClickHouse TTL`、`Kea #`、`Kea lease_cmds` 全部 i18n 化 |
| 不动项 | API 字段（`keaSubnetId` 等变量名）、后端 `detail`、采集配置、关于页组件名 |
| 门禁 | 新增 `scripts/check-ui-terms.py`，带文件 allowlist 与行内 `ipam-term-allow` 标记 |
