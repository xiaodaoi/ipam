# done/ 归档说明与看板口径

本目录存放**已交付并收口**的任务卡。2026-11-16 进行了一次看板收口（M6-035），把 `review/` 中 106 张历史卡统一归档到这里，并拆出真正未完成的事项。

## 列的含义

| 列 | 含义 | 进入条件 | 离开条件 |
|---|---|---|---|
| `backlog/` | 已识别、未排期或外部阻塞 | 需求成立但缺少排期/环境/依赖 | 开始实施 → `doing/` |
| `doing/` | 当前会话正在做 | 一会话一卡，开工时移入 | 交付并验收 → `done/`；阻塞 → `backlog/` 并注明原因 |
| `review/` | 待验收的临时队列 | 实现完成、等待复验/回填证据 | 验收通过 → `done/`；发现问题 → 回 `doing/` |
| `done/` | 已交付 | 交付内容合入主干、验收证据已记录 | 一般不再移动 |

> `review/` 是**临时队列**，不允许长期堆积；每次会话收尾应把已验收的卡移入 `done/`。

## 未勾选项的处理原则

归档卡中的 `- [ ]` 分三类，处理方式不同：

| 类型 | 例子 | 处理 |
|---|---|---|
| 当时未回填的验收记录 | M2 多数前端卡的「typecheck 通过」 | 保留原样，视为历史记录；不重复跟踪 |

| 真实功能缺口 | Syslog TLS、前端游标分页 | 已拆成独立卡，见下表 |
