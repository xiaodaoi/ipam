## 背景与根因

1. 现有封禁走 `unbound-control local_zone`，**RPZ 能力已具备但未启用**：unbound 1.26.0 已编译 `respip`，`module-config: "python iterator"` 未加载 respip。
2. 实测确认 **`local-zone` 优先于 RPZ `rpz-passthru`**，因此「白名单豁免」在旧路径上无法实现，必须把封禁整体迁到 RPZ。
3. 实测确认 **白名单 zone 必须排在 `rpz:` 子句第一位**，否则仍被后续 zone 拦截。
4. 实测确认 **损坏的 zone 文件 reload 会让 zone 进入 expired 状态**（未缓存域名无结果），因此必须「先校验、再原子替换、失败回滚」。
5. 历史缺陷「删条目后重加 / unbound 重启后不再下发」的根因是只信内存 `applied` 记账；改为显式编译产物 + `list_auth_zones` 实际态校正。
6. 拦截日志无 `action=blocked`，`rpz-log` 行格式已实测，可解析入库。

## 目标（P0）

- 启用 unbound `respip`，`num-threads: 4`；
- 固定 4 个 `rpz:` 子句（白名单 / hot / broad / custom，顺序固定，运行期不增删）；
- 现有封禁条目迁到 `intel.custom.rpz`，动作映射 `nxdomain/drop/tcp_only/redirect` → RPZ 原生；
- 白名单（passthru）落 `wl.whitelist.rpz` 并排第一，支持增删 + 立即 `flush_zone` 生效；
- 编译失败自动回滚；`list_auth_zones` 实际态校正（解决 M6-037）；
- `rpz` 日志 → vector → `action=blocked`，仪表盘「今日拦截量」可用；
- 前端在「封禁管控」页增加「运行态」与「拦截白名单」两块。

## 非目标（P1+）

- 情报源增删改（`intel_source` CRUD）、预设模板、自动同步调度、abuse.ch/Spamhaus 接入、质量闸门、revision 回滚、离线导入 → P1/P2（方案文档 §14）。

## 方案要点

| 项 | 决策 |
|---|---|
| zone 布局 | `wl.whitelist.rpz`（passthru）→ `intel.hot.rpz`（P0 空）→ `intel.broad.rpz`（P0 空）→ `intel.custom.rpz` |
| 渲染 | 新包 `internal/pkg/rpz`：SOA/NS 自举、确定性排序去重、`CNAME .` / `rpz-drop.` / `rpz-tcp-only.` / `rpz-passthru.` / Local Data `A <提示页IP>` |
| 生效 | 写 `.tmp` → 控制面自校验 → 原子 rename → `auth_zone_reload <zone>` → `list_auth_zones` 校验 serial，失败恢复上一版 |
| 白名单 | `intel_whitelist` 表；kind=qname/suffix；变更后重编译 + `flush_zone` |
| 缓存 | `cache-max-ttl=300`；白名单逐条 flush（实测 22ms/条），整源停用不逐条 flush |
| 语义收紧 | plain pattern 仅拦该名；`*.x` 同时输出 `x` 与 `*.x`（旧 `local_zone static` 会拦整棵子树，记录为行为变更） |
| 权限 | 复用 `dns:read|write`（`/api/v1/dns/*` 自动映射），不新增权限域 |

**关键实测/踩坑（均已在代码注释与实现说明中固化）**

1. RPZ 区 owner 必须写相对区名（`www.crphb.com`，加尾点会被当区外数据丢弃）——写成绝对名时 zone 正常加载但策略完全不生效。
2. `rpz-log-name` 必须显式配置，否则命中日志不带区名，无法区分是哪一层策略。
3. `unbound-checkconf` 只校验候选块会报 `RPZ requires the respip module`；复用主 conf 又因控制面镜像无 python 运行时在 `Py_InitializeFromConfig` 失败 → 只补 `respip iterator`。
4. serial 不能取 `now`：内容未变时沿用旧 serial 并跳过写盘/热载，否则每分钟调度整区重载（300k 条目≈3s/次）。

**验证结果**
