## 问题

`logexport.Render` 为了支持 M6-008 采样，把模板里 ClickHouse sink 的 `inputs = ["normalize"]` 整体替换为 `["log_out"]`，而 `log_out` 在自动降级时是 `.severity != "INFO"` 的过滤器。结果：

- 磁盘水位 ≥90% 自动降级后，所有 DNS/DHCP **INFO 事件被丢弃**，ClickHouse 完全停止写入；
- 仪表盘 `onlineNow/qps5m/blockedToday` 与日志概览 KPI 全部变成 0，但页面没有任何“采集已停止”的提示；
- 外发采样策略错误地绑定了内部存储，二者无法独立控制。

## 目标

拆分“内部入库”和“外部外发”两条链路，自动降级只降低内部写入量、绝不清零 INFO；页面与文档明确采样语义。

## 验收标准（可测）

- [x] 渲染结果中 ClickHouse sink 固定接 `ch_out`（`normalize → ch_out → clickhouse`），外发 sink 接 `log_out`。
- [x] 正常运行时 `ch_out` 为全量（rate=1）；自动降级时按可配置 1/N（默认 10）抽样，INFO 仍会入库。
- [x] 外发策略 all/sample/errors 仅作用于 `log_out`；用户选择 errors 不再影响内部入库。
- [x] `IPAM_LOG_DEGRADE_SAMPLE_RATE` 可配置，非法值回退默认 10；API 返回 `ingestSampleRate`。
- [x] 页面文案明确“采样仅外发、入库默认全量、降级仅抽样”，zh/en 成对。
- [x] ClickHouse 系统日志表设置保留期，避免再次因系统日志占满磁盘触发降级。
- [x] 单测覆盖双链路、降级抽样、外发 errors 不影响入库；真实栈恢复写入。

## 实施记录（追加式，勿删旧条目）

### 2026-11-23 · 会话1

- 根因：`Render` 把 CH sink 输入替换成外发 `log_out`，自动降级 errors 过滤器导致 INFO 全丢。
- 修复：拆为 `normalize → ch_out → clickhouse` 与 `normalize → log_out → siem_*`；降级时 `ch_out` 1/N 抽样（默认 10），外发仅异常。
- 契约：新增只读 `ingestSampleRate`；页面展示降级期间的入库抽样率。
- 部署：新增 `IPAM_LOG_DEGRADE_SAMPLE_RATE`，ClickHouse 系统日志表加 TTL。

### 2026-11-23 · 会话1（验证）

- 真实栈 `/etc/vector/vector.toml`：`[sinks.clickhouse] inputs = ["ch_out"]`，`ch_out.rate = 1`；Vector 恢复写入，ClickHouse `ipam.logs` 持续增长（近 10 分钟 dns 45k+ / dhcp 186）。
- ClickHouse 系统日志 TTL 生效：text_log 2 天、trace/metric/query 等 3 天、trace/processors 1 天；`part_log` 另用 ALTER 补 TTL；磁盘占用由 90% 降至约 69%。
- `go test ./internal/module/logexport/` 覆盖双链路、降级 1/N 抽样与 “外发 errors 不影响入库” 场景。
- unbound 镜像已重建（旧镜像 2026-09-03，缺 logrotate）：容器内 `/usr/sbin/logrotate` 与 `/etc/logrotate.d/unbound` 就位，logrotate 后台循环运行；重建后 DNS 解析与日志入库正常（近 2 分钟 dns 7.5k+ / dhcp 40）。
- 降级告警文案同步为「日志入库与外发已降级」，避免再被理解为只影响外发。
