## 问题（实测）

1. `POST /api/v1/orgs` 传 `{"name":""}` 返回 **201**，落库一条空名称组织，违反 OpenAPI
   `OrgCreate.name` 的 `minLength: 1 / maxLength: 64`。
2. 唯一性三处不一致：
   - 内存实现 `MemOrgStore.Create`：同父 `EqualFold` 判重；
   - `OrgService.Update`（改名）：同父 `EqualFold` 判重；
   - PG `UNIQUE (parent_id, name)`：大小写敏感，**且根节点 `parent_id IS NULL` 时 NULL 互不相等，导致同名根节点可重复**。
3. PG 唯一冲突未映射：直接冒泡为 **500 INTERNAL**，而非契约约定的 **409 ORG_NAME_DUP**。
4. 名称未 trim：`" 研发部 "` 与 `"研发部"` 可共存。

## 目标

- 服务层统一做名称规范化（trim 半角/全角空格）与长度校验（1–64 个字符，按 rune）；
- 同父（含根节点）名称大小写不敏感唯一，内存与 PG 行为一致；
- PG 唯一冲突映射为 `409 ORG_NAME_DUP`；
- 数据库层补充等价唯一索引，防绕过服务层写入；
- 清理历史空名称节点（迁移内安全删除，仅限无子节点/无引用的空名节点）。

## 验收标准

- [x] `POST /orgs {"name":""}` → `400 BAD_REQUEST`（code `ORG_NAME_REQUIRED`）
- [x] `{"name":"   "}` / `{"name":"\u3000"}` → `400`
- [x] 65 个字符 → `400`（code `ORG_NAME_TOO_LONG`）
- [x] `{"name":" 华东区 "}` → 201 且 `name == "华东区"`
- [x] 同名根节点（`parentId` 缺省）→ `409 ORG_NAME_DUP`
- [x] 大小写不同的同名兄弟 → `409`
- [x] `PATCH /orgs/{id}` 改名同样受校验，空名/超长/重名 → 400/400/409
- [x] 迁移 0042 可重复执行（`IF NOT EXISTS`），并在真实库上验证索引生效
- [x] 单测覆盖上述规则；`go test ./...`、E2E 17/17 通过

## 范围外

- 子网/上游等其他实体的同名策略（如后续需要另立卡）；
- 组织名称国际化（仅做长度与空白规范化，不做字符集限制）。

- 唯一性判重依赖服务层 `List()` 全量扫描 + 数据库唯一索引双保险；组织规模（<1e4）下可接受，后续若组织数量级增长需改为带索引的 `Exists` 查询。
