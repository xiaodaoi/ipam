## 问题

M6-032/M6-033 已把主机与控制面指标落库，并在「系统管理 → 服务与运行」提供基础趋势卡片，但排障时仍缺少一个**独立的监控视角**：

- 曲线只有 4 张，缺少容量构成类视图（磁盘各挂载点占比、内存构成、连接池占用）；
- 只能按预设时间范围看，不能自定义起止时间查询；
- 看不到逐条采样明细，无法核对某个时刻的具体数值。

## 目标

- 「日志中心」新增独立菜单页「主机资源」（`/logs-center/host`）；
- 展示当前快照（CPU/内存/磁盘/负载/连续运行）+ 时间窗峰值；
- 曲线图：CPU、内存、磁盘、1 分钟负载；
- 饼图：磁盘使用分布（按挂载点）、内存构成（已用/可用）、数据库连接池（占用/空闲）；
- 查询：预设范围（1h/6h/24h/7d/30d）+ 自定义起止时间 + 查询按钮；
- 采样明细表：时间、CPU、内存、磁盘、负载、并发任务、连接池、日志延迟；
- 遵循 M6-031 术语规范，不出现数据库/日志存储等底层产品名。

## 方案

| 项 | 决策 |
|---|---|
| 路由 | `router/routes/modules/logs.ts` 新增 `LogHost`，authority `dash:read`（与指标 API 域一致，内置 4 个角色均有） |
| 页面 | `views/logs/host/index.vue`，复用 `PageHeader/StatCard/TrendChart/MetricRing` 与现有样式类 |
| 饼图 | 新增通用 `components/pie-chart.vue`（SVG 环形饼图，支持中心汇总值、图例、空态；无第三方依赖） |
| 曲线数据 | `getSystemMetricsHistory({from,to,step})`，step 由时间窗推导（与运行页一致，服务端 ≤720 点兜底） |
| 峰值 | `getSystemMetricsSummary(hours)`；自定义窗口按小时换算 |
| 饼图数据 | 当前快照 `getSystemMetrics`（磁盘按挂载点、内存 used/available、连接池 inUse/max）；30s 轮询 |
| 明细表 | 历史返回点直接在客户端分页展示，不再新增后端端点 |
| 文案 | zh-CN / en-US 成对新增 `page.logs.host` 与 `logs.host.*` |
