## 问题

M6-032 之前，主机资源只有瞬时值：客户问「昨晚 2 点是不是 CPU 打满 / 磁盘是不是被备份写满」无法回答。后端落库后，管理页仍需要一个可读入口，把「历史 + 峰值 + 控制面状态」放在同一屏，且不暴露底层技术名（M6-031 规范）。

## 目标

- 「系统管理 → 服务与运行」新增「历史趋势」卡片；
- 时间范围 1h / 6h / 24h / 7d / 30d，四张趋势图（CPU / 内存 / 磁盘 / 1 分钟负载）；
- 一行峰值摘要（CPU / 内存 / 磁盘及最满挂载点）+ 历史数据起始时间；
- 控制面状态：并发任务数、应用内存、数据库连接、日志更新时间；
- 空态可读（服务刚启动未满 1 分钟时不能白屏或报错）。

## 方案

| 项 | 决策 |
|---|---|
| 组件 | 复用 `components/trend-chart.vue`（`{ts, value}[]`）与现有 `ipam-figure-row` 样式 |
| 数据 | `getSystemMetricsHistory({from,to,step})` + `getSystemMetricsSummary(hours)` 并行请求，`Promise.allSettled` 容错 |
| 粒度 | 1h/6h → 60s；24h → 120s；7d → 600s；30d → 1800s（服务端再按 ≤720 点兜底放大） |
| 文案 | zh-CN / en-US 成对新增 `system.runtime.history.*`；术语遵循 M6-031（不出现 PG/CH 等产品名） |
| 刷新 | 进入页面随 `load()` 拉取；切换时间范围即时重查，不整页刷新 |
| 磁盘口径 | 展示「最满挂载点」使用率，图下注明挂载点路径（仅管理页可见） |
