## 目标

恢复日志采集链路（Kea/Unbound → Vector → ClickHouse），使日志中心检索能查到近期日志。

## 现象与根因（可复现）

- **现象**：`ipam.logs` 最新一行停在上一次采集时段，前端默认「近 6 小时」窗口恒为空。
- **定位**：`docker logs ipam-vector-1` 反复出现 clickhouse sink `HTTP 500`；`system.errors` 中 **code 632 `UNEXPECTED_DATA_AFTER_PARSED_VALUE`**：
  `Unexpected data '%ens160","' after parsed IPv6 value 'fe80::13ee:ace7:ccb7:97fc'`。
- **根因**：DHCPv6/DNS 日志中的链路本地 IPv6 携带 **zone 后缀**（`fe80::…%ens160`），写入 ClickHouse `Nullable(IPv6)` 列时解析失败；`json_each_row` 整批原子失败 → Vector 无限重试同一批 → 采集彻底卡死。

## 验收标准（可测）

- [x] `config/vector/vector.toml` 的 `normalize` 对 `client_ip`/`sip`/`answer_ip` 剥离 `%zone`
- [x] `vector validate` 通过
- [x] 重启 Vector 后 ClickHouse 恢复写入（`max(ts)` 前进、sink 200 OK）
- [x] `/api/v1/logs` 近 6 小时返回非空（实测 ~144 万条）

## 实施记录（追加式，勿删旧条目）

### 2026-10-16 · 会话1

- **诊断**：`docker exec ipam-clickhouse-1 clickhouse-client -q "SELECT name,code,value,last_error_message FROM system.errors ORDER BY last_error_time DESC"` → 632；`SELECT max(ts) FROM ipam.logs` 早于当前时间约 1 天。
- **修复**：`normalize` 中用 `replace(.address/.sip/.answer_ip, r'%[^%]*$', "")` 剥离 zone（沿用文件既有 fallible 解构写法）；空值仍落 `null`。
- **生效**：`vector validate` 通过 → `docker restart ipam-vector-1` → sink 恢复 `200 OK`，`max(ts)` 追至当前，日志中心恢复。
- **验证**：登录后 `GET /api/v1/logs?from=-6h` `total≈1.44e6`；`system.errors` 632 不再增长。
- **遗留**：建议在 Vector 侧或 CH 列层再做一次防御（如 `input_format_*` 或清洗），并在 CI/巡检加入 632 告警。
