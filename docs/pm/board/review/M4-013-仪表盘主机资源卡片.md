## 实施记录（追加式，勿删旧条目）

### 2026-10-16 · 会话1

- **采集方式（方案 A）**：control-plane 容器新增只读挂载 `/proc:/host/proc:ro`、`/sys:/host/sys:ro`、`/:/host/root:ro`（Docker 默认递归绑定，含数据盘子挂载），env `IPAM_HOST_PROC/SYS/ROOT`。
- **采集器** `internal/pkg/hostmetrics`：读 `<proc>/stat`（两次差值算 CPU%，核数）、`loadavg`、`meminfo`（MemAvailable）、`uptime`；磁盘读 **`<proc>/1/mounts`（宿主 PID1 挂载命名空间）** + `syscall.Statfs(hostRoot+挂载点)`，过滤非 /dev/ 与 squashfs、按设备去重（注意：`<proc>/mounts` 实为 `/proc/self/mounts`，会误返回容器自身挂载）。
- **端点（spec 先行）**：新增 `GET /system/metrics`，`make gen` 再生；RBAC `domainOf` 将 `/api/v1/system/metrics` 归 `dash`（`dash:read`）。
- **前端**：`getSystemMetrics()` + 仪表盘「主机资源」卡片（CPU/负载·核数、内存、开机时长、各文件系统容量表），10s 轮询。
- **验证（运行态）**：`/system/metrics` → 12 核、CPU≈3.2%、内存 7.78G、磁盘 `/`(45.6%) 与 `/boot`(15.5%)；下发 `ipam-*.js` 含「主机资源」、`card-*.js` 含 `system/metrics`。
- **遗留**：磁盘若与根同盘会合并展示（按设备去重）；只读挂载降低了隔离强度（无 privileged/docker.sock，风险可控）。
