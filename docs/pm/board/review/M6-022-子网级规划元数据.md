## 背景

「逐 IP 台账」已有 VLAN/站点/用途/负责人（`ledger_meta`，M6-010B3），但**子网级**只有名称、
描述、网关、DNS、租约等运行参数，缺少规划视角的归属信息。实际交付中客户按「站点 → VLAN →
用途 → 负责人」组织地址规划，子网列表是该信息最自然的落点；缺失导致要么写在描述里、要么
维护外部表格，与产品定位（一体化 IPAM）不符。

## 目标

1. 子网增加 `vlan/site/purpose/owner` 四个规划元数据字段（创建/更新/列表/详情全链路）；
2. 明确语义：**仅规划展示，不参与 Kea 下发**（避免误认为会生成 DHCP option）；
3. 前端表单「规划信息」分组 + 列表行内展示（VLAN chip + 站点/用途/负责人）；
4. 支持清空（PATCH 语义：传空串即清除，而非保留旧值）。

## 实现要点

- 迁移 `0039_subnet_meta.sql`：四列 `text NOT NULL DEFAULT ''`，`vlan <> ''` 部分索引（按 VLAN 检索）。
- `ipam.Subnet` 增 `VLAN/Site/Purpose/Owner`；PG 仓储 `subnetCols`/`scanSubnet`/`Create`/`Update` 同步。
- `subnet_handler.go`：创建映射、更新按指针非 nil 才覆盖（支持置空）、`toGenSubnet` 回填（空串也回指针，
  前端统一按字符串处理）。
- 契约 `subnet.yaml`：`Subnet`/`SubnetCreate`/`SubnetUpdate` 增字段（`maxLength` 约束）。
- 前端 `views/dhcp/subnets/index.vue`：`emptyForm`/编辑回填/提交体/列表 meta 行。
- 保持列默认空串而非 NULL：扫描无需 `coalesce` 之外的分支，旧数据行为不变。
