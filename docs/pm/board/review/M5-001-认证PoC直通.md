## 目标
最小可用登录会话：`/auth/login·user/info·codes·logout` 四端点 + HMAC 无状态令牌，响应形状对齐 vben UserInfo——让 Web 界面立即可登录、菜单可见、数据可查。正式 JWT/RBAC/Bot Token 由 M5-002 替换。

- [x] 登录→用户信息→权限码→登出 全链路 HTTP 契约级验证通过（错误口令 401、令牌防篡改）
- [x] 生产产物 API 指向同源 `/api/v1`，百度统计外链移除（零外链 PASS）

## 实施记录

### 2026-08-27 · 会话1
- **根因**：前端生产构建 API 地址指向 vben 公网 mock 且后端无 /auth/* → 登录必然失败静默停留空页（即用户反馈"登录后啥也没有"的根因）；index.html 注入百度统计外链违反内网离线契约。
- **做了**：auth 四端点 spec-first（闸① 0 errors）+ gen；HMAC 形状令牌 `poc.<uid>.<exp>.<sig16>`（服务端零存储、24h 有效期）；fixed account admin/IPAM_POC_PASSWORD(默认 admin123)；组合体第四轮嵌入名规避（AuthHandler 类型名唯一直接嵌）；`.env.production` 改 `/api/v1` 同源；移除 baidu 统计注入。
- **验证**：契约级全流程实测（login 200/401 分支、user/info 形状与 vben UserInfo 对齐、codes []、logout ok=true、篡改签名拒收）；容器重建后实端点复测通过；homePath 校正为 /overview（路由绝对 path 语义）。
- **验证策略说明**：浏览器自动化因宿主 glibc 与 Playwright chromium-build 不兼容（系统库缺 9+12 项且版本冲突）暂不可行——e2e 浏览器化列后续任务卡（容器化 playwright 镜像方案），本轮以 HTTP 契约级模拟完整覆盖前端调用序列。
- **遗留**：① M5-002 正式 JWT/RBAC 时替换签发实现并接 ActorProvider（§12.3 token_sub 填充）；② 生产口令部署时必设 IPAM_POC_PASSWORD。
