## 目标

建立“出问题能看见、能告警”的最小运维闭环，不依赖云厂商：

1. 控制面 `/metrics` Prometheus 文本指标；
2. Prometheus 抓取配置 + Grafana 预置面板；
3. 告警规则（控制面/组件掉线、磁盘、内存、TLS 到期、5xx）；
4. Alertmanager 邮件/Webhook/钉钉示例；
5. NTP 校时预检；
6. 运行页提供监控入口与健康信息。

## 验收标准

- [x] `GET /metrics` 返回 Prometheus 文本：构建信息、运行时长、HTTP 请求计数/耗时、组件 up、宿主 CPU/内存/磁盘/运行时长、TLS 证书到期；
- [x] `/metrics` 与 `/healthz` 不需要 Bearer；`/metrics` 自身不计入请求统计；
- [x] Prometheus 配置抓取 `control-plane:8443/metrics`（15s）；
- [x] Grafana 自动 provision 数据源与「IPAM 概览」面板；
- [x] 告警规则覆盖：控制面不可抓取、组件 down、磁盘 85/90%、内存 90%、TLS 30 天到期、5xx 速率；
- [x] Alertmanager 示例含邮件/Webhook/钉钉；
- [x] `install.sh` 检查 `NTPSynchronized`，未同步告警；
- [x] 可选 observability compose 栈可启动（profile）；
- [x] `go test ./...`、`vue-tsc`/eslint/build 通过。

## 实施记录

### 2026-10-29

- 指标：标准库手写 Prometheus 暴露，避免引入新依赖；HTTP 中间件按 method/status 计数并累计耗时；组件探针 1.5s 超时；TLS 证书解析到期时间。

- 告警：6 条规则，覆盖可用性/容量/证书/错误率；通道以 Alertmanager 配置示例交付（邮件/Webhook/钉钉）。
- NTP：安装脚本检查 systemd 校时状态并警告。
- 验证：`/metrics` 实测输出；单测覆盖计数/组件状态/内容类型；`go test ./...`、`vue-tsc`、eslint、build 通过；observability compose config 通过。
