## 背景

M6-017/018 完成了 API/Web 与前端离线化加固，安全扫描已有 `govulncheck`/`gosec`/`pnpm audit`/`trivy fs`。
但**发布产物镜像层无 CVE 扫描门禁**：`release.yml` 只构建+推送+SBOM+签名，未校验基镜像/系统包
漏洞；`security.yml` 的 `trivy fs` 只看源码依赖，看不到运行镜像中的 OS 包。此外运行时加固不一致：
`coherence-daemon` 无健康检查、`unbound`/`kea*` 缺 `no-new-privileges`。

## 目标

1. 镜像 CVE 扫描进入发布门禁（release.yml）：对推送的每个镜像跑 trivy，HIGH/CRITICAL（可修）非零退出；
2. 新增 IaC/配置扫描（Dockerfile/compose 误配）进入周期安全扫描；
3. 提供本地扫描脚本 `scripts/scan-images.sh`（无 trivy 时明确跳过）；
4. 运行时加固：`unbound`/`kea-dhcp4`/`kea-dhcp6`/`kea-ctrl-agent` 加 `no-new-privileges`；
   `coherence-daemon` 补健康检查；
5. 文档记录非 root 化现状与共享 UDS 卷约束（多 uid 共享 `/run/ipam`，暂不改属主避免破坏 unbound/kea）。

## 验收标准

- [x] `scripts/scan-images.sh`：默认扫描本地镜像，`--strict` 下 trivy 缺失失败；无 trivy 时跳过并提示；
- [x] `release.yml` 新增 `image-scan` job（needs images），扫描已推送的矩阵镜像，HIGH/CRITICAL 可修即失败；
- [x] `security.yml` 新增 `trivy-config` job，扫描 `deploy/` 的 Dockerfile/compose 误配；
- [x] compose 为 unbound/kea* 补 `security_opt: no-new-privileges:true`；coherence-daemon 补 healthcheck；
- [x] `docker compose config` 校验通过；相关容器重启后功能无回归（DNS/DHCP/联动）；
- [x] 文档同步（运维手册安全章节、实现说明、进度日志）。

## 设计取舍

- 镜像扫描放在 `release.yml`（扫真实发布产物）而非 `ci.yml`（每次 PR 构建全部镜像过重）；
- CI 用 `aquasecurity/trivy-action`，本地脚本用 `trivy` 或 `docker run aquasec/trivy`；
- `ignore-unfixed: true`：只对可修复漏洞阻断，避免上游未修版本卡死发布；
- 非 root 化 `coherence-daemon` 需重构共享 `/run/ipam` 属主（control-plane uid10001 / unbound uid999 /
  kea root 共写），风险高，本卡不改，仅记录约束与建议方案。
