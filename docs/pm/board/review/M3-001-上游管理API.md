## 目标
upstream CRUD（addr/权重/协议）+ 健康探测循环（连续失败摘除、恢复回切）+ forward-zone 下发到 unbound；UI 探活状态灯数据源。

## 验收标准
- [ ] prober：TCP:53 探测，3 连败摘除/2 连胜回切；RTT 记录
- [ ] 下发：unbound-control forward_add/forward_remove 或 reload；不可达时 ErrUnboundUnavailable 语义
- [ ] 状态查询端点返回 up/down/rtt/权重

## DoD
单测（探活状态机/下发/CRUD）/ lint / §13.4 同步 / spec 先行 / commit [M3-001]

### 2026-08-28 · 会话2（用户报障修复）
- **现象**：前端上游管理点「添加」无反应。
- **根因**：CreateUpstream 在 PG 落库成功但 unbound 下发失败时返回 503——数据其实已保存，但前端 add() 无 try/catch，异常后表单不重置、列表不刷新，用户视角即"按钮无效"。Update/Delete 本就用 `_ = resync()` 软失败，唯独 Create 是硬 503。
- **修复**：① 后端 handler——`saved.ID != ""` 时走 soft-fail：201 + `X-Unbound-Warning: UNBOUND_DOWN` 头（与 Update/Delete 语义对齐）；仅 PG 也失败才 503。② 前端 add()/remove()——try/catch + message.success/error 反馈，无论成败都刷新列表（soft-fail 时数据已在库里）。
- **验证**：容器端到端 POST → **HTTP 201** + warning 头（修复前 503），GET 列表新条目立即可见；dns/platform/control-plane 测试绿，lint 0。
- **遗留**：unbound 下发失败本身是 PoC 环境容器间 unbound-control 通道未通（另一问题），页面现可正常添加，下发状态以后续卡跟进。
