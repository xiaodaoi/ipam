## 目标

建立可演练、可下载、可恢复的备份能力，覆盖配置库与日志：

1. PostgreSQL custom dump（pg_dump 16）；
2. 配置目录（Unbound 等）tar.gz；
3. ClickHouse 日志按月 Parquet（复用既有导出链路）；
4. 异步任务 + 状态轮询 + 每日自动备份 + 保留份数清理；
5. 管理页：列表、立即备份、下载、恢复（二次确认）、删除、策略；
6. 升级前快照入口（`kind=pre_upgrade`，供升级脚本/流程调用）。

## 设计取舍

- ClickHouse 不采用 `BACKUP DATABASE`（需要额外 backup disk 与共享卷权限）；复用已验证的 `ExportMonth` Parquet 导出，避免新增卷与权限面；
- 备份文件落在 `ch-exports` 卷的 `backups/` 子目录，control-plane 已有写权限；
- 恢复顺序：PG `pg_restore --clean` → 清空 `logs`/`logs_topn_hourly` → 逐月 `INSERT ... FORMAT Parquet`；
- 配置备份只归档、不自动覆盖（配置在仓库/compose 挂载中，自动覆盖风险高），恢复手册说明人工处理。

- [x] `GET /system/backups/{id}/download` 返回 tar.gz（带文件名）；
- [x] `POST /system/backups/{id}/restore` 必须 `confirm=true`，恢复 PG + 日志；
- [x] 每日自动备份（UTC 小时）与保留 N 份清理；
- [x] 删除进行中的备份被拒绝；删除成功清理磁盘目录；
- [x] 前端页面 `/system/backup`：4 KPI、列表、创建弹窗、下载、恢复/删除二次确认、策略保存；
