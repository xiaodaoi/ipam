## 背景

架构文档 §12 与 API 手册长期承诺「写操作支持 Idempotency-Key」，但全仓库**零实现**；
限流也只覆盖登录接口，业务写接口（创建/删除/恢复备份等）无独立保护，网络重试会造成重复创建，
暴力调用可放大数据库/引擎压力。

## 目标

1. 通用 `Idempotency-Key` 中间件：同 key + 同请求指纹重放首次响应，不重复执行副作用；
2. 写请求独立限流：按客户端 IP 对非安全方法单独计数；
3. 契约与手册同步（OpenAPI info 描述、`docs/manual/api.md`）。

## 实现要点

- `internal/module/platform/idempotency.go`
  - `Idempotency(ttl)`：仅作用于 `/api/v1` 的 POST/PUT/PATCH/DELETE，且请求带 `Idempotency-Key`；
  - key 校验 8–128 位 `[A-Za-z0-9._:-]`，非法 → 400 `IDEMPOTENCY_KEY_INVALID`；
  - 指纹 = method + path + rawQuery + body 的 SHA256；
  - 命中已完成条目 → 重放状态码/Content-Type/响应体 + `Idempotent-Replay: true`；
  - 同 key 不同指纹 → 422 `IDEMPOTENCY_KEY_REUSED`；
  - 并发同 key → 409 `IDEMPOTENCY_IN_PROGRESS`（首个请求完成后可重放）；
  - 5xx 与 >1 MiB 响应不缓存（保证可重试/不撑爆内存）；
  - 内存条目上限 4096 + TTL 惰性清扫（无后台 goroutine）。
- `WriteRateLimit(perMinute)`：仅对非安全方法计数，默认 120 次/分钟/IP，
  超限 429 `WRITE_RATE_LIMITED` + `Retry-After`；与全局 `APIRateLimit` 叠加。
- 接线（`cmd/control-plane/main.go`）：`IPAM_WRITE_RATE_LIMIT`、`IPAM_IDEMPOTENCY_TTL`；
  幂等中间件置于 **RBAC 之后**（401/403 不缓存）、**审计之前**（重放不重复入账）。
