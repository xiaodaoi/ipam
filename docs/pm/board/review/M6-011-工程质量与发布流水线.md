## 已完成

### 1. 前端单测 + 覆盖率门禁
- 根 `web` 新增 `test` 脚本：`vitest run --coverage apps/web-ipam`（只跑业务应用，避免上游 Vben 用例的时区环境差异）。
- 新增 `src/utils/mac.test.ts`、`src/utils/lease.test.ts`（MAC 归一化、租约剩余时长、租约过滤）。
- `vitest.config.ts` 覆盖率仅统计 `apps/web-ipam/src/utils/*.ts`（排除需浏览器偏好的 `site-branding.ts`），阈值 lines/statements/functions ≥80%、branches ≥70%。
- 本地结果：5 tests 通过，statements/lines/functions 100%，branches 96%。

### 2. Playwright E2E（8 条主链路）
- `tests/e2e/run.mjs`（原生 Playwright，无额外框架）：
  1. `/healthz` + `/readyz`；
  2. UI 登录（滑块验证码）；
  3. 仪表盘运行概览；
  4. DHCP 子网管理；
  5. 租约管理 v4/v6 切换；
  6. DNS 解析记录；
  7. 日志查询检索；
  8. 操作审计（完整性校验入口）；
  9. 系统账号管理。
- 自动识别 history/hash 路由与 HTTP/HTTPS；失败截图 + `result.json` 到 `tests/e2e/artifacts/`。
- 实测：完整 Compose 栈 9/9 通过；内存模式控制面 9/9 通过。
- CI：`ci.yml` 新增 `e2e` job（复用 webci 产物 + 内存模式控制面 + Chromium），失败上传 artifacts。

### 3. 压测工具与基线
- `tests/load/main.go`（Go 标准库，无外部依赖）：登录后并发压测、输出 RPS/p50/p95/p99/错误数。
- `make load-test` 入口；建议隔离环境 `IPAM_RATE_LIMIT=0`（生产默认 600 次/分钟/IP 属安全红线，压测会触发）。
- 本地基线（内存模式、20 并发、5s、限流关闭）：
  - `/api/v1/subnets`：18,663 RPS，p50 0.68ms / p95 2.71ms / p99 3.99ms，0 错误；
  - `/api/v1/dashboard`：16,485 RPS，p50 0.81ms / p95 3.00ms / p99 4.38ms，0 错误。
- 说明：该基线为控制面内存模式；含 PG/CH/Kea 的完整栈数据口径另需专项压测。

### 4. 安全扫描
- `.github/workflows/security.yml`（每周一 + 手动）：

  - `gosec` → SARIF 上传 Code Scanning；
  - `pnpm audit --audit-level high`；
  - `trivy fs` HIGH/CRITICAL（忽略无修复项）。

### 5. 发布流水线
