## 1. 范围与边界

### 1.1 本期必须完成（GA 门槛）

1. 安全基线：TLS、密钥治理、初始口令、口令策略、自助改密、登录审计、接口限流；
2. 备份恢复与升级回滚；
3. 高可用主备（keepalived + Kea hot-standby + config-replicate）；
4. License 与版本分级；
5. 可观测与告警（/metrics、Prometheus/Grafana、告警通道、NTP）；
6. 审计合规（前后值、只追加、留存、导出）；
7. 账号体系（LDAP/AD、TOTP、自定义角色赋值、会话管理）；
8. 日志外发与容量治理（Syslog/Kafka/Webhook、采样、水位）；
9. DNS/DHCP/IPAM 功能补齐（记录类型、hosts、DoT、rebind、提示页、时段、内置库、RA、option82、冲突、租约、利用率、发现、CSV、VLAN）；
10. 工程质量（前端单测、E2E、压测、fuzz、安全扫描、发布流水线、SBOM）；
11. 文档与交付（README、安装/升级/运维/用户手册、API 文档站、离线包、Helm）；
12. 体验（i18n、首次向导、批量操作）。

### 1.2 本期不做（Phase 3）

多租户/多站点、SNMP/NetConf 拓扑、云 DNS/DHCP 纳管、OEM、DoH/DoT 对外服务、自助申请审批门户、Terraform/Ansible Provider。

> 这些能力不解决当前「不能安全卖」的问题；在 GA 前投入会拉长交付周期并稀释质量。

## 5. 质量门禁（每个任务卡必须通过）

| Gate | 内容 | 证据 |
|---|---|---|
| G0 设计 | 任务卡验收标准、接口/数据模型变更先改 spec/ADR | 任务卡 + spec diff |
| G1 单测 | 新增/修改逻辑有单测；关键分支覆盖 | `go test` / `pnpm test` 输出 |
| G2 契约 | `make gen` 后 `make gen-check` 通过 | CI 日志 |
| G3 静态 | golangci-lint、eslint、stylelint、vue-tsc 全绿 | CI 日志 |
| G4 E2E | 主链路 Playwright 用例通过（Phase 1 起进 CI） | 测试报告/截图 |
| G5 安全 | 依赖/镜像扫描无高危；敏感信息不入库 | 扫描报告 |
| G6 文档 | 任务卡实施记录、进度日志、实现说明/手册同步 | 文档链接 |
| G7 发布 | 版本号、变更说明、回滚方案、监控项 | Release checklist |

**DoD 五条**（沿用 AGENTS）：单测 / lint+typecheck / 文档 / spec 先行 / commit 带任务号。任何一条不满足，任务卡不得移入 `review`。

## 6. 质量与稳定性专项要求

1. **契约测试**：所有写接口必须有成功/失败/权限不足用例；前端类型来自生成物，禁止手写重复类型。
2. **幂等与并发**：危险写操作支持 `Idempotency-Key`；DB 唯一约束 + 事务；并发用例覆盖。
3. **失败注入**：PG/CH/Kea/Unbound 不可达时页面降级、不白屏；后端返回 Problem Details。
4. **可回滚**：迁移必须可重入；升级前快照；配置变更保留上一 revision。
5. **可观测**：每个新模块必须有指标/日志字段；错误日志包含 request-id。
6. **性能预算**：新查询必须给出索引与 EXPLAIN；导出/大批量操作走异步任务。
7. **安全默认**：默认拒绝、最小权限、密钥不落库、日志脱敏。
8. **代码可维护性**：单文件职责单一；共享逻辑抽包；禁止复制粘贴跨页面；公共常量单一来源。

## 7. 风险管理

| 风险 | 影响 | 应对 |
|---|---|---|
| HA 涉及双 PG/CH 与租约一致性 | 数据错乱/双分配 | 先做备份与演练环境；Kea HA 官方机制；切换后全量对账 |
| License 与现有 RBAC/终端计数耦合 | 误伤现网 | 软降级、只告警；灰度开关 |
| LDAP/AD 环境差异 | 登录不可用 | 本地账号兜底；连接测试；超时/降级 |
| ClickHouse 备份复杂 | 恢复失败 | 优先 Parquet 归档 + 表级备份；定期演练 |
| 范围过大导致质量下降 | 返工 | 双周迭代、任务卡粒度、Gate 不放水 |
| 文档与实现再次漂移 | 交付/审计风险 | 每卡必须更新文档；roadmap 每周校对 |

## 8. 项目奖金与绩效方案（建议稿）

> 目的：把「交付质量」而非「代码量」作为分配依据；奖金按阶段 Gate 发放，出现生产事故可追溯扣减。以下为建议比例，最终由管理层确认。

### 8.1 奖金池与角色权重

| 角色 | 权重 | 说明 |
|---|---|---|
| 后端 | 30% | API/DB/引擎/安全/HA/License |
| 前端 | 22% | 页面/交互/i18n/向导 |
| DevOps | 20% | 部署/CI/监控/备份/发布 |
| 测试与文档 | 13% | E2E/压测/手册/验收证据 |
| 项目负责人 | 15% | 范围/质量/风险/跨团队协调 |

### 8.2 个人系数（0.8–1.2）

| 维度 | 权重 | 评分依据 |
|---|---|---|
| 任务完成度 | 40% | 任务卡验收项全部通过，按卡计分 |
| 交付质量 | 25% | 单测/契约/静态检查/E2E 一次通过率；返工次数 |
| 稳定性 | 20% | 上线后 30 天内 P0/P1 缺陷数；回滚次数 |
| 协作与文档 | 15% | 交接质量、文档同步、评审响应 |

**计算**：个人奖金 = 阶段奖金池 × 角色权重 × 个人系数 × 阶段完成率。
**否决项**：出现以下任一，阶段奖金系数封顶 0.5：隐瞒安全漏洞、跳过测试门禁、生产数据丢失、未授权变更。

### 8.4 质量扣分

- P0 生产事故：-30%～-50%，责任人/复核人分担；
- 安全高危漏洞流入：-20%；
- 任务卡文档缺失/状态失真：-5%/次；
- 未按 spec 先行导致契约漂移：-10%。

## 10. 变更控制

1. 新需求先进入 `backlog`，由 LEAD 评估对 GA 的影响；
2. 影响范围/进度的变更必须更新本计划与 `roadmap.md`；
3. 接口变更必须先改 OpenAPI 并 `make gen`，破坏性变更需 ADR；
4. 紧急修复走 hotfix 分支，合并后补任务卡与回归用例。
