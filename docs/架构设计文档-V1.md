## 2. 关键接口契约

### 2.1 hook ↔ coherence-daemon（gRPC over UDS `/run/ipam/coherence.sock`）

```protobuf
syntax = "proto3";
package ipam.coherence.v1;

service Coherence {
  // hook 在 pkt6_receive 时同步调用：<1ms 目标，超时 50ms 即走本地降级
  rpc ResolveBinding(ResolveRequest) returns (ResolveResponse);
  // hook 在 lease6_commit/lease4_commit 时异步上报（fire-and-forget）
  rpc ReportLease(LeaseReport) returns (Ack);
}

message ResolveRequest {
  string mac      = 1;  // 归一化小写冒号格式 aa:bb:cc:dd:ee:ff
  string duid     = 2;  // 原始 DUID（供审计）
  uint32 subnet_id = 3; // Kea subnet-id
}
message ResolveResponse {
  bool   hit        = 1;
  string ipv6       = 2;  // 计算结果，如 2406::10:61:172:10
  string template_id = 3;
  enum Source { CACHE=0; COMPUTED=1; NONE=2; } source = 4;
}
```

**降级策略**：daemon 不可达时，hook 使用本地只读快照文件（daemon 每 5s 刷新至 `/run/ipam/bindings.snapshot`）做 DUID-LLT 本地解析兜底；仍失败则按普通动态池分配并打标 `coherence-miss`。

### 2.2 控制面 ↔ Kea

- 全部经 Ctrl Agent REST（127.0.0.1:8000）：`config-set`（整包配置+校验回滚）、`reservation-add/del`、`lease4-*`、`statistic-get`。
- 配置变更采用"生成→`config-set`(staged 校验)→生效"三步，失败自动回退上一 revision（存 `engine_config` 表）。

### 2.3 控制面 ↔ Unbound

- 静态区域：控制面从 PG 导出 zonefile → 写入共享卷 → `unbound-checkconf` 校验 → `unbound-control reload`。
- 动态记录（租约联动）：`unbound-control local_data "<rr>"` / `local_data_remove`，秒级增量。
- 一致性对账（K9）：`local_data` 仅运行态生效、进程重启即失效——coherence-daemon 启动时全量重放 + 周期（默认 5min）比对 PG 绑定表做增量修正，保证最终一致。
- 上游探活（FR-B-01）：控制面内置 prober 周期探测各 forward-zone 上游（dig + RTT 采样），连续失败自动摘除并告警、恢复后回切。Unbound 仅提供被动 infra-host RTT 探测，主动摘除逻辑由控制面承担。
- ⚠️ PoC 校验项：确认 `local-data` 对同名记录的优先级高于 `auth-zone`（预期成立，需实测记录冲突场景）；确认 **auth-zone 不可置于 view 内**的版本边界，按策略组差异化的内网数据一律用 view 内 `local-zone` 表达。

## 3. 核心数据模型（PostgreSQL）

```sql
-- 联动核心表
CREATE TABLE prefix_template (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name          text NOT NULL,
  ipv4_cidr     cidr NOT NULL,
  ipv6_prefix   cidr NOT NULL,
  encoding      text NOT NULL CHECK (encoding IN ('B','A','CUSTOM')), -- 默认 B
  expr          text NOT NULL,        -- '{v4.hextet4}' / '{v4.hex32}' / 自定义
  dns_sync      boolean NOT NULL DEFAULT true,
  grace_hours   int NOT NULL DEFAULT 24,
  enabled       boolean NOT NULL DEFAULT true
);

CREATE TABLE coherence_binding (
  mac            text PRIMARY KEY,               -- 身份锚点
  ipv4           inet NOT NULL,
  ipv6           inet NOT NULL,
  template_id    uuid REFERENCES prefix_template(id),
  hostname       text,
  state          text NOT NULL DEFAULT 'active'
                 CHECK (state IN ('pending','active','grace','expired','conflict')),
  conflict_reason text,
  last_seen      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON coherence_binding(ipv6);

CREATE TABLE reservation (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  mac text, duid text,
  ipv4 inet, ipv6 inet[],
  origin text NOT NULL CHECK (origin IN ('manual','coherence','import'))
);
-- Kea host 后端直接读本库（identifier=hw-address）；lease 后端同库由 Kea 自管 schema

-- 全局组织分组（主数据：多级自定义树，系统管理统一维护，全模块引用，见 §13.4）
CREATE TABLE org_group (
  id        uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  parent_id uuid REFERENCES org_group(id) ON DELETE RESTRICT,
  name      text NOT NULL,
  path      text NOT NULL,             -- 物化路径，便于子树整体展开（组织→CIDR 过滤）
  UNIQUE (parent_id, name)
);

-- 资产登记（以 MAC 为身份键，独立于 coherence_binding，换址后备注不丢，见 §13.4）
CREATE TABLE asset (
  mac        text PRIMARY KEY,
  org_id     uuid REFERENCES org_group(id),
  owner      text,                     -- 使用人员
  dept       text,
  note       text,
  tags       text[] NOT NULL DEFAULT '{}',
  updated_at timestamptz NOT NULL DEFAULT now()
);

-- DNS 封禁（FR-B-11~18，选型 D13）
CREATE TABLE blocklist (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name       text NOT NULL,
  kind       text NOT NULL CHECK (kind IN ('builtin','custom','feed')),
  sync_url   text,                -- kind=feed 的订阅地址(HTTP/AXFR)
  last_sync  timestamptz,
  version    int NOT NULL DEFAULT 1
);
CREATE TABLE blocklist_entry (
  list_id       uuid REFERENCES blocklist(id) ON DELETE CASCADE,
  trigger_type  text NOT NULL CHECK (trigger_type IN ('qname','response_ip')),
  pattern       text NOT NULL,    -- 泛域名 *.bad.com 或 CIDR
  action        text NOT NULL DEFAULT 'nxdomain'
                   CHECK (action IN ('nxdomain','drop','tcp_only','redirect')),
  redirect_target text,           -- action=redirect 时的提示页记录名
  category      text,             -- 分类标签，供拦截报表
  PRIMARY KEY (list_id, trigger_type, pattern)
);
CREATE TABLE policy_group (
  id        uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name      text NOT NULL,
  view_name text UNIQUE NOT NULL, -- 对应 Unbound view 名
  cidrs     cidr[] NOT NULL,      -- view 匹配的来源网段
  list_ids  uuid[] NOT NULL,      -- 生效名单集合(白单优先)
  schedule  jsonb                 -- 时段表，由调度器展开为 cron
);
```

## 4. 特色功能：联动链路设计（D12 PoC 核心）

### 4.1 正常时序

```
终端A(mac=aa:bb..)        kea-dhcp4        PG(NOTIFY)      daemon        kea-dhcp6/hook
    │──DISCOVER────────────▶│                 │              │                │
    │◀────OFFER 10.61.172.10│                 │              │                │
    │──REQUEST─────────────▶│ COMMIT租约      │              │                │
    │                       │────trigger─────▶│ NOTIFY lease4│                │
    │                       │                 │────读取──────▶│ 模板计算(B型)   │
    │                       │                 │◀─UPSERT绑定──│ 写binding+预留  │
    │═══════ 之后终端发起 Solicit ═══════════════════════════════════════════▶│
    │                       │                 │              │   pkt6_receive │
    │                       │                 │   ResolveBinding(UDS,<1ms)    │
    │◀════ ADVERTISE 2406::10:61:172:10 ═════════════ lease6_select 注入 ════ │
```

### 4.2 双路径竞态对比（PoC 评估项）

双栈终端可能几乎同时发出 Request(v4) 与 Solicit(v6)，Solicit 先于绑定落库即产生竞态。

| 路径 | 机制 | 竞态覆盖 | 复杂度 | 结论 |
|---|---|---|---|---|
| A 异步预留 | daemon 收 NOTIFY 后 `reservation-add`（Kea PG host 后端每次 Solicit 实时查库） | 依赖客户端重传窗口（~1s），风暴期有漏 | 低 | **保留为持久化/对账层** |
| B hook 同步 | pkt6_receive 同步 RPC 查询，lease6_select 直接注入 | 报文级闭环，无窗口依赖 | 中（C++） | **运行时主路径** |

**定稿标准（PoC 验收）**：100 终端并发重启风暴下，B 路径联动成功率 ≥ 99.9%，ResolveBinding P99 ≤ 5ms；A 路径单独成功率 ≥ 97%（作为降级与审计基线）。两路并存：B 决定"给什么"，A 保证"账上有据"。

**MAC 来源优先级链（§4.2 补充）**：DHCPv6 报文以 **option79（RFC6939 客户端链路层地址）为第一来源**——hook 解析后以该 MAC 查询 IPv4 池租约得到对应 IPv4，再经模板计算 IPv6；option79 缺失或非以太网时按 L2 源 MAC → DUID-LLT/EN 解析降级。三层中继场景由 RFC6939 原生携带，无需嗅探。

**多池对绑定（§4.3 补充）**：系统支持**多组 v4/v6 地址池对**（池可自定义增删改查，仅需 IP 合法且不重复），每组以一条 `prefix_template` 表达：`ipv4_cidr ↔ ipv6_prefix`（如 `192.168.0.0/23 ↔ 2407::`、`172.16.248.0/24 ↔ 2409::`）。daemon 在联动计算时**按租约 IPv4 的最长前缀自动匹配**所在池对的模板，无需手工指定；例：MAC 在 192.168.0.0/23 池租得 192.168.0.10，则 IPv6 = `2407::192:168:0:10`（B 型 hextet4 直映）。

### 4.3 映射计算（daemon 内实现）

```
输入: ipv4=10.61.172.10, template={prefix:"2406::", encoding:B, expr:{v4.hextet4}}
B型: octets=[10,61,172,10] → hextets=["10","61","172","10"] → 2406::10:61:172:10
A型: u32=0x0A3DAC0A       → 2406::a3d:ac0a
校验: 结果不得落入普通动态池/人工预留段 → 冲突则 state=conflict 并告警(P1)
```

生命周期：v4 expire → state=grace(grace_hours) → expired；renew 换址 → 重算并刷新 DNS 记录。

### 4.4 DNS 联动

daemon 在绑定 active 时向 unbound 下发：
`host-aa-bb-cc-dd-ee-ff.corp.local. 300 IN A 10.61.172.10` 与 AAAA 及两条 PTR（in-addr.arpa / ip6.arpa）。主机名来源 option12/FQDN，缺省规则 `host-<mac横线>`。

## 5. DNS 封禁与黑名单设计（FR-B-11~18，选型见 D13）

### 5.1 数据流

```
控制面(blocklist/policy_group 表)
   │ 增量编译：每策略组一个 zonefile                 订阅源(HTTP/AXFR)──定时拉取──┐
   ▼                                                            │
/var/lib/ipam/rpz/<policy>.zone ──unbound-checkconf──▶ unbound(rpz zone) ◀──┘
   ▲                                                │ 命中 qname / response-ip 触发器
   │ unbound-control auth_zone_reload <zone>        ▼
   └──────────── 变更热更新(单区刷新,不整进程) ── 动作: NXDOMAIN/DROP/TCP-only/CNAME→提示页
                                                    │
                                     vector ──▶ ClickHouse(action=blocked, category=分类)
```

### 5.2 引擎配置形态（示意，键名以 PoC 校准为准）

```yaml
server:
  access-control-view: 10.61.128.0/17 name "students"   # 分组策略=按网段映射 view
  access-control-view: 0.0.0.0/0 name "default"
view:
  name: "students"
  rpz:
    name: "policy-students.rpz"
    zonefile: /var/lib/ipam/rpz/students.zone
    rpz-log: yes
    rpz-log-name: students
```

zone 条目示例：

```
badsite.com            CNAME .                    ; 整域 NXDOMAIN
*.cdn.badsite.com      CNAME .                    ; 通配子域
gamble.example.com     CNAME block.corp.local.    ; 重定向到内网提示页(B-17)
; response-ip 触发段(CIDR) 同文件按 RPZ 标准语法表达
```

提示页由 control-plane 内置静态页服务承载，文案/logo 可在 UI 定制。

### 5.3 控制面职责

- 名单生命周期：内置分类库（随版本发布+在线增量、可回滚）、自定义（UI/CSV）、订阅源同步去重（失败保留旧版）；
- 策略编译：条目变更 → 仅重写受影响策略组 zonefile → checkconf → `auth_zone_reload` 单区刷新；
- 时段切换：`policy_group.schedule` 展开为 cron 任务，分钟级切换并写审计。

### 5.4 边界与缓解（与调研报告 §7.2 口径一致）

1. 封禁粒度为域名/响应 IP，不含 URL 路径；
2. 分组粒度为网段（view），终端级依赖 DHCP 固定分配等价达成；
3. DoH 绕过：主流 DoH 域名/IP 出厂入默认库 + 部署指南提供网关 NAT 重定向 53 样例；
4. 不做秒级实时策略，时段精度为分钟。

## 6. 日志链路

```
kea stdout/stderr ─┐
unbound logfile  ──┼──▶ vector(syslog source /var/run/ipam/log.sock)
keepalived/control │        │ VRL 解析归一化(client_mac 统一关联键)
                   ▼        ▼
             clickhouse(logs 表, 批量 5000条/5s 刷盘)
                   ▲
control-plane ─────┘ 查询网关: 组合过滤/TopN/QPS曲线, 大查询走物化视图
```

- 分级开关写入 Kea/Unbound 运行参数（全量/抽样/仅异常）；
- 磁盘水位 80% 告警、90% 自动降级采样（需求 E-05）；
- 外发通道：vector 同时 sink 到客户 SIEM（syslog rfc5424 / 可选 kafka）。

| 8000/5432/9000/8123 | ctrl-agent/PG/CH | 仅 127.0.0.1 或内部网络 |

```

其余容器:     cap_drop ALL, 只读根文件系统, secrets 经 /run/secrets 挂载(0600)
```

### 6.3 交付矩阵

| 形态 | 内容 | 适用 |
|---|---|---|
| docker-compose | `compose.yaml` + `.env` 安装脚本（预检：内核参数/端口/时间同步） | 默认，单机或主备两台 |

| 镜像仓库 | 统一多服务镜像矩阵 tag `x.y.z-jammy`，`latest` 禁用 | — |

### 6.4 主备行为

- 两节点同配置运行数据面，VRRP MASTER 承载 VIP；
- Kea hot-standby 同步租约（PG 同库不可跨节点 → 采用 Kea 自带 lease 同步机制 + 各自本地 PG，故障切换后全量对账）；
  ⚠️ 设计约束：**主备各自独立 PG/CH 实例**，控制面配置通过主节点 API 推送到备节点（`config-replicate`），日志不跨节点合并（各自留存），避免分布式存储复杂度——符合 RTO≤30s 且实现最简。
- 脑裂防护：keepalived unicast + 双向心跳检测 + 备机抢占延迟 60s。

### 11.2 明确不做

| 项 | 理由 |
|---|---|
| 应答 IP 结果排序 / CDN 优选 | 改写应答破坏 DNSSEC 签名（与 B-10 冲突），且属跨境个人场景，与企业治理定位不符 |
| docker.sock 自动解析容器 | 等效宿主机 root 权限，违反 cap_drop ALL 加固基线；服务发现走 API/Webhook 注册 |
| 污染检测 / 漫游 / 域前置 | 属规避审查用途，与合规治理定位相悖；域前置已被主流 CDN 弃用 |
| 更换 DNS 引擎 | GOGDNS 类个人项目缺乏 HA/多节点/审计佐证，仅作交互灵感来源 |
| FakeIP / Redir-Host 分流模式 | 透明代理专用语义，与企业治理产品无关；且破坏反向解析与长连接地址稳定性 |
| 分流结果自学习 | 判定过程不可审计，与"策略可解释"的产品主张冲突；本项目 CIDR→view 映射确定性更强 |
| 引入 mosdns 作数据面组件 | GPL-3.0 许可传染；单机无 HA；纯转发无递归/权威能力；违背 D4"不引入第二套 DNS 进程" |

## 12. API 与 AI 集成规范（选型见 D14）

### 12.1 覆盖目标与工程路线

- 主要功能 100% API 化（承接需求 FR-F-03 API-first），**OpenAPI 3.1 spec 为唯一事实源**：手写 YAML 按模块拆分 `$ref` 组装 → oapi-codegen 生成 Gin 服务端接口/类型，并生成 TS 客户端供前端（§13.2），前后端契约单一来源。
- 选 3.1 的理由：其 schema 即 JSON Schema 2020-12，与大模型 function calling 的工具参数定义同构，转换零损耗。

### 12.2 LLM 友好设计约定（CI 强制）

| # | 约定 | 目的 |
|---|---|---|
| 1 | `operationId` 稳定动词命名（如 `createReservation`） | 它即未来 AI 的工具名，发布后不可改 |
| 2 | 每 operation 必含 summary/description + ≥2 组 example（成功+典型错误） | LLM 看不到 Wiki，描述必须自包含 |
| 3 | 字段级 description（单位/范围/业务含义）；枚举带 `x-enum-descriptions` | 避免 agent 猜参数语义 |
| 4 | 错误模型 = RFC 9457 Problem Details + 业务错误码字段 | 机器可判读，agent 可据此自纠重试 |
| 5 | 写操作支持 `dry_run=true` 预检 + `Idempotency-Key` 头 | AI 安全执行变更的两大保险 |
| 6 | 危险操作标注 `x-risk-level: destructive` 并要求二次确认参数 | 给 agent 划红线 |
| 7 | securitySchemes 声明所需 scope | agent 权限不足时可自查原因 |

### 12.3 AI 接入层：MCP 网关（P1 预留）

- 从同一份 OpenAPI 自动生成 MCP tools 暴露给 agent 框架，不手写第二套接口；
- 独立 Bot Token 类型，审计日志区分人/AI 调用者；只读 scope 默认开启，写操作需管理员显式授权；
- 提供 capabilities 清单端点："任务 → 端点编排配方"，降低 agent 规划成本。

### 12.4 CI 质量门禁

1. Spectral 规则集：缺 description/example/operationId 直接 fail；
2. **路由覆盖率测试**：Gin 注册路由必须 ⊆ spec，缺失即 fail——"所有功能有 API 且有详细说明"由流程保证而非自觉；
3. openapi-diff 检测破坏性变更（v1 内禁止）；example 与 schema 一致性校验；
4. `/api/v1/openapi.json` 版本化在线提供；静态文档站（Scalar）embed 进 control-plane 二进制随产品分发。

### 12.5 工具链

oapi-codegen、Spectral、openapi-diff、Scalar——均为宽松许可（MIT/Apache 类），无 GPL 传染。

### 13.4 主导航信息架构（定稿）

> 一级菜单 5 个，二级菜单覆盖需求族 FR-A~F 全量；菜单项即权限码载体——`accessMode='backend'` 动态菜单下发，权限码与 OpenAPI scope 同源（§12/§13.2）。首次部署 5 步向导（F-01）为全屏 Wizard，不占菜单。

#### 一级结构

| 菜单 | 内容要点 |
|---|---|
| 仪表盘 | 今日在线 IP 数、在线 IP 趋势（24h）、今日新增/离线终端、服务健康状态灯（kea/unbound/keepalived/PG/CH）、DNS QPS/缓存命中率/拦截量、池利用率 TopN（着色预警）、双栈联动成功率 |
| DHCP 服务 | 二级结构见下 |
| DNS 服务 | 二级结构见下 |
| 日志中心 | 查询检索（组合过滤/TopN/QPS 曲线 E-04，支持按组织维度过滤）/ 实时流 live-tail（F-R7）/ 操作审计（含 AI/Bot 调用者标识，§12.3）/ 外发集成（syslog/Kafka/SIEM，E-06） |
| 系统管理 | 组织管理★ / 用户与角色 / 节点与高可用 / 备份升级 / License / 告警通道 / 时间设置(NTP) |

#### DHCP 服务（二级，6 项）

1. **地址台账**：IPv4/IPv6 统一台账矩阵，六态着色（见下表）；行内查看租约状态/到期时间/MAC/主机名；操作：转保留（冻结不下发）、转静态+MAC 绑定、释放；页签：总览矩阵 / 租约明细 / 资产登记（以 MAC 为键登记使用人/部门/备注，换址不丢）；左侧常驻组织树引用视图（可折叠）按节点过滤。
2. **DHCPv4 管理**：子网+地址池增删改查，挂接所属组织节点。
3. **DHCPv6 管理**：子网+地址池+PD 前缀委派，挂接所属组织节点。
4. **保留与绑定**：保留地址列表（冻结不下发）/ 静态绑定列表（MAC↔IP）。
5. **选项与类匹配**：标准选项配置（C-02）、类匹配规则（C-03）。
6. **双栈管理**：v4 池↔v6 池绑定映射与自动同步开关、映射模板（B 型/hex 编码）、绑定台账、冲突处理。

#### DNS 服务（二级，6 项）

1. **上游管理**：全局上游池 CRUD——地址/协议（UDP/TCP/DoT 可选加密 B-08）、权重顺序（B-01）、探活状态灯与自动摘除回切（F-R4）。
2. **转发规则**：默认上游选择 + 条件转发规则表（域名后缀→专属上游、内网根域整体指向、例外规则，B-02）；变更支持 dry_run 预检。
3. **缓存与性能**：命中率曲线、手动清空（B-06）、min/max TTL、serve-expired 开关（F-R2）、每域名 TTL 覆盖列表（F-R3）。
4. **解析记录**：zone 与记录 CRUD；页签：正向记录（A/AAAA/CNAME）/ 反向记录（PTR）/ 联动记录（只读，来自 DHCP 双栈联动自动生成）。对应 Unbound auth-zone/local-zone。
5. **封禁管控**：三页签——名单库（内置/自定义/订阅源同步状态，B-11~14）/ 策略分组（view×网段×时段表，B-15~16）/ 提示页定制（文案/logo，B-17）；拦截统计跳转日志中心并预过滤 action=blocked（B-18）。
6. **安全与诊断**：RRL 应答限速与防放大（B-08）、DNSSEC 校验开关（P2，B-10）、解析测试台（选定 view/模拟来源发起 dig 式查询，就地验证分流与封禁生效）。

#### 地址六态颜色规范

| 状态 | 颜色 | 判定 |
|---|---|---|
| 在线 | 绿 | 租约活跃度近似（租约存在≈在线，零探测成本）；精确在线探测列 P2 预留 |
| 空闲 | 灰蓝 | 池内未租出 |
| 保留（冻结） | 黄 | 管理员标记，动态分配不下发 |
| 静态绑定 | 蓝 | host reservation 生效中 |
| 过期/宽限 | 橙 | grace 期内 |
| 冲突 | 红 | conflict state |

#### 主数据原则与关联链

- **组织为全局主数据**：多级自定义树（公司→部门→…无限层级）仅在「系统管理→组织管理」维护一次；DHCP/DNS 各页面以引用方式消费（左侧树筛选、表单下拉），保证单一事实源；
- 关联链：`org_group → subnet/pool → 租约/台账`；`org_group → asset(mac) → 日志`。日志中心按组织过滤 = 控制面展开该节点下全部 CIDR 集合 ∪ 组内资产 MAC 后查询 ClickHouse；
- 删除保护：节点存在子节点、或仍被子网/池/资产引用时禁止删除；
- 数据模型支撑见 §3 新增 `org_group`、`asset` 两表；
- 结构调整说明：原 FR-A"地址管理"一级并入 DHCP 承载；"日志审计"更名"日志中心"；双栈联动由一级降为 DHCP「双栈管理」（仪表盘保留联动成功率卡片作为演示入口）。

**组织原则**

1. **api/ 先行**：后端接口实现与前端 TS 客户端均从 `api/openapi` 生成，"所有功能有 API 且有详细说明"由 §12.4 CI 门禁看守；
2. **web/ 是唯一整体引入的外来项目**：业务改动锁死在 `apps/web-ipam/`，`packages/@vben/*` 不动；
3. **internal/module 与主导航一一对应**：菜单权限码（如 `dns.blocklist.write`）↔ 模块路由注册，路由覆盖率测试自然对齐；
4. **C++ 隔离**：`hook-coherence` 独立目录与独立流水线，不污染 Go 构建链路；
5. **镜像与配置分离**：`deploy/images` 出通用镜像，`config/` 存模板按环境渲染，交付物不含环境耦合。
